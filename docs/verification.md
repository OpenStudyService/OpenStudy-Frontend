# 프론트엔드 검증 기록

검증일: 2026-10-17. Windows · Node 24.19.0 · npm 11.10.1 · 설치된 Google Chrome. 원본 HTML 목업과 개정 요구사항 v1.0을 기준으로 확인했습니다.

2026-10-18 해석 정정: 아래 좌석 배정·퇴실·차감 검증은 백오피스 직원의 예외 지원 경로를 대상으로 한 MSW 시험입니다. 정상 고객 입퇴실의 주체는 QR 등을 직접 사용하는 고객이며 고객 화면·인증·QR 연동은 후속입니다. 과거 시험 결과를 고객 QR 연동 검증으로 해석하지 않습니다.

## 실행 결과

| 검사 | 결과 |
|---|---|
| `npm run api:generate` | 25개 자원, 입력·변경·명령·공통 응답의 OpenAPI와 TypeScript 생성 성공 |
| `npm run typecheck` | TypeScript strict 통과 |
| `npm run lint` | 통과. 원본 목업·생성 타입·배포 결과·테스트 산출물 제외 |
| `npm test` | 3개 파일 **24개 테스트 통과** |
| `npm run test:e2e` | **15개 시나리오 통과** |
| `npm run test:builds` | live·demo 빌드 성공, 배포 결과 **2개 시나리오 통과** |

마지막 API 보완으로 로그인·로그아웃·초대 수락·401/CSRF 오류 뒤 CSRF 토큰을 다시 받도록 했습니다. 익명 세션 토큰을 로그인 뒤 재사용하지 않는 단위 테스트를 추가했고, 실제 빌드 로그인과 모바일·테마 화면을 다시 확인했습니다.

## 확인한 내용

- **인증·조직:** 초대 생성 → 새 계정 수락 → 승인 대기 → 관리자 최종 승인 → 로그인. 직원의 관리자 메뉴·타 지점 직접 주소 및 HTTP 요청 거부, 세션 만료 처리.
- **협업:** 업무 등록·배정·체크리스트 → 채팅 공유 → 직원 스레드 보고 → 완료. 목록·연결 카드·새로고침 후 상태 일치. 다른 화면의 집계는 같은 원장 API를 다시 조회.
- **채팅:** 한글 조합 Enter 방지, 전송 실패·동일 ID 재전송, 중복 표시 방지, SSE 단절 후 백오프 재연결·REST 이력 복원.
- **거래:** 구매 조건 스냅샷, 실패 시 미발급, 미사용 만료권 환불·사용권 환불 거부, 멱등·롤백, 중복 예약 거부와 입력 보존, 취소 후 자원 해제, 한 고객 중복 입실 거부와 퇴실 한 번 차감.
- **인력:** 휴가 신청·승인·취소와 잔여량/주간 근무표 일치, 대체근무 승인·원근무 복원. 근태 원본·정정·휴게의 화면과 명령을 제공.
- **분석:** 환불 처리일·원거래일 두 집계 기준, 일반 매출과 AI 같은 원장 값 비교, AI SSE 진행·취소·확인 질문·미지원·빈 결과·실패·미지원 ViewSpec 대체 화면.
- **경합·입력:** 지점 전환 중 지연 응답 폐기, URL 검색 조건 새로고침 복원, 실패 폼 입력 유지, 버전 경합·권한 회수 후 멱등 응답 재사용 거부.
- **반응형:** 1440·1024·390px에서 16개 주요 경로의 페이지 전체 가로 넘침 검사, 등록 버튼과 패널 입력 접근. 모바일 채팅 목록→대화와 작성창 위치 확인.
- **테마·키보드:** 포레스트·네이비·샌드의 로그인·홈·업무·채팅·AI 캡처, 새로고침 테마 유지·테마 전환 시 입력 유지, Escape 패널 닫기·원래 버튼 포커스 복귀, 레이블·오류 연결·본문 건너뛰기·모션 감소 구현. 일반 경로 탐색에서 처리되지 않은 브라우저 예외 없음.
- **배포 모드:** live 산출물에는 MSW/가상 원장 동적 청크가 없음. API 실패를 화면에 표시하고 데모 로그인·worker를 활성화하지 않음. demo 산출물은 번들된 worker로 로그인·채팅 조회 성공.

## 산출물·재현

기본 브라우저 테스트 캡처는 `test-results/`, 배포 검증 결과는 `test-results-builds/`에 생성합니다. 실패 시 스크린샷과 기본 테스트의 trace를 남깁니다. 생성 결과이므로 Git 대상에서 제외합니다. 정상 시연은 `npm run dev`, 장애·권한·빈 응답 등의 재현은 설정의 데모·검증 도구를 사용합니다. 예약·버전 충돌은 같은 자원에 중복 작업을 요청해 재현합니다.

테스트 도중 잘못된 테스트 날짜·정확한 레이블 선택자·미입력 취소 사유를 바로잡았습니다. 앱에서는 초대 비밀번호 이름, SSE 종료 복구, KST 점검 날짜, 지점별 권한, CSRF 갱신, 로그인 초기 API 오류 표시를 수정했습니다. 브라우저가 거부 응답을 기록하는 오류 시나리오와 일반 화면의 처리되지 않은 JS 오류를 구분했습니다.

## 실서버 연결 후 별도 검증

다음 항목은 **미검증**입니다. 프론트 모킹 통과로 대체하지 않습니다.

| 항목 | 확인할 내용 |
|---|---|
| 세션·CSRF | 실제 HttpOnly/Secure/SameSite 쿠키, 토큰 회전·세션 만료·로그아웃 |
| 서버 권한 | 직접 API·ID·범위 변조, 권한 회수 중 실행·캐시 재조회 |
| 거래·근태 | DB 동시 요청 경합, 영속 멱등 키, 재시작 후 원장·감사 보존 |
| 초대 이메일 | 실제 발송·실패·대상 이메일 확인·토큰 만료·재발급 |
| 실시간 | 두 사용자·두 브라우저 전달, 네이티브 SSE·프록시·장시간 재연결 |
| DomainLens | 확정 SDK/DTO 버전, 컨슈머 지표·권한·시계 등록, 실제 DB 집계 비교 |
| 운영 품질 | 실제 배포·SPA/API 프록시·재기동·기기 테스트·응답 시간 목표 실측 |

현재 범위의 제한: mock 원장은 탭 단위이며 여러 사용자 사이 동기화를 제공하지 않습니다. 주간 근무표·예약 달력은 날짜 범위 조회의 최대 100개 페이지를 사용합니다. 대규모 운영 데이터 적용 시 해당 보기에 페이지 수집 또는 별도 기간 집계 API를 연결해야 합니다. DomainLens DTO는 엔진 정본 수령 전의 표시 어댑터 계약입니다. 일반 문서·표의 프론트 대응 표시는 요구사항 전체의 최종 실서버 검수 완료를 뜻하지 않습니다.
