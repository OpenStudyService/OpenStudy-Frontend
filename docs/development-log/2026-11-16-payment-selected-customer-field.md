# 2026-11-16 · 결제 고객 선택값 표시

## 배경 / 문제

결제 조회와 Mock 결제에서 고객을 선택하면 이름과 회원번호를 검색 버튼 옆에 표시했다. 검색창이 남아 있어 입력한 검색어와 실제 선택값을 함께 확인해야 했다.

## 결정 및 구현

- 고객을 선택하면 검색창 자리에 이름과 회원번호를 표시한다. 선택값 오른쪽의 × 버튼으로 해제하면 빈 검색창과 입력 초점을 복원한다.
- 고객 검색 버튼을 눌러 다른 고객을 고를 때 모달 검색어는 빈 상태로 시작한다. 선택값과 검색어를 구분해 기존 고객을 둔 채 새 검색을 시작할 수 있다.
- 검색어 입력으로 모달을 열었다가 취소하면 입력으로 초점을 돌려준다. 고객을 선택하면 검색 버튼으로 초점을 옮긴다.

## 검증 결과

- 관련 Vitest 2개 파일, 43개 통과. 마지막 초점 처리 변경 후 결제 화면 테스트 25개를 다시 통과했다.
- 타입 검사, 린트, `git diff --check` 통과.
- Chrome Mock 환경에서 1440px 결제 목록과 390px Mock 결제 사이드바의 선택값 위치, 빈 검색어로 모달 다시 열기, 해제와 검색창 초점 복귀를 확인했다.

## 남은 검증

- 전체 테스트와 실제 API 연동 검증은 실행하지 않았다.

## PR 준비 재검증

- 전체 Vitest 95개 파일, 855개 테스트 통과. 타입 검사와 린트도 통과했다.
- 운영 빌드와 Mock 빌드, 두 빌드의 산출물 모드 검사 통과. Vite는 500kB를 넘는 청크에 대해 경고했다.
- 운영 빌드 프리뷰에서 고객 모달을 사용한 Mock 결제 요청과 API 오류 표시를 Playwright 한 건으로 확인했다. 실제 백엔드 연동은 실행하지 않았다.
