# 2026-11-03 사물함 정본 API 연결 (#24)

## 1. 배경 / 문제

Frontend #24의 기존 사물함 화면은 데모 원장과 범용 명령을 사용했다. 루트 AGENTS.md·graphify 스킬/그래프·이슈·현재 코드·관련 PR과 개발 기록을 확인하고, 최신 Frontend main `5ff942f`에서 `feature/locker-api-integration`을 만들었다. Backend #67 계약과 #71의 실제 구현, 병합 PR #154(`18d6826`)를 확인했다.

사용자 요청대로 서브에이전트 3명은 모두 **gpt-6.1-sol / High**로 실행했다. 계약·API/모델, UI, Mock 어댑터·집중 검증을 분담했고 주 에이전트가 통합·실제 서버 검증·기록·PR·CI를 맡았다. 사용량 제한으로 중단된 뒤 사용자 재개 요청에 따라 같은 브랜치와 모델 설정에서 이어갔다. 미완성 화면의 import 오류로 끝난 중간 시험을 성공으로 간주하지 않았다.

기존 미추적 `.gitattributes`와 Backend의 채팅 작업·환경 파일은 변경하거나 포함하지 않는다. 실제 검증은 Backend main `7fcac51`의 별도 복사본과 일회용 DB를 사용했다.

## 2. 검토한 선택지

- 데모 필드에 변환을 덧붙이는 방법과 공통 UI를 재사용하는 정본 화면 분리를 검토했다. 운영 상태·점유 상태·예정 배정·청구 snapshot·권한별 nullable charges가 서로 달라 전용 DTO와 폼을 선택했다.
- 기존 데모 원장과 별도의 Mock 원장을 만드는 대신 같은 사물함·고객·결제 저장소에 정본 메타데이터를 둔다. 결제가 다른 화면에서도 일관되게 조회되도록 공유 결제 어댑터를 최소 보완한다.

## 3. 결정 및 이유

- 정본 API 경로·생성 DTO·28일 단위·반열린 날짜 구간을 따른다. 가짜 견적 경로를 만들지 않고 서버 4주 요금과 저장 후 서버 확정 청구 금액을 표시한다.
- 관리·일괄 요금은 `operations:write`, 유료 배정·연장은 `payments:write`, 반납은 해당 지점 직원에게 허용한다. 운영 중단 지점·사물함에서도 반납은 허용한다.
- 생성·배정·연장·일괄 요금에 계약상 요청 키를 보내고 같은 입력 재시도는 같은 키를 유지한다. 반납·수정·상태 변경은 버전을 보낸다.
- 조기 반납은 이용 종료만 처리하며 기존 청구와 결제는 보존하고 잔여 요금을 환불하지 않는다. 현재 요금 변경은 과거 청구 snapshot을 바꾸지 않는다.
- 청구 정보는 서버 `charges=null`과 현재 사용자 결제 권한을 함께 반영한다. 권한 회수 후 이전 캐시로 금액을 보충하지 않는다.
- 백그라운드 재조회 중에도 원래 명령의 버전·기간·입력을 유지한다. 409 버전 충돌의 최신값 비교와 기간 충돌의 배정 현황 재조회는 별도로 처리한다.

## 4. 구현 내용

- 기존 공간 탭·ResourcePage·Panel·Field·고객 검색을 재사용해 목록·상세·등록·수정·운영 상태·지점 일괄 요금을 연결했다. Panel의 동기 초기 제목 포커스는 유지한다.
- 유료 배정·연장·반납과 청구 이력·점유 요약을 연결했다. 반납 전 환불 없음 안내를 표시하며 목록·현황·배정 내역을 재조회한다.
- 제출 잠금·취소 신호·권한 문맥 분리·403 세션 갱신·성공 응답 버전 캐시 반영을 공유 hook으로 처리한다. 422 필드 오류와 충돌에서 입력을 보존한다.
- 성공 응답도 식별자·범위·기간·청구 산식·적용/실패 결과를 검증한다. 2xx 결제 실패를 배정·연장 성공으로 가장하지 않는다.
- 실제 UI 시험에서 선택 반납 사유의 빈 문자열을 서버에 보내면 422라는 점을 확인했다. 공백 사유는 요청에서 생략하고 비어 있지 않은 사유만 trim하여 보낸다.
- MSW에서 동일 키 재시도·현재 권한 재검사·기간 경합·중단 상태 점유·연체와 서버 청구 snapshot을 처리한다. 사물함 결제는 공유 결제 원장에 남고 일반 환불 명령은 거부한다.

## 5. 검증 결과

최종 통합 실행과 인수 조건별 근거는 아래에 누적한다. 상세 환경·명령과 실제 HTTP/UI 구분은 [검증 문서](../testing/lockers-live.md)에 남겼다. 중간 시험의 미완성 import 오류, 선택 사유 422, 테스트 선택자 불일치·CSRF 조회 시간 제한은 수정/재검증 대상으로 구분했다.

## 6. 남은 작업 / 보류 사항

- 운영 배포·실제 모바일 기기·부하·다중 인스턴스, Backend 자체 통합 테스트 재실행은 수행하지 않는다.
- 고객 상세의 타 지점 요약·룸/사물함 이력(#25)과 범용 결제 화면의 목적별 안내 후속은 이번 범위가 아니다.
- 작업 브랜치 push·main 대상 PR·CI 확인까지만 진행하고 사용자 병합을 기다린다. main 직접 push·병합·자동 병합은 하지 않는다.
