# 2026-11-08 · 운영 홈 요약 API 연결

## 배경 / 문제

홈은 백엔드 local 프로필의 샘플 경로를 사용해 라이브에서 요약을 표시할 수 없었다. [Frontend #31](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/31)과 [Backend #177](https://github.com/OpenStudyService/OpenStudy-Backend/pull/177)에 맞춰 홈을 정식 집계 API에 연결했다.

## 검토한 선택지와 결정

- 홈에서 목록 데이터를 다시 세는 기존 방식을 걷어내고 서버 요약의 수치·적용 업무 조건·이동 정보를 표시했다. 직원의 첫 요청에서 업무 조건을 생략해 서버의 역할 기본값을 적용한다.
- 업무 전환과 담당자 조건은 홈 URL에서 읽어 요청과 캐시에 함께 반영했다. 목록·상세 이동에는 기존 지점 경로와 검색 파라미터를 사용했다. 근무는 날짜 조건을 읽는 목록 보기를 열고, 동료 근무는 이름과 시각만 표시한다.
- ADR-COM-001에 따라 기존 메뉴 재진입·재클릭과 화면 새로고침을 사용했다. 지점이나 사용자가 바뀔 때 기존 요청과 캐시를 정리하는 공통 동작을 유지했다.

## 구현 내용

- Backend 원격 main의 b9fd53b4 OpenAPI로 Foundation 타입을 재생성했다. 메시지 홈 카드·스키마와 채널 링크를 제거했다.
- 홈과 데모가 같은 요약 계약을 사용한다. 데모는 기존 좌석·업무·문의·시설·근무·공지 데이터에서 카드 내용을 만들고, 홈의 메시지 영역은 AI 화면으로 가는 링크로 바꿨다.

## 검증 결과

- TypeScript, ESLint, Vitest, 라이브·데모 빌드와 두 빌드 격리 검사 통과.
- 컴포넌트·MSW 테스트에서 해당 없음과 0%, 서버 기본 업무 조건과 명시 조건, 지점·계정 전환, 상세 URL 직접 재진입, 메시지·채널 요청 없음, 상충하는 업무 조건의 422를 확인했다.
- Backend 원격 main의 별도 복사본과 격리 MySQL을 npm run dev:live에 연결했다. Chrome에서 소유자·직원 기본 업무 조건과 지점 전환, 두 비율 표시, 업무 상세 열기와 새로고침 복원을 확인했다. 홈의 GET /api/home/summary가 200을 반환했고 레거시 홈·메시지·채널 요청은 없었다.
- graphify update와 git diff --check를 실행했다.

## 남은 작업 / 보류 사항

- 배포 환경과 라이브에서 모든 카드에 데이터가 채워진 조합은 미검증이다. 실제 상세 이동과 새로고침은 업무 카드로 확인했다.
- 백엔드 local 전용 홈 샘플 제거는 백엔드 후속 작업이다. AI 바로가기 대상 화면의 교체는 [Frontend #70](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/70)에서 진행한다.
