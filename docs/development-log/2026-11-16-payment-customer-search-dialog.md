# 2026-11-16 · 결제 관리 고객 검색 모달

## 배경 / 문제

결제 목록에서 고객을 찾으려면 검색 입력, 고객 선택 드롭다운, 고객 페이지 이동을 함께 사용해야 했다. 연락처와 회원번호를 여러 결과에서 비교하기 어려웠고, 고객 검색 도구가 결제 필터바에서 별도 공간을 차지했다.

## 결정 및 이유

결제 관리의 고객 검색을 화면 중앙 모달로 옮겼다. 검색 결과에 이름, 회원번호, 연락처, 상태를 별도 열로 표시해 동명이인을 구분하고 한 번의 선택으로 결제 목록을 좁힐 수 있다. 넓은 화면에서는 페이지 이동이 검색 입력과 같은 줄에 있고, 좁은 화면에서는 줄을 나눠 버튼을 누를 공간을 확보한다.

## 구현 내용

- 모달을 열면 검색창에 초점이 이동하며, 결과를 선택하거나 닫으면 초점이 검색 버튼으로 돌아간다.
- 검색어가 바뀌면 고객 결과의 첫 페이지로 이동한다. 결과 선택 시 기존 URL의 고객 조건에 반영해 결제 목록의 첫 페이지를 조회한다.
- 필터바에서 선택 고객을 확인하거나 해제할 수 있다. 결제 등록과 다른 화면은 기존 고객 선택 UI를 사용하고, 조회와 페이지 상태는 공용 훅을 사용한다.

## 검증 결과

- 결제·고객 선택 관련 Vitest 12개 파일, 154개 테스트 통과. 검색어 전달, 페이지 이동, 고객 선택, URL 반영, 결제 목록 조회, 필터 해제, 닫힌 뒤 초점 복귀를 확인했다.
- 타입 검사, 린트, `git diff --check` 통과.
- Chrome Mock 화면에서 1440px 검색창·페이지 이동의 같은 줄 배치, 390px 모달 너비, 검색·선택·해제 및 Escape 후 초점 복귀를 확인했다.

## 남은 검증
