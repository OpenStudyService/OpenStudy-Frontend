# 조직 관리와 승인 제한 세션의 화면 경계

## 배경 / 문제

B04 서버가 승인 후에도 APPROVAL_ONLY 세션을 유지하도록 보완되면서, 계정 상태만 보고 업무 화면으로 이동하던 기존 프론트는 재로그인 정책을 지키지 못할 수 있었다. F02 조직 관리 진입과 현재 배치의 인증 변경을 함께 검증했다.

## 결정 및 구현

CurrentUser의 선택적 sessionMode를 확인해 제한 세션은 로그인·업무 경로에서 승인 화면으로 이동시킨다. 계정이 활성으로 바뀌어도 제한 모드이면 승인 완료 안내와 재로그인 버튼을 제공한다. 재로그인 버튼은 기존 세션을 로그아웃하고 스트림·개인 상태·쿼리를 정리한다. 제한 세션에서는 업무 lookup이나 스트림을 시작하지 않는다. 이전 시연 응답의 모드 필드 누락은 기존 화면과 호환한다.

직원 관리 메뉴는 관리자 역할과 people:manage 행위 권한을 함께 확인한다. 서버 인가를 UI 숨김으로 대체하지 않는다.

## 검증 결과

- 제한 세션 관련 UI 테스트 4개 통과: 승인 후 제한 유지·재로그인, 로그인 경로 차단, 업무 lookup 미호출, 기존 WORKSPACE 유지.
- Chrome의 조직 관리 흐름 2개 통과: 7요일·익일 운영시간과 멱등 키를 포함한 지점 등록, 단일 지점 소속 PUT의 employeeVersion/version과 이메일 읽기 전용 확인.
- 기존 로그인·전체 화면 smoke 통과.
- 최종 F02 코드와 함께 TypeScript·ESLint·전체 81개 테스트 및 live 빌드 통과.
- Chrome 회귀 13개 흐름의 첫 실행은 11개 통과·2개 실패였다. 기존 `?tab=invitations` URL이 무시되는 실제 회귀를 수정해 탭을 URL로 보존했고, 새 직원 관리 권한 안내에 맞춰 오래된 테스트 문구를 갱신했다. 실패했던 초대 전체 흐름·직원 권한 HTTP 거절 2개를 다시 실행해 통과했으며 이후 전체 81개 테스트와 빌드를 재통과했다.

## 남은 검증

실제 B05/B06 운영 API와의 M1 연동 및 실제 B11 SSE 스트림 검증은 해당 서버 구현 이후에 수행한다. 현재 MSW 인증은 계정 상태로 모드를 계산하는 기존 시연 동작이며, 서버의 고정 모드와 같다고 주장하지 않는다. 제한 모드 UI 테스트는 고정된 실제 서버 응답 계약을 입력으로 사용했다.
