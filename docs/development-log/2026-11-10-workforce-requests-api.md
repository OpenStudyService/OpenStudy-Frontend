# 2026-11-10 근태 정정·대체근무 API 연결 (#38)

## 배경

근무 관리의 정정·대체근무 탭은 데모용 일반 리소스를 사용했다. [Frontend #38](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/38)의 상태·권한·충돌 조건을 [Backend 계약](https://github.com/OpenStudyService/OpenStudy-Backend/blob/86b782a/docs/design/foundation/workforce-requests-api.md)에 맞췄다.

## 결정과 구현

- 기존 근태·근무 상세에서 본인 신청을 시작하고 별도 탭에 처리 이력을 표시한다. 신청 대상은 읽고 있던 기록을 사용하며, 서버가 반환하는 권한과 상태로 처리 버튼을 제한한다.
- 기존 HTTP 클라이언트와 멱등 키 관리 도구를 사용한다. 같은 입력의 실패 후 재시도에는 키를 유지하고, 명령이 진행되는 동안 중복 제출을 차단한다.
- 정정 반려에만 1~500자의 사유를 전송하고 처리 이력에서 응답의 사유를 표시한다. 대체 승인에는 근무 버전을 함께 전송한다.
- 충돌은 서버가 공개한 대상 정보와 함께 표시한다. 입력을 그대로 유지하며, 버전 충돌에서는 목록 새로고침으로 최신 상태를 읽는다. 승인 후 관련 근태·근무 조회를 무효화해 서버 계산값을 다시 읽는다.
- 데모에도 같은 경로를 제공하고 기존 근태·근무 원장을 갱신한다. 휴가 흐름은 [#39](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/39)에서 다룬다.

## 검증

- 타입 검사, lint, 전체 Vitest, live·demo 빌드와 모드 격리 검사를 실행했다. MSW 근무 계약 파일 8개 시험을 통과했다.
- 격리 MySQL 8.4와 Backend `86b782a`, Chrome으로 신규 live E2E 2개를 통과했다. 기존 작업 트리의 Backend 소스와 개발 DB는 검증에 사용하지 않았다.

| 인수 조건 | 결과 |
| --- | --- |
| 실제 신청·승인·반려·취소 | Chrome과 실제 API에서 정정·대체근무 모두 확인했다. 대체 승인 취소로 원래 담당자 복원을 확인했다. |
| 상태·권한별 버튼 | 서버 권한 플래그와 상태로 표시를 제한했다. MSW에서 신청자에게 승인·반려 권한이 없음을 확인했고 live에서 관리자 승인·반려·승인 취소를 실행했다. |
| 승인 후 실근무 분 갱신 | live에서 498분이 468분으로 갱신되는 것을 확인했다. |
| 충돌·버전 대상과 입력 보존 | MSW에서 대기 정정 ID, 비공개 근태 구간 통합, 휴게 ID, 최신 버전과 재조회 대상 응답을 확인했다. 화면의 모든 오류 조합에 대한 브라우저 시험은 수행하지 않았다. |
| 중복 방지 | live에서 동일 키 재전송에 같은 신청 ID가 반환됐고 MSW에서 같은 응답 재생을 확인했다. UI는 진행 중 재호출을 막는다. |
