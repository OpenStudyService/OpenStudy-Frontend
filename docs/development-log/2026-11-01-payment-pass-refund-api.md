# 2026-11-01 — Frontend #20 결제·보유 이용권·환불 실제 API 연결

## 1. 배경 / 문제

[Frontend #20](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/20)은 기존 결제·보유 이용권 화면을 M4 실제 API에 연결하는 작업이다. [Backend #57](https://github.com/OpenStudyService/OpenStudy-Backend/issues/57)·[#58](https://github.com/OpenStudyService/OpenStudy-Backend/issues/58)은 [PR #134](https://github.com/OpenStudyService/OpenStudy-Backend/pull/134)·[#135](https://github.com/OpenStudyService/OpenStudy-Backend/pull/135)로 main에 병합된 상태다.

구현 전에 이슈, 병합 PR, [정본 고객·판매 계약](https://github.com/OpenStudyService/OpenStudy-Backend/blob/d5b68f8346f4ae68edde7e8d1b897bd3894bb286/docs/design/foundation/customer-sales-api.md), 같은 커밋의 OpenAPI, [ADR-M4-002](https://github.com/OpenStudyService/OpenStudy-Backend/blob/d5b68f8346f4ae68edde7e8d1b897bd3894bb286/docs/db/ADR-M4-002.md), 기존 고객 구현 및 [#19 개발 기록](2026-10-29-customer-management.md)을 대조했다. 범용 화면은 `/members`·평면 데모 모델, 관리자 환불 조건, 수동 조정을 사용했다. 정본은 `/customers`, 서버 산정 금액, 유형별 잔량·시작·만료, 원결제 지점 권한과 사용 이력·시각 검증을 요구한다.

Frontend 원격 main `3455f96`에서 `feature/payment-api`를 만들었다. 기존 미추적 `.gitattributes`는 제외한다. 사용자 요청에 따라 API·멱등 처리, UI, MSW 검증을 서브에이전트에 분담하고, 주 에이전트가 계약 대조·통합 리뷰·실제 Backend/DB/Chrome 검증과 전달을 담당했다.

## 2. 검토한 선택지

- 범용 화면에 모든 계약 분기를 추가하면 다른 운영 화면의 데모 필드와 정본 DTO가 섞인다. 기존 메뉴·표·패널·폼·페이지 이동 컴포넌트를 유지하고 결제·이용권 진입을 전용 화면으로 위임했다. 고객 선택은 #19의 정본 고객 어댑터를 재사용한다.
- 환불을 결제 상세에서만 제공하면 `payments:write`만 가진 계산원이 장부 조회 권한 부족으로 환불할 수 없다. 이용권의 원결제 ID·구매 지점을 이용한 환불 경로를 함께 제공했다.
- 멱등 키를 컴포넌트 내부에만 보관하면 응답 유실 후 패널을 다시 열 때 키를 잃는다. 요청자·동작·정규화 본문의 지문에 키를 연결하고, sessionStorage에는 SHA-256 지문과 UUID만 보관한다. 본문·고객 ID·환불 사유 원문은 저장하지 않는다.
- 실제 연동을 MSW 통과만으로 판단하지 않기 위해 병합된 Backend main 독립 사본과 일회용 MySQL을 준비했다. 기존 Backend 작업 브랜치, `.env`, 사용자 DB는 사용하지 않았다.

## 3. 결정 및 이유

- 응답 상태·유형은 OpenAPI의 한글 값을 사용하고, Mock 요청 결과만 `APPROVED`/`FAILED`다. 기존 일반 API 문서의 legacy 결제 필드 대신 M4 정본과 이미 생성된 `foundation.generated.ts`를 따른다.
- 결제 요청은 고객·지점·상품·수단·Mock 결과만 보낸다. 상품 API의 가격은 참고로 보여 주고, 결과 금액은 결제 API의 `amountKrw`로 확정한다. 환불 요청은 `reason`만 보내며 처리 지점은 원결제 지점이다.
- 화면과 생성·환불 결과에 **Mock 결제·실제 금전 이동 없음**을 표시한다. 정식 Mock 결과 선택은 live에서도 제공하고 이전 결제 전용 강제 실패 입력은 제거한다.
- 환불 버튼은 구매 지점 `payments:write`, 승인 결제/활성 이용권, `used=false`, `canRefund=true`, 만료 전 조건을 함께 확인한다. 서버가 요청 처리 시 다시 검증한다. 환불 처리 중 실시간 갱신이나 만료로 힌트가 바뀌어도 열린 폼을 제거하지 않는다. 결과가 불확실하면 사유를 고정하고 동일 키로 재시도한다.
- 동기 ref 잠금으로 같은 이벤트 턴의 중복 제출을 막는다. 응답 유실·서버 오류에서는 키를 보존하고 확정 응답을 받은 의도만 키를 정리한다. 실패 결제의 201도 확정 결과이므로 다음 결제는 새 키다. 계정·지점 변경이나 언마운트 뒤 도착한 응답은 새 화면에 적용하지 않는다.
- 결제 기간의 화면 날짜는 한국 시간 하루 범위로 해석해 UTC ISO 시작 이상·다음 날 시작 미만으로 보낸다. 잘못된 URL 날짜·역전 범위는 요청 전에 안내한다.
- 만료 판정 시각은 `/me`의 `asOf`에 세션 조회 이후의 캐시 경과 시간과 패널 열린 뒤의 경과 시간을 더한다. 클라이언트 날짜나 고정된 데모 시각 차이 때문에 정상 이용권을 만료로 표시하거나 패널 재진입 시 시간이 뒤로 가는 문제를 막는다.
- 데모 고객 입력은 기존 정책상 새로고침 시 고정 fixture로 돌아간다. 신규 고객과 연결된 결제·이용권도 메모리에서만 유지해 고아 참조를 방지하며, 환불 사유는 저장 직렬화에서 제거한다. MSW 구매 조건/멱등 결과의 sidecar는 메모리 전용이다. 실제 영속성은 Backend/DB 시험으로 검증한다.

## 4. 구현 내용

- `features/payments`: 정본 API 어댑터·타입, 결제 목록·지점/상태/기간/고객 필터·정렬·상세·Mock 등록, 고객별 보유 이용권 목록·유형/상태 필터·상세, 전액 환불, 멱등 제출 훅.
- 시간권은 분, 정액권은 원, 기간권은 시작·종료 일시를 표시한다. 모든 이용권에 시작 일시를 표시하고 null 만료는 **만료 없음**으로 표시한다.
- `ResourcePage`/`RecordPanel` 진입 및 기존 권한 안내를 변경한다. 수동 조정 노출을 없애며 매출 집계·직원 관리 기능은 구현하지 않는다.
- `mocks/payments`: 정본 승인·실패·환불·목록·상세·이용권 API를 기존 고객/상품/좌석 데모 원장과 연결한다. 서버 가격, 스냅샷, 사용·만료 판정, 지점 권한, 멱등 충돌과 동시 환불을 검증한다.
- [실제 서버 검증 재현 방법](../testing/payment-live.md)과 전용 `test:e2e:payments:live` 명령을 추가한다. 기존 MSW 및 초대·고객 live 명령과 분리한다.
- 로컬 Backend 통합 시험이 만드는 HTML 보고서가 lint 입력이 되지 않도록 `qa-artifacts/`·`graphify-out/`를 ESLint에서 제외한다. 실제 소스 규칙은 유지한다.

## 5. 검증 결과

### MSW·자동 검사

- `npm run check`: typecheck·ESLint 통과, **36개 파일 / 279개 단위·컴포넌트 시험**, 별도 실제 메일 도구 시험 **9개** 통과.
- 결제 API/멱등 훅 시험 **10개**, 결제 UI 시험 **13개**, MSW 결제 계약·권한·영속화 제한 시험 **8개**가 포함된다. 같은 키 재시도·키 교체·동기 잠금·언마운트 응답·개인정보 비저장·실패 미발급·상태/유형 필터·만료 경계·원지점 권한·서버/클라이언트 시각 차이·세션 캐시 나이를 확인했다.
- `npm run test:builds`: live/demo 프로덕션 빌드 성공, 모드 Chrome 시험 **2개** 통과. live가 MSW/데모 로그인으로 실패를 대체하지 않음을 확인했다. 기존 500kB 번들 크기 권고는 남는다.
- 첫 정적 검사에서 새 MSW listen 옵션의 타입 오류를 수정했다. sandbox 실행에서 로컬 소켓을 사용하는 기존 SSE 시험이 실패해 동일 검사를 소켓 접근 가능한 환경에서 실행했고 통과했다. 로컬 Backend 보고서가 lint에 들어간 문제도 제외 경로로 해결했다.
- 결제 Chrome MSW **3개 통과**: 승인·미사용 전액 환불·원본 보존, 실패 미발급·날짜 필터, 실제 데모 좌석 배정으로 사용 이력을 만든 이용권의 환불 비노출·서버 409. 이는 실제 Backend 검증이 아니다. 데스크톱 및 390px 패널 캡처를 직접 검토했으며 Mock 안내·값·버튼이 보이고 가로 넘침이 없었다.
- 고객·상품·업무·채팅·결제/예약·세 테마·1440/1024/390px·smoke Chrome 회귀 **34개 시나리오를 최종 확인**했다. 첫 실행은 32개 통과, 기존 상품 분류 시험의 MSW 초기화 전 직접 요청(CSRF 불일치)과 세 테마 시험의 45초 제한 초과가 발생했다. 상품 시험에는 화면 준비 대기를 추가했다. 다른 검증이 끝난 뒤 두 사례만 재실행해 **2개 모두 통과(29.5초)**했다. 제품 오류를 가짜 성공으로 대체하거나 실패 검증을 삭제하지 않았다.

### 실제 Backend·DB

Backend main **`d5b68f8346f4ae68edde7e8d1b897bd3894bb286`**의 독립 아카이브를 Java 21로 새로 빌드했다. 사용자 Backend 작업 트리를 수정하지 않았다. 일회용 MySQL 8.4 `payment_live`(loopback **13320**), Backend(**18090**), Vite live(**15180**)와 공식 오프라인 OWNER 초기화를 사용했다.

- 독립 사본의 `PaymentIntegrationTests`: **18개 / 실패·오류·스킵 0**. Testcontainers MySQL에서 실제 HTTP·DB 결제/발급 트랜잭션, 서버 금액, 멱등/동시 처리, 스냅샷, 환불 권한·사용/만료·원본 불변·롤백을 확인했다. 이는 MSW 시험과 다른 실행이다.
- 실제 Chrome **3개 모두 통과**. 초기 전체 통과는 28.2초, 마지막 서버 시각 보완을 반영한 재실행도 3개 통과(1.9분)했다. 서비스 워커를 차단하고 trace를 끈 상태다.
- 세 유형의 실제 UI 승인, 서버 금액 17,500원, 분·원·기간과 시작/만료 없음, 새로고침 후 지속성, 정식 FAILED 요청과 미발급, 결제 상태·고객·지점 필터를 확인했다.
- `route.fetch()`로 실제 서버가 결제·환불을 완료한 뒤 응답 전달만 중단했다. 같은 키 재시도, 결제/이용권 각 1건, 환불 후 새로고침, 원금액·승인 시각 보존을 확인했다. 성공 응답을 가짜 데이터로 대체하지 않았다.
- `payments:read` 조회자의 환불 UI 비노출·직접 환불 403, 범위 밖 조회 거절, `payments:write`만 가진 계산원의 장부 미조회·이용권 경유 환불·원결제 지점 기록을 확인했다.
- 초기 브라우저 실행의 선택 대기는 공통 label에 select option 텍스트가 포함되는 시험 선택자 문제였다. 접근성 role/name 선택자로 수정해 최종 3개를 재실행했다.

## 6. 남은 작업 / 보류 사항

- 이용권 수동 조정·실제 이용 차감(M5), 매출 집계(M9), 직원 관리, 타 지점 환불은 이번 범위에서 구현하지 않았다.
- 운영 HTTPS, 운영 DB, 다중 인스턴스 SSE, 좌석 세션 실제 사용과 연결한 전체 업무 흐름은 검증 범위가 아니다. 사용·만료 환불 거절은 MSW/UI 및 Backend 전용 HTTP/DB 통합 시험으로 확인했다.
- 브라우저 멱등 키는 같은 브라우저 세션의 같은 입력을 재시도할 때 복원된다. 서버 멱등 레코드의 보존 기간을 넘는 장기 복구나 다른 기기 간 복원은 추가하지 않았다.
- 원격 main 직접 갱신, PR 병합·자동 병합은 수행하지 않는다. 작업 브랜치 push 및 PR 준비 후 사용자가 검토·병합한다.

## 7. 전달 기록

- Frontend `graphify update .`: **1,465 nodes / 4,532 edges / 75 communities**. 워크스페이스 전체 그래프도 갱신했다(**8,661 nodes / 19,139 edges / 633 communities**). AST만 실행했으며 LLM/API 비용은 없다. 그래프는 기존 ignore 정책에 따라 로컬에 유지한다.
- 전체 그래프에는 SQL 파서 미설치로 SQL 18개 미추출, Backend Gradle 구문의 부분 추출 경고와 심벌 없는 설정 파일 경고가 남는다. 새 기능 검증을 대신하는 근거로 사용하지 않았다.
- 실제 시험의 Backend PID·포트·명령 및 생성한 컨테이너 ID·이름을 대조한 뒤 해당 Backend와 일회용 MySQL 컨테이너를 종료·제거했다. 자격증명 fixture도 제거했다. 사용자 DB·기존 서버·Backend 작업 트리는 변경하지 않았다.
- `git diff --check` 통과. 위 검증을 확인한 관련 변경만 커밋·push하며 기존 `.gitattributes`는 제외한다. PR의 base는 main이고 사용자가 검토·병합한다.
