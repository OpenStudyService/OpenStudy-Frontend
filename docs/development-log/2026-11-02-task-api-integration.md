# 2026-11-02 업무 화면 실제 API 연결 (#26)

## 배경 / 문제

Frontend #26은 기존 업무 화면의 실제 API 연결 작업이다. 이슈, 기존 PR #37의 구현, 개발 기록, Backend #74 계약 및 #75 구현(PR #138)을 대조했다. Frontend main `5445819`에서 `feature/task-api-integration`을 만들고 기존 목록·폼·상세·체크리스트 UI를 재사용했다. Backend 검증 기준은 main `3bef6413717b65574b4d64a077e7c2899b871094`이다.

## 검토한 선택지

- 데모 DTO를 서버 응답에 맞춰 변환하는 방법과 정본 생성 타입을 업무 기능에서 직접 사용하는 방법을 검토했다. 후자를 선택하여 담당자·작성자 요약, nullable 기한, 버전과 집계 의미가 어긋나지 않도록 했다.
- 채팅·홈이 공유하는 데모 원장을 모두 전환하는 대신 업무 전용 MSW 계약 계층을 추가했다. #27의 채팅 공유 서버 연동을 선행 구현하지 않으면서 기존 데모 흐름을 유지하기 위해서다.
- 실제 검증은 기존 Backend 작업 트리·DB 대신 고정 main을 별도 추출하고 일회용 MySQL에서 수행했다.

## 결정 및 이유

업무 수정, 상태 전환, 체크리스트 변경은 정본의 별도 API를 사용한다. 서버가 반환하는 업무 버전으로 충돌을 처리한다. 수정 권한은 `canEdit`와 현재 세션의 활성·지점 접근 조건을 함께 확인한다. 담당자 등록·변경에는 해당 지점의 활성 후보 API만 사용한다.

409 이후에는 입력을 유지하고 최신값을 비교한다. 재저장은 사용자 변경 필드와 최신 버전만 보내 다른 사용자가 수정한 미편집 필드를 보존한다. 등록은 동기 제출 잠금과 동일 본문 멱등 키 재사용을 적용한다. 응답 중단은 서버 커밋을 취소하지 못하므로 응답 유실·패널 종료 후에도 남은 목록과 집계를 무효화한다.

## 구현 내용

- 검색·내 업무·담당자·상태·기한 범위·기한 초과·정렬·페이지를 URL과 연결하고, 서버 목록·집계 및 처리 이력 페이지를 표시한다.
- 등록·부분 수정·상태 변경과 체크 항목 추가·수정·삭제·완료를 연결했다. 기한은 로컬 시각 입력과 ISO API 값을 변환한다. 자유 분류와 긴급 우선순위를 지원한다.
- 누락된 목록 meta, 집계, 상세 및 저장 성공 응답을 성공이나 0건으로 대신하지 않고 오류로 표시한다. 일시적인 상세 조회 실패로 입력 중인 편집 폼을 제거하지 않는다.
- 고정한 Backend OpenAPI에서 `foundation.generated.ts`를 재생성했다. 전체 생성물이므로 이미 병합된 M5·M7 계약 추가도 포함된다.
- MSW는 업무 전용 계약과 기존 채팅 데모 원장을 연결하고 버전·이력·체크 항목 ID를 유지한다. live 화면에는 채팅 공유 API를 연결하지 않았다.
- 서브에이전트로 계약·UI·MSW 구현과 독립 검토를 분담했다. 사용자의 추가 모델 제한 이후에는 GPT-6.1 Sol, High만 사용했다.

## 검증 결과

최종 소스에서 확인한 결과는 다음과 같다.

- 실제 Backend 자체 통합 검사: 독립 Backend 복사본에서 `TaskIntegrationTests` 16개 통과, 실패·오류·건너뜀 0.
- 실제 Backend·MySQL·Chrome 최종 검사: 4개 전체 통과(약 1분). 등록·재조회, 체크 항목 CRUD, 상태 순환, 두 사용자 409, 권한 403·404, 퇴사자 배정 422, 응답 유실 후 동일 키 재시도와 URL 조건 복원을 확인했다.
- `npm run check`: typecheck·lint 성공, Vitest 38개 파일 308개 테스트, 메일 도구 검사 9개, 빌드 격리 검사 19개 통과. 메일 도구 검사는 SMTP 실발송 검증이 아니다.
- `npm run test:builds`: live/mock 빌드 및 오염 검사 성공, Chrome 산출물 검사 5개 통과. 이 브라우저 검사는 HTTP fixture를 사용한다.
- MSW Chrome 회귀: 채팅·업무·반응형·홈·공유 업무 흐름 19개 중 18개가 전체 실행에서 통과했다. 3가지 테마·여러 화면·재로그인을 순회하는 나머지 1개는 45초 전체 제한으로 종료되어 `--timeout 90000` 단독 재검사에서 통과했다(실제 38.7초). 한 번의 19개 전체 성공으로 기록하지 않는다. 구형 완료 버튼명 단언은 현재의 `할 일로 변경`으로 수정했으며 채팅 코드는 추가 수정하지 않았다.
- 초기 검사에서 구형 빈 업무 응답 fixture를 정본 빈 페이지·집계로 교체했다. 서버 응답 후 바뀌는 체크박스에 대해 즉시 상태를 요구하던 브라우저 단언을 비동기 완료 대기로 수정했다.
- 제한된 실행에서 SSE 소켓 연결이 EACCES로 실패했으며 로컬 소켓 접근이 가능한 재검사는 통과했다. 병렬 빌드·브라우저 검사 중 페이지 이동 시간 초과가 발생하여 재검사했다. 중단 기간에 검증용 DB·서버도 정지되어 해당 일회용 자원만 재시작했다.
- 최종 검토에서 409 이후 원래 값으로 되돌린 명시적 편집을 PATCH에서 누락하는 문제와 원격 삭제된 체크 항목의 편집창이 사라지는 문제를 수정했다. 관련 회귀 3개를 추가하여 UI·모델 검사 24개가 통과했다.
- `graphify update .`: Frontend 1,604 nodes / 4,789 edges, 작업 공간 9,676 nodes / 24,185 edges 갱신. 작업 공간의 SQL 추출 의존성 미설치·기존 Gradle 파싱 경고는 남으며 타입 검사 결과와 별개다.

실제 서버 검증 재현 조건과 정리 절차: [업무 실제 Backend·DB 검증](../testing/task-live.md).

## 남은 작업 / 보류 사항

- #27 채팅 공유 API, 홈의 전체 실제 데이터 연결, 운영 HTTPS·다중 인스턴스 검증은 이번 범위가 아니다.
- 로컬 실제 Backend·DB 결과를 운영 환경 검증으로 간주하지 않는다. 빌드 브라우저의 HTTP fixture 검사도 실제 Backend 검증과 구분한다.
- main 병합은 사용자가 수행한다.
- 실제 검증 종료 후 PID·jar 경로·포트 및 컨테이너 ID를 대조하여 이번 작업의 Backend·일회용 DB만 제거했고 임시 자격 증명 파일을 삭제했다.
