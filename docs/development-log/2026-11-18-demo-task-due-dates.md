# 2026-11-18 데모 업무 기한을 시간대별로 조정

## 1. 배경 / 문제

- 데모 홈과 업무 목록의 기본 업무 3건에 "기한 지남/기한 초과" 배지가 붙어 있었다.
- 원인: 시드 업무 4건의 기한이 모두 날짜만(`2026-10-17`) 있어서 그날 00:00 KST로 해석된다. 데모 기준 시각은 10-17 11:00 KST이므로 완료되지 않은 업무가 모두 기한 초과로 계산됐다.
- README 대표 화면에 기한 초과 업무가 그대로 보여 서비스 인상이 좋지 않았다.

## 2. 검토한 선택지

| 선택지 | 판단 |
|---|---|
| 데모 기준 시각 자체를 최근 날짜로 옮김 | 매출 집계 구간·이용권·예약 등 시드 전체와 테스트가 기준 시각에 묶여 있어 영향이 크다 |
| 업무 기한만 기준 시각 이후의 서로 다른 시각으로 조정 | 문제 화면만 고치고 다른 시드는 그대로 둔다 → 선택 |

## 3. 결정 및 이유

- 기준 시각은 유지하고 업무 4건의 기한에 실제 운영처럼 시각을 넣었다.
- 업무 성격에 맞춰 시각을 나눴다. 오후 예약 전 냉방 점검 13:00, 교대 인수인계 18:00, 저녁 청소 21:30. 이미 완료된 소모품 보충은 오전 10:00로 두었다.
- 모두 기준일 안에 있어 홈의 "오늘 업무" 개수(3건)와 목록 순서는 바뀌지 않는다.

## 4. 구현 내용

- `src/mocks/seed.ts`: 업무 시드에 KST 오프셋을 포함한 기한(ISO 문자열)을 추가하고 각 업무에 적용했다.

## 5. 검증 결과

- `npm run typecheck`, `npx eslint src/mocks/seed.ts` 통과.
- `npx vitest related src/mocks/seed.ts --run`: 42개 파일, 401개 테스트 통과.
- 데모 모드 Chrome 확인: 홈 오늘 업무에 13:00·18:00·21:30 기한과 진행 중·할 일 배지 표시, 업무 관리 "기한 초과 0건".
- 전체 테스트와 Playwright e2e는 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 데모 시계는 탭 실행 중 계속 흐르므로, 오래 열어 두면 13:00 이후에는 냉방 점검 업무가 다시 기한 초과로 보일 수 있다.
