# 2026-11-02 — v8 참고 레이아웃으로 DomainLenz 데모 재구성

## 1. 배경 / 문제

사용자가 `OpenStudy_DomainLens_Demo_v8_Layout_Refined.html`을 참고해 데모를 다시 만들도록 요청했다. 기존 채팅 데모의 데이터 근거와 개인 조회·공유 흐름을 유지하면서 남색 내비게이션, 넓은 대화 영역, 하단 대표 질문과 크기 조절, 실행 추적 구성을 반영한다.

참고 파일은 읽기·화면 확인만 수행했다. SHA-256은 `0CFC93BA9CB5156392D2B9217C4EE875D3BEF2E713FAC4BE050C013E57905BD4`다. 기존 참고 HTML과 이전 전달 ZIP도 수정하지 않았다.

[이전 PR #56](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/56)은 병합 없이 닫혀 있었다. main `242af5b`에서 `feature/domainlenz-demo-layout`과 별도 worktree를 만들고, 이전 구현·기록 커밋만 가져와 이번 개정의 기반으로 사용했다. 기존 main 작업공간의 `.gitattributes`, 이전 데모 worktree와 백엔드 변경은 수정하지 않았다.

## 2. 검토한 선택지

- 첨부 HTML을 별도 복사본으로 운영하는 대신 기존 React 렌더러·시나리오를 확장했다. 단독 파일과 프로젝트 채팅에서 결과와 DB 설명이 달라지지 않게 하기 위해서다.
- 독립 데모에는 참고 파일의 전체 레이아웃을 반영하고, 프로젝트 채팅에서는 기존 앱 외곽 구조를 유지하며 대표 질문·결과를 공유한다.
- 참고 파일의 CSV 승인·자동 업무 기록은 조회 시연 범위를 넘어가므로 구현하지 않았다. 공유 기록·DB 도메인·Trace는 실제로 동작하는 로컬 시연 메뉴로 제공한다.

## 3. 결정 및 이유

- 하단 대표 질문 6개와 전체 예문 갤러리를 함께 제공한다. 질문을 전송하면 추천 영역을 접어 결과에 공간을 준다. 가로폭, 추천/결과 분할, 입력 높이는 사용자가 조절한다.
- 히트맵은 요일·시간대별 입실 시작 건수를 표현한다. 동시 점유율이나 혼잡도 예측으로 과장하지 않는다. 좌석 배치는 기존 지점별 상태 합계와 일치하는 가상 도면이다.
- 기존 34개에 히트맵과 이용권 판매 TOP 5를 더해 36개로 확장했다. 상품·결제·환불 관계 및 추가 필드를 커밋된 DDL과 대조하고 바인딩을 협의용 ViewSpec에 명시했다.
- Trace는 현재 사용자·채널에서 완료·실패·취소된 시연 상태와 결과 명세만 보여 준다. 서버 실행 로그나 실측 시간·정확도를 만들지 않는다.
- worktree 수명과 무관하게 사용할 수 있도록 완성 HTML·문서·화면을 작업공간 `outputs/domainlenz-demo-v8/`에 별도 복사하고 새 이름의 전달 ZIP을 생성한다.

## 4. 구현 내용

- 독립 화면을 남색 메뉴, 상단 상태 표시, 대화창, 하단 추천 영역과 입력창으로 재구성했다. 메뉴는 업무 AI·공유 기록·DB 도메인·실행 추적·데모 안내다.
- 드래그/방향키 분할 조절, 가로폭 슬라이더, 입력 높이 버튼, 추천 접기/펼치기, 모바일 메뉴, Trace 패널, 3개 질문의 워크플로 시연을 추가했다.
- 개별 조회를 취소하면 후속 워크플로도 멈춘다. 새로운 질문·사용자·채널 변경 시 예약된 자동 질문을 정리한다.
- 공통 렌더러에 히트맵·좌석 배치·주간 일정 시각화를 추가했다. 표·상세·KPI·공유 스냅샷은 같은 데이터로 유지한다.
- 대화 결과 스크롤을 해당 대화 영역 안으로 제한하여 전체 페이지와 상단 메뉴가 밀리지 않게 했다.
- `npm run dev:domainlenz`는 전용 진입점에서 로그인·MSW·백엔드 없이 독립 화면만 실행한다(5195). 일반 mock 앱과 live 앱의 기존 명령은 유지한다. 테스트는 사용 중이던 5186을 건드리지 않고 5196을 사용한다.
- README·연동 계약·도메인 사전·기대값 JSON을 갱신하고 v8 개정 안내와 화면 10장을 제공한다. 이전 개발 기록은 보존한다.

## 5. 검증 결과

- `npm run check` 통과: TypeScript·ESLint, 44개 파일/388개 단위·컴포넌트 검사, 메일 도구 가드 9개, 빌드 검사 단위 20개.
- `npm run test:e2e:domainlenz` Chrome 19개 통과: 기존 채팅·업무·테마·반응형과 새 v8 조작을 확인했다. 36개 예문 전체의 오프라인 실행에서 HTTP 요청·런타임 오류가 없고 상태·행 수가 기대값과 일치했다.
- 필드 바인딩 및 워크플로 취소 보완 후 관련 단위 12개, v8 레이아웃/워크플로 Chrome 2개, 타입·린트를 추가 확인했다. 히트맵 35셀, 좌석 80석 중 이용 중 53·가능 24·불가 3, 주간 일정 7일과 예약 3건, 상단 고정·스크롤·공유 열람 제한을 포함한다.
- `npm run test:builds` 통과: live/demo 빌드·산출물 검사와 Chrome 모드 5개. 마지막 바인딩 변경 후 두 빌드·산출물 검사와 lint를 다시 통과했다. live에서 데모 모듈·데이터와 추가 미리보기 진입점이 제외되는 것을 확인했다. 기존 큰 청크 권고 경고는 남는다.
- 전용 `dev:domainlenz`를 5195에서 실행하고 Chrome에서 첫 화면이 열리는 것을 직접 확인했다. 단독 HTML과 개발 서버 화면은 같은 React 진입점을 사용한다.
- 데스크톱·모바일·히트맵·좌석·캘린더·Trace 화면을 캡처해 직접 확인했다. 원본 참고 파일과 완성 화면의 레이아웃을 비교했다.
- `graphify update .` 성공: 1,923 nodes / 5,550 edges / 99 communities. AST만 사용했고 그래프 산출물은 기존 ignore 규칙대로 로컬 유지한다.

## 6. 남은 작업 / 전달

- 실제 DomainLenz·모델·DB 연결, 서버 인가·공유 보관, 정형 API 수치 동등성, CSV 및 성능·비용 측정은 후속 범위다. 시연 성공을 실제 자연어 연동 완료로 처리하지 않는다.
- 독립 화면의 모든 텍스트 입력은 AI 예문으로 처리한다. 일반 프로젝트 채팅은 `@DomainLenz` 호출로 구분한다. 질문 선택은 입력창 준비 단계이며 전송 후 실행한다.
- 전달본은 작업공간 `outputs/domainlenz-demo-v8/OpenStudy_DomainLenz_Demo.html`, 문서·화면을 포함한 ZIP은 `outputs/OpenStudy_DomainLenz_Demo_v8.zip`이다. worktree 없이 파일을 열 수 있다.
- 작업 브랜치 push와 새 PR 준비까지 수행한다. 원격 main 반영·병합·자동 병합은 사용자에게 맡긴다.
