# 2026-11-07 · SSE·polling 제거와 명시적 재조회 전환

## 배경 / 문제

화면을 읽거나 편집할 때 SSE, 주기 조회, 포커스 복귀로 데이터가 바뀌었다. ADR-COM-001과 [Frontend #77](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/77)에 따라 사용자 행동에 맞춰 조회하고, [Backend #175](https://github.com/OpenStudyService/OpenStudy-Backend/pull/175)에서 제거된 경로 호출을 없앴다.

## 검토한 선택지와 결정

- 같은 메뉴 클릭에서 URL을 다시 탐색하는 방식과 현재 화면의 활성 쿼리를 조회하는 방식을 검토했다. 후자는 화면을 다시 마운트하지 않아 검색·필터·정렬·페이지와 입력을 보존하고, 서버 GET을 명확히 실행한다.
- 현재 화면에 공통 새로고침과 성공 조회 시각을 두었다. 여러 결과를 표시하는 화면에서는 가장 오래된 성공 시각을 사용했다. 저장 응답을 캐시에 쓴 시각과 네트워크 조회 시각을 구분했다.
- 조회 오류와 이전 결과를 함께 유지했다. 401이면 로그인으로 돌아간다. 403·404는 기존 접근·누락 오류로 표시하고, 지점 접근 거부가 확인되면 해당 지점의 비공개 상태를 정리한다.
- 저장 후 전체 업무 캐시를 무효화하던 곳은 해당 목록·상세·요약의 쿼리 그룹을 갱신하도록 좁혔다. 예를 들어 휴가 승인 시 휴가 신청 목록, 잔여량, 근무표를 다시 읽는다.

## 구현 내용

- 공통 SSE 연결, 개발 프록시의 SSE 처리, SSE 전용 Mock·테스트와 표시 상태를 제거했다. 근태·승인 대기·팀 채팅의 서버 주기 조회와 Query 창 포커스·재연결 조회를 껐다.
- 메뉴 진입과 같은 메뉴 재클릭, 주요 업무 화면 새로고침, 승인 상태 확인을 연결했다. 계정·지점 변경과 로그아웃·401에서 진행 요청을 취소하고 오래된 결과를 버린다. 기존 폼 이탈 경고와 AI JSON 질문·기록을 유지했다.
- Backend 계약에서 Foundation 타입을 재생성했다. 레거시 OpenAPI 생성기는 기존 Node 환경 변수와 Zod 사용자 정의 스키마 오류로 실행할 수 없어, 체크인된 OpenAPI에서 SSE 항목만 제거하고 해당 타입을 재생성했다.

## 검증 결과

- `npm run check` 통과. TypeScript·ESLint, Vitest 617개, 메일 도구 테스트 9개, 빌드 격리 테스트 19개.
- `npm run build`, `npm run build:demo` 통과.
- 검색 결과 실행 소스와 스크립트에 `EventSource`, `refetchInterval`, 업무·AI 스트림 경로와 서버를 조회하는 `setInterval`이 없다. 남은 두 타이머는 결제 시계와 AI 경과 시간 표시다.
- `graphify update .`와 `git diff --check` 통과.
- Mock 개발 서버의 Chrome에서 화면 접근성과 모바일 레이아웃, 초안 보호, 조회 시각을 확인했다. 새 요청 횟수 테스트는 브라우저 시작 타임아웃 후 재시도에서 통과했다. 포커스·온라인 복구·60초 경과 중 GET 증가가 없고, 같은 메뉴와 새로고침이 기존 조건으로 GET을 각각 한 번 보냈다.
- Mock 개발 서버의 근태 8개·근무 6개는 최초 실행과 실패 케이스 재실행을 합쳐 모두 확인했다. 초대 2개, 채팅 새로고침과 AI JSON 조회·취소도 통과했다. 개발 서버의 첫 탐색·새로고침이 시간 초과되는 경우가 있었다.
- 개발 서버에서 시간 초과된 고객 409와 지점 전환 후 재로딩은 최신 Mock 빌드 미리보기에서 통과했다. 같은 실행에서 재조회 네트워크 검사, 출퇴근·휴게, 휴가 승인·잔여량과 AI JSON도 통과했다. 초대 시나리오는 테스트가 Mock 소스 모듈을 직접 import하므로 미리보기에서는 실행할 수 없었으며, 개발 서버에서 통과했다.
- 격리 MySQL과 Backend `7aaaa1a` 기반 로컬 빌드에 Live Vite 프록시로 연결했다. 두 독립 세션의 지점 저장·재조회와 409, 로그아웃 뒤 401, 제거된 SSE 세 경로의 404를 확인했다. Backend 작업트리에는 기존 요청 로그 출력 수정이 있었다.
- Live Chrome에서 로그인, 마지막 조회 시각, 유휴·포커스·온라인 복구 시 GET 없음, 새로고침·메뉴 재클릭·지점 전환 GET을 확인했다. 두 독립 브라우저 세션에서 저장 변경이 재클릭 전에 보이지 않고 재클릭 뒤 반영되는 것과, 로그아웃 세션의 다음 401이 로그인 화면으로 이동하는 것도 확인했다.

## 남은 작업 / 보류 사항

- 실제 환경에서 다른 직원의 권한 회수, 두 사용자 좌석·예약 경합, 결제 중복과 버전 충돌을 조합한 회귀는 별도 검증이 필요하다.
- 공통 새로고침은 대시보드와 주요 업무 화면에 적용했다. 설정의 지점 목록과 AI 대화 기록에도 공통 버튼과 조회 시각을 둘지 검토가 필요하다. 팀 채팅은 기존 채팅 새로고침을 사용한다.
