# 업무 상세 주요 버튼 색상 후속 수정

## 배경 / 문제

PR #151의 색상 정리 후 사용자가 업무 상세의 항목 추가·수정하기·진행하기·완료하기가 여전히 기본 색상이라고 지적했다. 이전 계획에서는 상세의 진입 버튼과 체크 항목 추가를 보조 작업으로 분류했으나, 사용자의 요청에 따라 이 화면의 주요 작업으로 재분류한다.

## 결정 및 구현

- 기존 `fix/button-action-colors` 작업 단위의 후속 변경으로 PR #151에 포함한다. 원격 main의 최신 e85c791에는 PR #150이 반영되어 있고 PR #151의 변경은 아직 반영되지 않았다.
- 업무 상세의 수정하기와 상태별 진행하기·완료하기·할 일로 변경에 primary를 적용했다.
- 항목 추가와 삭제된 체크 항목 입력 복구의 새 항목으로 추가에도 primary를 적용했다.
- 기존 항목 삭제는 danger, 편집 취소는 보조 스타일을 유지했다. 이벤트·권한·비활성 조건은 수정하지 않았다.

## 검증 결과

- `npx vitest related src/features/tasks/TaskPanel.tsx --run`: 2개 파일·41개 테스트 통과.
- `npm run typecheck`, `npm run lint`: 통과.
- Chrome MSW 일회성 점검 1개 통과. 1440·390px의 업무 상세에서 네 주요 버튼에 primary 적용을 확인하고 실제 캡처를 확인했다. 항목 추가 → 진행 상태 변경 → 완료 상태 변경 후에도 적절한 버튼이 표시되고 primary를 유지하는지 확인했다.
- `git diff --check` 통과, `graphify update .` 코드 그래프 갱신 완료.
- 이번 후속 변경은 버튼 variant 네 곳의 변경이므로 전체 테스트·빌드는 반복하지 않았다. PR #151의 이전 구현 검증인 전체 889개 통과와 구분한다.

## 남은 작업 / 보류 사항

실제 Backend·운영 환경 검증은 수행하지 않았다. 작업 브랜치를 push하고 기존 PR의 변경 사항과 검증 결과를 갱신하며, 병합은 사용자가 수행한다.
