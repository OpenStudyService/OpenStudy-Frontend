# 2026-11-16 AI 채팅 처리 과정을 오른쪽 사이드바에 표시

## 1. 배경 / 문제

- AI 답변마다 처리 과정(접수 → 검색 → 조회 명세 → 검증 → 조회 → 결과 검증)이 접힌 토글(`<details>`)로 붙어 있었다.
- 펼치면 단계 이름과 ms만 한 줄씩 나와서 문제가 있었다.
  - 어느 단계가 오래 걸렸는지 한눈에 보기 어려웠다.
  - LLM을 불렀는지, 캐시를 썼는지 알기 어려웠다.
- 사용자가 오른쪽 사이드바에서 더 직관적으로 보여 달라고 요청했다.

## 2. 검토한 선택지

- **참고 디자인**: DomainLens 결과 목업(`OpenStudy_DomainLens_v9-6_Final_Stage6.html`)의 실행 추적 패널을 따랐다. 번호 아이콘, 세로 연결선, 단계 이름과 설명, 시간이 있고 위에 요약이 있다.
- **사이드바 위치**
  - 대화 오른쪽 고정 열: 넓은 화면에서 답변과 처리 과정을 함께 본다.
  - 좁은 화면에서는 오른쪽에서 열리는 서랍: 결과 차트·표 공간을 줄이지 않는다.

## 3. 결정 및 이유

- 1440px 이상에서는 300px 고정 열, 그보다 좁으면 서랍으로 연다.
  - 처음에는 1280px을 기준으로 했다.
  - 1280px에서는 대화 영역이 약 650px로 줄어든다. 차트와 표를 나란히 놓는 결과에는 좁다고 판단해 1440px로 올렸다.
- 사이드바에는 선택한 답변 하나의 처리 과정을 보여 준다.
  - 기본은 가장 최근 답변이고, 새 질문을 하면 그 답변을 따라간다.
  - 답변의 "처리 과정 N단계 · X초" 버튼을 누르면 그 답변으로 바뀐다. 좁은 화면에서는 서랍이 열린다.
- **조회 계획**은 서버의 조회 명세 단계(`generating`) 이름으로 판단한다. API를 바꾸지 않고 프론트엔드만으로 처리했다.
  - "재사용" → 캐시 재사용(LLM 호출 없음)
  - LLM/Qwen/DomainLens 조회 계획 생성 → LLM 호출
  - 그 외 → 등록 분석 규칙

## 4. 구현 내용

- `ProcessPanel.tsx`(새 파일): 오른쪽 사이드바
  - 질문과 시각을 보여 준다.
  - 요약: 총 소요, 단계 수, 조회 계획.
  - 단계 목록
    - 상태 색: 완료는 기본색, 되묻기·지원 안 함은 주황, 거절·실패는 빨강
    - 단계 이름, 설명, 시간
    - 가장 오래 걸린 단계를 기준으로 한 막대
  - 답변을 기다리는 동안 "처리 중" 상태를 보여 준다.
  - 질문이 없으면 안내 문구를 보여 준다.
  - 좁은 화면에서는 닫기 버튼, 배경 클릭, Escape로 서랍을 닫는다.
- `processStages.ts`(새 파일): 시간 표기와 조회 계획 판단.
- `Ai.tsx`
  - 접힌 토글을 버튼으로 바꿨다. 버튼은 "처리 과정 N단계 · X초"와 조회 계획 표시를 보여 주고, 누르면 사이드바에 그 답변을 띄운다.
  - 사이드바에 표시할 답변을 기억한다.
- `styles.css`: 사이드바, 단계, 버튼, 1440px 미만 서랍 스타일.

## 5. 검증 결과

- `npm run typecheck`, `npm run lint`, `npm test`(861개), `npm run build` 통과.
- 사이드바 테스트를 추가했다.
  - 최근 답변의 단계·시간·조회 계획(LLM 호출)이 보이는지
  - 다음 답변의 캐시 재사용과 거절 단계가 보이는지
  - 이전 답변 버튼을 누르면 그 답변으로 바뀌는지
- 데모 모드(가상 응답)로 화면을 확인했다.
  - 1600px: 대화 974px 오른쪽에 300px 사이드바가 붙고, 가로 스크롤이 없다.
  - 1200px: 사이드바가 숨고, 버튼을 누르면 서랍과 배경이 열리고, 닫기·배경 클릭으로 닫힌다.
  - 창이 최소화되어 있어서 스크린샷은 찍지 못했다. 배치는 요소 크기와 위치로만 확인했다.
- 실제 백엔드(live) 응답으로는 확인하지 않았다. 데모 응답은 단계가 2개뿐이다.

## 6. 남은 작업 / 보류 사항

- 사이드바는 단계 기록만 쓴다. 토큰 수 같은 `securityGate` 정보는 화면 응답에 없어서 보여 주지 않는다.
- 조회 계획 판단은 서버의 단계 이름에 의존한다. 서버 문구가 바뀌면 함께 바꿔야 한다.

## 추가 변경 (2026-11-17): 버튼을 눌렀을 때만 사이드바 표시

### 배경

- 넓은 화면에서 사이드바가 항상 떠 있어 대화 영역이 300px 줄었다.
- 사용자가 "처리 과정" 버튼을 눌렀을 때만 보이도록 요청했다.

### 결정 및 구현

- 사이드바는 닫힌 상태로 시작한다.
- 답변의 "처리 과정 N단계 · X초" 버튼을 누르면 그 답변의 처리 과정이 열린다.
- 같은 버튼을 다시 누르면 닫힌다. 다른 답변의 버튼을 누르면 그 답변으로 바뀐다.
- 열려 있는 동안 새 질문을 하면 새 답변을 따라간다.
- 넓은 화면에서도 닫을 수 있도록 닫기 버튼을 항상 보인다.
- 1440px 미만에서는 열었을 때 오른쪽 서랍이 된다. 닫힌 동안에는 그리지 않으므로 서랍 이동 애니메이션은 없앴다.
- 작업 위치를 워크트리에서 사용자의 `openstudy-frontend` 로컬 브랜치(`feature/ai-process-sidebar`)로 옮겼다. 사용자가 직접 확인하고 승인하기 위해서다.

### 검증 결과

  - 다른 답변으로 바뀌는지
  - 같은 버튼으로 닫히는지
