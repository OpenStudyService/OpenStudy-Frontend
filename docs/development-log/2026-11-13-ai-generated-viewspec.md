# 2026-11-13 AI 생성 결과의 범용 ViewSpec 렌더링 (#122)

## 1. 배경 / 문제

- 백엔드 OpenStudy-Backend#233(PR #236)으로 AI 채팅이 등록 분석에 없는 질문을 생성 경로로 답한다. 생성 결과는 분석 ID가 없고(`GENERATED_EXECUTION`), QuerySpec과 ViewSpec을 서버가 만든다.
- 지금 화면은 생성 결과를 그리지 못한다.
  - 생성 ViewSpec은 카탈로그 컴포넌트 이름(`PaginatedDataTable`, `BarChart`, `KpiGroup` 등)을 쓴다. 화면은 등록 분석용 대문자 이름(`DATA_TABLE`, `BAR_CHART` 등)만 알아서 "지원하는 결과 표시 명세가 없어요."를 보인다.
  - 생성 컴포넌트에는 page·sort·CSV 이벤트가 붙어 있다. 화면은 이벤트가 있는 컴포넌트를 그리지 않는다.
  - 열 이름이 서버 컴파일러 별칭(`d0`, `m0`) 그대로다.
  - 제목·조건은 등록 분석 10개 목록(`POC_QUESTIONS`)에서만 찾는다. 생성 결과는 제목이 "AI 데이터 분석 결과"이고, 조건이 "실시간"·"전체"처럼 사실과 다르게 표시된다.
- 작업 브랜치는 사용자 요청대로 로컬 `main`(5d14147)에서 만들었다.

## 2. 검토한 선택지

- **생성 컴포넌트를 그리는 방법**
  - 렌더러에 새 컴포넌트 종류를 추가한다: 등록 분석 화면 코드까지 바뀐다.
  - 결과를 읽는 단계(`parseAiResult`)에서 생성 컴포넌트를 같은 모양의 기존 종류(표·막대·선·KPI)로 바꾼다(선택). 등록 분석 결과는 이 단계를 거치지 않아 화면이 그대로다.
- **열 이름**
  - 데이터의 열 별칭을 사람이 읽는 이름으로 바꾼다: 결과 상세 표는 정렬 열 별칭을 서버로 보내므로 서버와 어긋난다.
  - 열에 표시 이름(`label`)을 따로 붙인다(선택). 별칭은 그대로 둔다.
- **생성 결과 판별**: QuerySpec의 실행 방식이 `REGISTERED_ANALYSIS`가 아니면 생성 결과다. 다시 연 결과는 결과 분류(`REOPENED`)가 바뀌어도 QuerySpec은 그대로라 같은 기준으로 판별된다.

## 3. 결정 및 이유

- 생성 결과의 표시 이름은 화면에 둔 카탈로그 이름표(`FIELD_LABELS`)에서 가져온다. 백엔드가 응답에 표시 이름을 아직 보내지 않기 때문이다. 이름표에 없는 항목은 카탈로그 ID를 그대로 보여 준다.
- 생성 결과의 조건 편집은 1차 범위에서 제외했다(2026-11-13 결정). 백엔드도 생성 결과에 수정 가능 조건을 주지 않는다.

## 4. 구현 내용

- `domainlens.ts`
  - QuerySpec(하나 또는 저장된 결과의 목록)으로 생성 결과를 판별한다.
  - 생성 컴포넌트를 기존 표시 종류로 바꾸고 이벤트를 비운다. 페이지·정렬·CSV는 결과 화면의 기존 기능이 맡는다.
  - 열에 표시 이름(`label`)을 붙인다.
  - 제목을 "지점별 결제 승인액"처럼 묶음과 지표로 만든다.
  - 조건(`generated`)을 만든다: 지표, 묶음, 기간. 기간은 필터의 [시작, 끝) 시각을 한국 날짜로 바꾸고 양 끝을 포함해 표시한다.
- `Charts.tsx`: 표 머리글, KPI 이름, 차트 계열 이름에 표시 이름을 쓴다.
- `AiConditions.tsx`: 생성 결과의 적용 조건은 분석 종류("AI 생성 조회"), 지표, 묶음, 기간, 지점으로 보인다. "조건 변경" 버튼은 보이지 않는다.
- `AiExports.tsx`, `Ai.tsx`: 차트 내보내기 조건과 적용 조건에 생성 조건을 넘긴다.

## 6. 남은 작업 / 보류 사항

- 표시 이름을 백엔드가 응답에 실어 보내면(카탈로그 메타데이터의 이름) 화면 이름표(`FIELD_LABELS`)를 지운다. 지금은 카탈로그에 지표·항목이 추가될 때 이름표도 함께 고쳐야 한다.
- 생성 결과의 조건 편집은 이후 단계다.
- 실제 백엔드와의 브라우저 확인은 PR #236 병합 뒤에 한다.
