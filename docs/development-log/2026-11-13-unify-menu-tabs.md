# 2026-11-13 · 상품 관리·직원 관리 탭 통일

## 1. 배경 / 문제

상품 관리와 직원 관리의 탭은 일반 버튼처럼 보여 화면 전환용이라는 점을 알아보기 어려웠다. 회원·공간·근무 관리에서 쓰는 탭과 모양, 위치, 키보드 동작을 맞추기로 했다. [이슈 #107](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/107)

## 2. 검토한 선택지

- 두 화면에 기존 Radix Tabs와 스타일을 적용하면 각 화면의 URL 갱신 방식을 해당 화면에서 관리할 수 있다.
- 탭 목록을 공통 컴포넌트로 추출하면 트리거 마크업을 공유할 수 있다. 각 화면의 URL 갱신과 탭 본문은 여전히 별도로 처리해야 한다.

## 3. 결정 및 이유

두 화면에서 `ResourceGroup`과 같은 Radix Tabs와 `tabs`, `tab`, `active` 스타일을 사용했다. 각 화면에 탭이 두 개씩 있고 URL 갱신 방식이 달라 기존 컴포넌트를 직접 사용하는 편이 화면별 동작을 파악하기 쉽다.

## 4. 구현 내용

- 제목 바로 아래에 탭을 배치했다. 상품 목록의 판매 가능 여부 필터와 안내 문구는 상품 목록 탭 본문에 배치했다.
- 분류와 초대·승인은 각각 `tab=categories`, `tab=invitations`를 기록하고 기본 탭으로 돌아가면 `tab`을 제거한다. 상품 탭 전환 시 기존 페이지 초기화를 유지하고, 두 화면의 필터 값과 등록 버튼 노출 조건을 유지했다.
- 두 화면의 탭 역할, 선택 상태, 클릭과 좌우 화살표에 따른 URL 갱신을 시험에 추가했다.

## 5. 검증 결과

- 관련 Vitest 2개 파일, 31개 시험 통과. 타입 검사, 린트, live 프로덕션 빌드와 산출물 검사 통과.
- 첫 `npm test` 실행에서 AI 계약 시험 1개가 5초 제한을 넘겼다. `npm test -- --maxWorkers=4`로 전체를 다시 실행해 87개 파일, 764개 시험이 통과했다.
- Chrome에서 사장님 MSW 데모로 로그인해 상품·직원 관리 탭이 회원·공간 관리 탭과 같은 스타일로 제목 바로 아래에 표시되는지 확인했다. 클릭과 좌우 화살표로 전환하고, 선택 상태와 URL 변경, 새로고침 후 탭 유지, 필터 값과 등록·초대 버튼 노출을 확인했다.
- `graphify update .`로 코드 그래프를 갱신했다.

## 6. 남은 작업 / 보류 사항

- 브라우저 검증은 Chrome의 MSW 데모에서 수행했다. 실제 API 환경과 다른 브라우저는 미검증이다.
