# 지점 휴무일과 상품 판매 기간·한도

## 배경

Frontend #40(FR-BR-09, FR-PROD-10)은 지점 휴무일과 상품 판매 조건을 설정하고 홈·예약·판매 화면에서 제한 사유를 보여 달라는 요구사항이다. Backend PR #200으로 설계 계약이 확정되었고, 실제 동작은 Backend #112·#113에서 구현한다.

## 결정 및 이유

- Backend OpenAPI `0.1.14-m13-operations-extension`의 휴무일 operation과 기존 응답의 `x-planned-changes`를 구분했다. 예정 필드는 화면 타입에서 선택 값으로 읽고 데모 MSW에서 제공한다.
- 사용자가 선택한 방식에 따라 live 빌드에서는 권한이 있는 사용자에게 설정 영역과 서버 업데이트 안내를 표시한다. 휴무일 조회·변경과 상품의 기간·한도 입력은 mock에서 활성화한다. 기존 live 상품 등록·수정은 계속 사용할 수 있다.
- 휴무일은 한국 시간 기준으로 예약이 시작하는 날짜에만 적용한다. 이미 존재하는 예약은 등록 응답에 경고로 표시하고 해당 지점의 예약 목록으로 연결한다.
- 상품 판매 한도는 모든 판매 지점의 승인 결제를 합산한다. 환불하면 다시 판매할 수 있도록 결제 상태에서 판매 수를 계산한다. 상품 PATCH는 변경한 판매 필드만 보내며, 입력을 지우면 해당 제한을 해제한다.

## 구현

- 지점 설정에 휴무일 등록·기간 조회·안내 수정·미래 날짜 삭제를 추가했다. 지점 관리자 역할과 서버의 편집·삭제 가능 여부를 함께 적용한다.
- 홈과 예약 달력에 휴무를 표시한다. 새 예약에서 휴무 날짜를 고르면 시작 시각·이용 시간과 등록을 비활성화한다.
- 상품에 판매 기간·한도·남은 수량과 판매 가능 여부 필터를 추가했다. 판매 중지, 판매 기간 외, 판매 한도 소진에 각각 다른 안내를 표시한다.
- MSW에서 휴무일 생성 재시도, 버전 충돌, 204 삭제, M13 충돌 세부 필드, 상품 판매 판정 순서와 환불 후 수량 복구를 검증한다.

## 검증

- `npm run typecheck`, `npm run lint`, 변경 파일 기준 `npx vitest related … --run` 통과. 관련 테스트는 73개 파일, 633개 테스트다.
- 전체 `npm test` 76개 파일, 650개 테스트 통과. `npm run build`와 `npm run build:demo`는 번들 격리 검사까지 통과.
- `npm run test:e2e:rooms:mock -- --workers=2`에서 7개 통과. 새 휴무일 시나리오에서 등록 → 홈 안내 → 예약 시간 비활성화를 확인했다. 기존 smoke 1개는 상품 화면 탐색 중 `net::ERR_ABORTED`가 발생했으며, 단독 재실행에서 통과했다.
- `graphify update .` 완료. 초기 worktree에는 그래프가 없었고, 갱신 결과는 저장소에서 무시하는 로컬 산출물이다.

## 후속 작업

- Backend #112·#113을 배포한 뒤 실제 OpenAPI 본 정의에 맞춰 타입을 동기화하고 live 설정을 활성화한다. 실제 환경에서 지점별 권한, 예약 경고와 휴무 차단, 판매 제한 등록·해제 및 세 가지 판매 불가 사유를 확인한다.
- live 실제 API 연동은 검증하지 못했다. PR에서 `Refs #40`으로 연결하고 이슈는 실제 연동 확인까지 열어 둔다.
