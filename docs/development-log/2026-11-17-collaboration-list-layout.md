# 2026-11-17 시설·고객 문의·공지 목록을 공통 목록 레이아웃으로 정리

## 1. 배경 / 문제

- 시설 관리 목록의 제목 열이 일반 버튼(`Button`)으로 그려져서, 다른 목록 화면과 달리 행마다 테두리 있는 버튼이 보였다.
- `Records` 컴포넌트는 시설 관리·고객 문의·공지 목록이 함께 쓴다. 이 컴포넌트만 공통 목록 컴포넌트(`ListCard`·`ListFilters`·`ListTable`·`ListFooter`)를 쓰지 않고 카드·필터·표·페이지 이동을 직접 구성하고 있었다.

## 2. 검토한 선택지

- 시설 목록의 제목 셀만 `cell-link`로 바꾸기: 변경은 작지만 필터 바, 표 스타일, 빈 상태와 오류 표시, 하단 페이지 영역이 계속 다른 목록과 어긋난다.
- `Records` 전체를 공통 목록 컴포넌트로 옮기기: 같은 컴포넌트를 쓰는 고객 문의·공지 목록도 함께 바뀌지만, 기준 목록(회원 목록)과 배치와 상태 표시가 일치한다.

## 3. 결정 및 이유

- `Records` 전체를 공통 목록 컴포넌트로 옮겼다. 요청이 "다른 공통 레이아웃처럼"이었고, 세 목록이 같은 컴포넌트를 공유하므로 따로 맞출 이유가 없었다.
- 열 이름, 정렬 기준, 조회·집계 로직은 바꾸지 않았다. 이번 작업은 배치와 표시만 맞춘다.

## 4. 구현 내용

- `src/features/collaboration/Records.tsx`
  - 카드·필터·표·하단 영역을 `ListCard`·`ListFilters`·`ListTable`·`ListFooter`로 교체했다.
  - 제목 셀을 공통 `cell-link` 버튼으로 바꿨다.
  - 등록 버튼을 `ListFilters`의 actions 영역으로 옮기고, 회원 목록처럼 `plus` 아이콘을 붙였다.
  - 로딩·오류·빈 상태 표시는 `ListTable`이 표 안에서 처리한다.
  - 하단 페이지 영역을 `Pager`에서 `ListFooter`로 바꿨다. `총 N건 · N페이지`와 이전·다음 버튼이 표시된다.
  - 표 셀에서 중복되던 담당자·대상 표시 계산을 기존 `assigneeOrTarget` 함수로 합쳤다.

## 5. 검증 결과

- `npm run typecheck`: 통과
- `npm run lint`: 통과
- `npx vitest related src/features/collaboration/Records.tsx --run`: 2개 파일, 24개 테스트 통과
- mock 모드 dev 서버(데모 owner 페르소나)에서 시설 관리·고객 문의·공지 목록이 공통 목록 형태로 표시되는 것을 확인했다. 시설 제목을 클릭하면 상세 패널이 열리는 것도 확인했다.
- 실제 백엔드에 연결한 live 모드 화면은 확인하지 않았다.
- 전체 테스트(`npm test`)와 빌드(`npm run build`)는 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 같은 날 로컬 DB에서 확인한 시설 목록 오류(열린 점검 작업이 없는 시설에서 `openWork: null`이 반환되고 프론트 응답 검증이 이를 거부하는 문제)는 이번 작업 범위에 넣지 않았다. 로컬 DB만 보정했고, 시드 스크립트와 서버·프론트 코드는 그대로다.
