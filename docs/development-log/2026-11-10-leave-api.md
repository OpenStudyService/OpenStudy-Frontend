# 2026-11-10 휴가 부여·신청·승인·잔여량 API 연결 (#39)

## 배경

[Frontend #39](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/39)의 휴가 화면은 데모 원장을 사용했다. [Backend #108 계약](https://github.com/OpenStudyService/OpenStudy-Backend/blob/86b782a/docs/design/foundation/workforce-requests-api.md)을 기준으로 부여·신청·처리·잔여량을 연동했다. 공통 요청·충돌 UI가 들어 있는 [PR #85](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/85) 브랜치에서 시작했다.

## 결정과 구현

- 지점별 권한과 서버 응답의 처리 플래그로 부여 및 처리 동작을 제한했다. 신청 지점에는 본인의 활성 소속을 표시한다. 부여 지점과 대상의 최종 권한 검사는 서버가 담당한다.
- 한국 날짜 기준으로 같은 해의 기간과 달력 일수 상한을 확인한다. 반일 단위 입력 오류를 제출 전에 표시한다.
- 잔여량은 서버 합계를 표시한다. 부여별 원장을 열면 부여·사용·복원과 합계를 표시한다. 승인·승인 취소가 성공하면 열려 있는 목록, 잔여량, 원장을 다시 조회한다.
- 휴가 반려 본문에는 버전만 보낸다. 부여와 신청의 재시도에는 동일 요청 키를 유지한다.
- 충돌 응답에 담긴 근무 시간·식별자와 겹치는 휴가 신청 ID를 표시한다. 공개 범위 밖의 대상은 서버가 제공한 구간이나 겹침 안내로 표시한다. 실패하면 작성 중인 입력을 유지한다.
- 데모에서도 같은 경로와 원장을 사용한다. 기존 데모 주간 근무표가 보는 승인 상태와 동일한 기록을 갱신한다.

## 검증 결과

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run build:demo`와 빌드 모드 격리 검사를 통과했다.
- 전체 Vitest 76파일·648개, MSW 근무 계약 10개. 부여·신청 키 재생, 권한, 기간·일수, 승인·복원 원장, 충돌 대상을 확인했다.
- 격리 MySQL 8.4, Backend `86b782a`, Chrome에서 신규 휴가 live E2E 1개를 통과했다.

## 남은 검증

운영 환경과 실제 API에서 겹치는 승인 휴가를 직접 주입하는 시나리오는 검증하지 않았다. 겹치는 휴가의 공개 범위는 MSW로 확인했다.
