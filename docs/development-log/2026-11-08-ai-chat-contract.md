# 2026-11-08 업무 AI 채팅 계약 전환

## 1. 배경 / 문제

- 프런트엔드 #32·#33·#71의 구현은 정식 계약과 이전 호환 형식을 함께 사용하고 있었다.
- 백엔드 main `109f01c`의 OpenAPI `0.1.12-m10-ai-chat`에는 준비 상태 사유, 지점 확인 선택, 중복 제출 키와 다시 열기 사유가 반영됐다.

## 2. 검토한 선택지

- 기존 지점 매출 차트는 결과 행의 별칭을 직접 가정했다. 이 방식으로는 기간별 매출과 근무시간처럼 서로 다른 지표를 동일한 규칙으로 렌더링하기 어렵고, 누락된 값을 0으로 바꿀 수 있었다.
- 기존 전용 뷰는 유지하고, 일반 차트와 표는 ViewSpec 바인딩과 같은 결과 데이터셋을 사용하도록 했다.

## 3. 결정 및 이유

- 프런트엔드 main의 PR #83 병합 커밋에서 작업을 시작했다. 백엔드 원격 main 커밋의 OpenAPI 사본에서 타입을 생성해 기존 백엔드 체크아웃을 보존했다.
- ADR-COM-001에 따라 질문은 동기 JSON 요청 한 번으로 처리한다. SSE, 재연결, 상태 폴링은 대체된 인수 조건으로 기록했다.
- 입력 한도는 최신 서버 계약의 500자, 화면 대기 제한은 60초로 설정했다. 대기 취소와 제한 시간 경과 시 늦게 받은 결과를 버린다. 전송 결과가 불확실한 경우 재시도에서 요청 본문과 키를 유지한다.
- 권한 변경은 앱 세션 정보와 다음 API 인가 응답에서 감지한다. 지점 전환은 기존 결과를 비우며, 저장 대화를 다시 열면 새 범위를 전달한다.

## 4. 구현 내용

- 준비 상태와 대화 API를 정식 `/api/ai/*` 경로에서 사용한다. 실행 다시 조회 및 `legacyExecution` 의존을 제거했다.
- 질문은 `clientRequestKey`와 함께 보내고 진행 중 전송을 잠근다. 지점 확인 선택은 원래 질문과 선택 ID를 보낸다. 준비 사유, 실패 분류, 다시 열기 거절 사유를 구분한다.
- 허용된 아홉 컴포넌트를 렌더링하며 등록 ID, 버전, 이벤트 유무, 바인딩 및 필드 타입을 확인한다. 값이 맞지 않으면 원본 표 또는 표시 오류를 제공한다. 차트는 표시 범위를 안내하며, 표는 정렬·페이지 이동을 제공한다. 시계열의 0원 값은 서버가 반환한 값을 사용한다.
- 매출 KPI는 바인딩된 데이터셋을 읽고 인기 이용권 순위는 판매 수량을 표시한다. 결과 행의 0과 해당 없음을 구분하고 서버의 잘림과 기준 시각을 표시한다.

## 5. 검증 결과

- `npm run typecheck`, `npm run lint`, `npm test`(76개 파일, 642개 테스트), `npm run build`(live 검사 포함), `npm run build:demo` 통과. Vite는 일부 번들이 500 kB를 넘는다는 경고를 출력했다.
- MSW 계약 테스트에서 실제 화면이 정식 경로로 질문과 대화 목록·다시 열기·제목 변경·삭제를 호출하는 것을 확인했다.
- 컴포넌트 테스트에서 중복 전송 방지, 동일 키 재시도와 REPLAY 표시, 늦은 응답 차단, 준비 사유와 실패별 문구, 지점 선택, 다시 열기 거절, 권한 변경과 세션 만료 후 결과 제거를 확인했다. 렌더러 테스트는 미등록 컴포넌트와 이벤트 거부, HTML의 텍스트 처리, 바인딩 오류, 0과 해당 없음, 시계열·표 정렬을 확인했다.
- 원격 백엔드 `109f01c`의 별도 스냅샷과 임시 MySQL에 `dev:live`를 연결해 브라우저에서 매출 KPI, 지점 확인 선택·재요청, 빈 좌석 결과, 지점 전환 후 이전 결과 제거, 새 범위로 대화 다시 열기, 제목 변경·삭제, 로그아웃을 확인했다. 일별 매출 31행의 시간 순서와 0원 값, 차트 20개 제한, 키보드 초점도 확인했다.

## 6. 남은 작업 / 보류 사항

- #32의 서버 취소는 남아 있다. 동기 응답이 돌아오기 전에는 서버의 requestId나 executionId를 얻을 수 없어 이번 화면의 취소는 브라우저 대기를 종료한다. 백엔드가 실행을 중단하거나 저장 상태를 `CANCELED`로 바꾸는 동작은 검증 범위에 포함되지 않았다.
- 실제 백엔드에서 권한을 회수하는 시나리오와 실제 Qwen 호출은 미검증이다. 권한 회수 화면은 세션 권한 변경을 재현하는 테스트로 검증했다. Live 검증에는 모델 playback과 임시 DB를 사용했다.
- 이 PR 병합 뒤 백엔드에서 호환 경로와 이전 응답 필드를 제거할 수 있다. 정식 질문 응답의 ViewSpec과 ResultEnvelope는 유지한다.
