# 2026-11-12 · 업무 메뉴 새로고침 버튼 제거

## 배경과 결정

[공통 업무 화면의 새로고침 버튼 제거](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/97) 뒤에도 각 메뉴에서 별도로 제공하던 버튼 16개가 남아 있었다. 현재 메뉴를 다시 누르거나 브라우저를 새로고침해 같은 데이터를 조회할 수 있으므로, 일반 재조회 경로를 이 두 동작으로 통일했다.

## 구현

- 공간 관리의 스터디룸·사물함·좌석 현황, 스터디룸 예약, 시설 관리, 고객 문의, 공지사항, 매출 조회와 일별 마감, 근무 관리의 출퇴근 카드·근태 목록·기록 정정·대체근무·휴가 신청 및 승인, 직원 초대, 변경 이력에서 메뉴별 새로고침 버튼을 제거했다.
- 시설·문의·공지의 조회 키에서 버튼 전용 상태를 제거했다. 초대 처리 뒤 목록·상세 반영, 오류 복구, 좌석 이동 및 AI 결과의 작업별 다시 조회는 유지했다.
- 설정의 스터디룸 탭도 공간 관리와 같은 화면을 사용하므로 같은 버튼이 사라진다.
- [화면 갱신 정책](../design/data-refresh-policy.md)과 Backend ADR-COM-001을 갱신했다. [간소화된 승인 대기](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/100)는 화면에 들어오거나 브라우저를 새로고침할 때 상태를 조회한다.

## 검증

- 타입 검사·린트, 관련 Vitest 35개와 전체 Vitest 757개, live 프로덕션 빌드 및 산출물 검사 통과.
- Playwright Mock 환경에서 대상 버튼 16개의 제거와 설정의 스터디룸 탭을 확인했다. 사물함 목록과 집계가 메뉴 재클릭과 브라우저 새로고침 때 재조회되고 상태 필터와 탭이 유지됐다. 스터디룸 조회 오류에서 다시 시도한 뒤 목록이 복구되는 동작과 등록 패널·초대·근태 회귀를 확인했다.
- 실제 백엔드 근태 테스트의 조작을 메뉴 재클릭으로 갱신하고 테스트 검색을 확인했다. 실제 백엔드 연동 실행은 검증하지 않았다.
