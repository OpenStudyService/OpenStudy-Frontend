# 2026-11-13 · 직원 목록 공통 레이아웃 적용 및 권한 프리셋 탭 분리

관련 작업: [#106 기록](2026-11-13-unify-list-layout.md)(공통 목록 레이아웃), #109(상품·입퇴실 이력·출퇴근 적용, PR #116)

## 1. 배경 / 문제

사용자가 직원 관리 > 직원 목록 탭을 회원 목록과 같은 구조로 바꾸고, 그 아래에 붙어 있던 권한 프리셋을 별도 탭으로 옮기도록 요청했다.

- 직원 목록은 라벨 달린 검색 칸 아래에 직원마다 카드(`article`)를 쌓는 형태였다. 상세는 `직원 상세: {name}` 버튼, 페이지 이동은 `organization/shared`의 `Pager`였다.
- 직원 목록 탭 맨 아래에 사장님 전용 `권한 프리셋` 카드가 붙어 있어서 목록과 설정이 한 화면에 섞여 있었다.

이 요청에 대응하는 GitHub 이슈는 없다(열린 이슈 검색 기준).

## 2. 검토한 선택지

- **권한 프리셋 탭 노출 범위**: 프리셋 관리는 원래 `session.user.owner`일 때만 보였다. 탭도 사장님에게만 보이게 했다. 사장님이 아닌 사용자가 `tab=presets`로 들어오면 빈 탭 대신 직원 목록을 보여 준다.
- **프리셋·권한 정의 조회 오류 표시 위치**: 두 조회는 프리셋 탭뿐 아니라 직원 상세의 권한 편집(`권한 프리셋 복사`, 권한 설명)에도 쓰인다. 프리셋 탭에만 오류를 보이면, 직원 목록 탭에서 상세를 열었을 때 프리셋이 비어 있는 이유를 알 수 없다. 그래서 두 탭 모두에 오류를 보인다.
- **프리셋 탭 자체를 표 형태로 바꿀지**: 요청은 탭 이동이었고 프리셋 목록은 필터·페이지가 없는 설정 화면이다. 이번에는 기존 `PresetManagement`를 그대로 옮기고 위쪽 여백만 탭에 맞췄다.

## 3. 결정 및 이유

- 직원 목록 탭은 #106 재사용 방법을 그대로 적용했다(`ListCard` → `ListFilters` → `ListTable` → `ListFooter`). `ListLayout`은 수정하지 않았다.
- 상세는 직원 이름 셀 링크로 연다. 선택 상태는 기존처럼 `useState`로 관리한다. 상품 목록(#109)과 같은 이유로, URL로 옮기려면 단건 조회 흐름이 따로 필요하기 때문이다.
- 직원 목록에는 등록 버튼을 두지 않았다. 직원 추가는 `초대·승인` 탭의 초대 흐름이 담당하므로, 회원 등록 위치에 대응하는 버튼이 원래 없었다.
- 권한 프리셋은 `권한 프리셋` 탭(`tab=presets`, 사장님 전용)으로 옮겼다.

## 4. 구현 내용

- `src/features/organization/EmployeeManagement.tsx`
  - 직원 목록 탭
    - 필터 바에 `직원 이름·이메일 검색`(기존 라벨을 `aria-label`로)과 `초기화`를 둔다. `초기화`는 `employeeSearch`·`employeePage`만 지우고 `tab`은 남긴다.
    - `직원 목록` 표의 열은 직원(아바타, 이름 셀 링크, 사장님 표시), 이메일, 상태, 소속 지점·역할(소속마다 한 줄)이다.
    - 로딩·오류·빈 상태는 표 안에, 페이지 이동은 `ListFooter`로 보여 준다.
  - 탭 목록에 사장님 전용 `권한 프리셋` 탭을 추가했다. 프리셋을 불러오는 동안 로딩을 보여 주고, 프리셋·권한 정의 조회 오류는 공용 `ReferenceErrors`로 두 탭에 같은 방식으로 표시한다.
- `src/features/organization/PermissionPresets.tsx`: 탭의 첫 요소가 되므로 카드의 `mt-5`만 뺐다.
- 시험
  - `Organization.test.tsx`에 두 시험을 추가했다.
    - 표 안 빈 상태, 상세 버튼이 없는지, `초기화` 범위, 프리셋 탭 이동과 프리셋 목록 표시를 확인한다.
    - 지점 관리자에게는 프리셋 탭이 없고, `tab=presets`로 들어와도 직원 목록이 열리는지 확인한다.
  - Playwright `organization`·`usability`와 live `customer-spaces` spec은 `직원 상세:` 버튼 대신 `직원 목록` 표 안의 이름 셀 링크를 찾는다.

## 5. 검증 결과

- `npx vitest related`(직원 관리 관련, 16건)를 실행했고 시험 추가 후 `Organization.test.tsx` 18건이 통과했다.
- `npm run typecheck`, `npm run lint`, 전체 `npm test`(88파일 790건), `npm run build`(live 빌드와 산출물 검사)가 통과했다.
- Playwright MSW 관련 spec(`organization`, `usability`, `invitations`, `workflows`) 22건이 통과했다. 다른 dev 서버를 재사용하지 않도록 15190 포트 임시 설정으로 실행했다.
  - 전체 MSW 스위트는 이번에 실행하지 않았다.
- 화면 확인은 MSW dev 서버(15192)에서 했다. 회원 목록, 직원 목록(강남점·전체 범위), 권한 프리셋 탭을 1440/1024/390px로 Playwright Chrome 스크린샷을 찍고 측정했다.
  - 모든 조합에서 페이지 가로 스크롤과 카드 밖으로 나간 컨트롤이 없었다.
  - 카드 시작 위치가 회원 목록과 같았다.
- 실제 백엔드가 필요한 `tests/live/customer-spaces.spec.ts`는 고쳤지만 실행하지 않았다.
- 직원 상세의 권한 편집과 프리셋 등록·수정을 사람이 직접 클릭해 확인하지는 않았다. `organization.spec.ts`(소속 권한 저장)와 단위 시험으로 확인했다.
- 이 저장소에는 `graphify-out/graph.json`이 없어 graphify 질의·갱신은 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 직원 상세를 URL(`detail`)로 옮기는 작업은 하지 않았다.
- 권한 프리셋 탭을 목록 형태(표·필터 바의 `프리셋 등록`)로 바꿀지는 별도로 정한다.
- 이 브랜치는 `origin/main` 기준이며 #116(상품·입퇴실 이력·출퇴근)과 수정 파일이 겹치지 않는다.
