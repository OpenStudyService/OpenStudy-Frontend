# 2026-11-12 초대 미리보기와 세션 조회 간 요청 취소 수정

## 배경

초대 페이지는 로그인 상태를 조회하면서 메일의 토큰으로 초대를 미리 확인한다. Chrome에서 로그인 상태 조회가 먼저 401을 반환하면 공통 API 클라이언트가 진행 중인 초대 검증까지 취소하는 현상을 재현했다. 브라우저의 취소 예외가 초대 페이지에 그대로 표시됐다.

## 결정

로그인 상태 조회 뒤에 미리보기를 실행하는 방법도 검토했다. 두 요청을 순차 실행하면 미리보기 표시가 늦어지고 다른 업무 요청의 401에 의해 취소될 수 있다. 두 요청을 병렬로 실행하면서 공개 미리보기와 CSRF 조회를 업무 세션의 일괄 취소 대상에서 분리했다.

## 구현

- 미리보기 시도마다 CSRF 토큰을 가져온다. 페이지를 떠나거나 다른 링크로 이동할 때는 화면의 취소 신호로 두 요청을 중단한다.
- 세션 확인이 끝난 뒤 초대 유형과 현재 로그인 상태에 맞는 폼을 표시한다. 유효한 세션이 있으면 계정 역할과 관계없이 신규 계정 등록 전에 로그아웃한다.
- 일시적인 미리보기 실패는 화면에 보관한 초대 토큰으로 다시 시도할 수 있다. 실제 초대 수락에는 기존 인증과 권한 검사를 적용한다.

## 검증

- API 응답을 제어한 Chrome에서 CSRF 조회 중, 미리보기 진행 중, 미리보기 완료 후에 세션 401이 도착하는 경우와 관리자·직원 세션에서 로그아웃 후 같은 화면에서 수락하는 경우를 확인했다.
- 세션 만료 시 업무 캐시 정리, 새 CSRF 토큰을 사용하는 재시도, 기존 계정 수락 및 링크 전환을 관련 Vitest로 확인했다.
- 전체 Vitest 757개, ESLint, 타입 검사와 운영 모드 빌드 및 산출물 검사를 통과했다.
- 운영 서버와 실제 수신함의 링크는 이번 수정에서 검증하지 않았다.
