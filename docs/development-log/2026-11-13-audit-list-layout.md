# 변경 이력에 공통 목록 레이아웃 적용

## 1. 배경 / 문제

별도 메뉴로 이동한 변경 이력에서 검색 폼, 결과 표, 페이지 이동이 따로 배치되어 있었다. 지점 관리와 같은 공통 목록 형태로 맞춰 달라는 요청을 받았다. [공통 목록 PR #114](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/114) · [구현 PR #119](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/119)

## 2. 검토한 선택지

기존 폼과 표의 스타일을 개별 수정하는 방식과 공통 목록 카드·필터·표·하단 페이지 이동을 재사용하는 방식을 비교했다.

## 3. 결정 및 이유

지점 관리와 같은 목록 흐름을 사용한다. 기간·결과·검색·초기화는 첫 필터 바에 두고, 대상·행위·작업자·요청 ID 등은 카드 안의 추가 조건 영역에 배치한다. 표의 행위 셀에서 상세를 열 수 있게 했다.

## 4. 구현 내용

- 로딩·조회 오류·빈 결과를 표 안에 표시하고, 적용 기간과 하단 결과 건수·페이지 이동을 카드에 묶었다.
- 초기화는 감사 검색·페이지 파라미터를 제거한다. 기간 검증, OWNER 권한, 감사 상세 및 같은 요청 검색은 기존 로직을 사용한다.

## 5. 검증 결과

- 타입 검사, 린트와 관련 Vitest 128개를 통과했다.
- Chrome MSW 시험 3개에서 필터 초기화와 행위 셀 상세, 세 역할의 감사 접근 및 1440·1024·390px 레이아웃을 확인했다.
- `graphify update .`로 코드 그래프를 갱신했다.

## 6. 남은 작업 / 보류 사항

이번 후속 변경은 관련 시험을 대상으로 검증했다. 실제 Backend 연결과 전체 테스트·빌드는 다시 실행하지 않았다.
