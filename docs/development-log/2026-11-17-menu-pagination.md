# 2026-11-17 · 메뉴 목록 페이지네이션 통일

## 배경 / 문제

업무 목록과 결제 관리의 고객 검색 모달은 페이지 번호로 바로 이동할 수 있다. 다른 메뉴의 목록 24개는 이전·다음 버튼으로 한 페이지씩 이동했다.

## 결정 및 이유

기존 목록 16개가 사용하는 `ListFooter`에 공용 `Pagination`을 연결하고, 페이지 버튼을 직접 구현하던 근무 관리와 매출 조회의 목록 8개도 같은 하단 영역을 사용하도록 변경했다. 각 화면의 기존 페이지 상태와 변경 콜백을 사용해 조회 조건과 주소 동작을 유지했다.

## 구현 내용

- 공용 하단 영역을 쓰는 회원 목록·보유 이용권, 상품 목록, 결제 목록, 예약 목록 보기, 입퇴실 이력·사물함·스터디룸, 지점 관리, 시설 관리·고객 문의·공지사항, 출퇴근·휴게, 직원 목록·초대·승인, 변경 이력에 적용했다.
- 근무표 목록 보기, 기록 정정, 대체근무, 휴가 신청·승인, 휴가 부여, 상품 판매 순위, 원장, 일별 마감에서 페이지 버튼을 공용 하단 영역으로 교체했다.
- 목록 하단에 전체 건수와 현재 페이지를 표시한다. 첫 페이지의 결과가 한 페이지 이내이면 전체 건수만 표시한다. 조회 중과 오류 상태에는 항목 수 안내를 표시한다.

## 검증 결과

- 전체 프런트엔드 Vitest 95개 파일, 865개 테스트 통과. 페이지 번호로 직접 이동하는 동작, 현재 페이지 표시, 첫·마지막 페이지 버튼 상태, 변경 이력과 매출 원장에서 페이지 이동 시 적용된 검색 조건 유지를 확인했다.
- `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` 통과. 운영 빌드의 산출물 검사도 통과했다.
- Chrome에서 Mock 화면을 열려고 했으나 실행 환경이 로컬 서버 접속을 차단했다. 브라우저 E2E와 운영 API 검증은 수행하지 못했다.
