# 개인 설정과 운영 메뉴 재배치

## 1. 배경 / 문제

개인 설정에서 지점 운영과 변경 이력까지 함께 제공해 기능의 위치를 찾기 어려웠다. 스터디룸 관리는 공간 관리에서도 열 수 있었다. [#108 확정 설계](../design/settings-menu-scope.md)와 [구현 이슈 #111](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/111)의 배치를 적용했다.

## 2. 검토한 선택지

- #108에서 변경 이력을 지점 관리의 OWNER 전용 탭으로 두는 안과 데스크톱 설정 아이콘을 남기는 안을 함께 검토했다. 사용자가 개인 설정을 사용자 메뉴에 모으고, 지점과 변경 이력을 각 운영 메뉴에 배치하는 안을 확정했다.
- 운영 화면은 기존 컴포넌트를 재사용하고, 기존 설정 주소는 인증·지점 검사 뒤 필요한 검색 조건을 전달한다. 전체 검색 문자열을 전달하면 운영 탭과 지점 검색 조건이 섞일 수 있어 목적지별로 사용 중인 항목을 전달했다.

## 3. 결정 및 이유

- 지점 관리에는 기존 조회·수정 권한을 적용해 일반 직원의 담당 지점 운영 정보와 휴무일 조회를 보존했다.
- 변경 이력에는 독립 경로를 부여하고 기존 OWNER 검사를 재사용했다. 같은 요청 보기는 감사 주소에서 요청 ID와 기간을 적용한다.
- 데모 도구를 지연 로딩하는 라우트는 빌드 모드에서 직접 분기했다. 가져온 모드 상수로 분기했을 때 live 산출물 검사에서 데모 청크가 검출됐고, 빌드 시점 분기로 수정했다.

## 4. 구현 내용

- 헤더 사용자 메뉴의 개인 설정은 테마·프로필·비밀번호만 제공한다. MOCK 사용자 메뉴에 데모·검증 도구를 분리했다.
- 매장 운영에 지점 관리를 추가하고 스터디룸은 공간 관리의 기존 탭으로 통합했다. 운영 관리에 OWNER 전용 변경 이력을 추가했다.
- 기존 설정 주소에서 감사·스터디룸·지점 목록으로 이동할 때 지점 범위, 해당 화면의 검색·페이지·상세 조건을 보존한다. 브라우저 뒤로 가기가 기존 주소를 다시 열지 않도록 히스토리 항목을 교체한다.

## 5. 검증 결과

- 관련 Vitest 4개 파일, 54개 테스트에서 기존 주소 호환, 뒤로 가기, 권한 검사를 확인했다.
- `npm test -- --maxWorkers=2` 전체 89개 파일, 798개 테스트 통과. 초기 병렬 실행에서는 매출·회원 테스트 2건이 시간 제한에 걸렸으며 워커를 줄인 전체 재실행에서 통과했다.
- `npm run typecheck`, `npm run lint`, `npm run build`, `npm run build:demo` 통과. live 산출물에 데모 도구 청크와 API가 포함되지 않는지 확인했다.
- Chrome MSW에서 관련 브라우저 시험 11개를 확인했다. 감사·스터디룸 상세 복원을 추가한 최종 역할별 시나리오 3개도 통과했다. OWNER·지점 관리자·일반 직원의 데스크톱·모바일 메뉴, 지점과 스터디룸 버튼, 기존 링크, 감사 요청 차단을 확인했다.
- live·MOCK 산출물의 브라우저 시험 5개를 통과했다. live의 데모 메뉴 비노출·직접 주소 접근 거부와 MOCK의 도구 동작을 확인했다.
- `graphify update .`로 작업 worktree의 코드 그래프를 갱신했다.

## 6. 남은 작업 / 보류 사항

- 실제 Backend·DB를 연결한 브라우저 시험은 실행 범위에 포함하지 않았다. 브라우저 확인은 MSW와 live 빌드의 HTTP fixture를 사용했다.
