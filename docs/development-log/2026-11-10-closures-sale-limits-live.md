# 지점 휴무일·상품 판매 기간과 한도 실제 연동

## 배경

Frontend #40의 데모 동작은 #88에서 구현했다. Backend #112·#113이 main에 들어가 실제 API로 설정을 저장할 수 있게 됐다.

## 결정 및 이유

- Frontend main에 없던 휴무일 경로와 M13 충돌 응답, 휴무일·상품 판매 조건 스키마를 Backend OpenAPI의 본 정의와 동기화했다. 생성 파일의 나머지 계약은 별도 작업과의 범위 및 호환성을 위해 유지했다. Backend main 16a4748에서 #112·#113 정의를 확인했고, 결제·예약의 공유 operation 설명은 후속 고객 병합 문구가 추가되기 전인 ba60ce8 기준으로 반영했다.
- 두 실행 모드에 동일한 설정 화면을 열고 기존 접근 권한과 서버가 내려 주는 편집 가능 여부를 적용했다. 조회 범위는 두 날짜를 함께 보내며 상품 제한을 비우면 null로 보낸다.

## 구현

- 설정에서 OWNER·지점 관리자는 휴무일을 등록·수정·삭제할 수 있고 지점 소속 직원은 조회할 수 있다. 등록 결과에 기존 예약의 룸·시간·상태를 표시한다.
- live 상품 목록에 판매 가능 여부 필터를 열고 등록·수정에서 판매 기간과 한도를 설정하거나 해제할 수 있게 했다.
- MSW의 접근 불가 지점 응답을 403으로, 예약 경고 상태를 확정·이용 중으로 맞췄다. 실제 Backend와 동일하게 조회 날짜 하나만 요청하면 422를 반환한다.
- Chrome 실제 API 검증을 기존 룸 live 설정에 추가했다. Backend main은 git archive로 격리해 빌드하고 합성 계정과 전용 MySQL 8.4를 사용했다.
