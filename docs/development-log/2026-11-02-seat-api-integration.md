# 2026-11-02 좌석 현황·입퇴실·이동 API 연결 (#21)

## 배경 / 문제

Frontend #21을 진행하기 위해 이슈, 기존 ResourcePage 좌석 UI, Backend #60 계약과 #61~#63 구현(PR #139~#141), 후속 계약 정리 PR #143을 대조했다. Frontend main `b13aca6`에서 작업 브랜치 `feature/seat-api-integration`을 만들었다. Backend 기준은 main `adcf15c`이다. 기존 Backend 작업 트리에는 다른 기능 변경이 있어 수정하거나 실행에 사용하지 않았다.

## 검토한 선택지

기존 범용 리소스 화면의 데모 필드를 서버 DTO에 맞춰 계속 확장하는 방법과 좌석 전용 화면·어댑터를 분리하는 방법을 검토했다. 좌석의 현재 이용·정확 일치 조회·퇴실 정산이 일반 CRUD와 달라 전용 기능으로 연결하고, 기존 좌석 그리드 스타일·공통 패널·버튼·오류 표시를 재사용했다.

## 결정 및 이유

- 배치도와 수치는 하나의 board 응답을 사용한다. 유형 필터와 기준 시점이 다른 요청 때문에 어긋나는 일을 방지한다. 전체 지점에서는 별도 occupancy 응답을 표시한다.
- 입실 고객 조회는 연락처가 URL에 남지 않는 정확 일치 POST만 사용한다. 타 지점 고객을 일반 고객 상세 API로 조회하지 않고 최소 응답과 사용 가능한 이용권만 표시한다.
- 입실·퇴실은 유효 소속 직원, 좌석 등록·수정·이동은 operations:write, 운영 중단·재개는 관리자 역할과 해당 권한을 함께 확인한다.
- 서버가 이용·차감·초과량을 계산한다. 종료된 이용 상세의 잔량 null을 0으로 바꾸지 않으며 명령의 처리 직후 잔량과 구분한다.
- 동기 제출 잠금과 동일 본문 멱등 키 재사용을 적용한다. 응답 중단은 서버 커밋 취소를 보장하지 않으므로 남은 화면의 데이터를 무효화하고 재조회한다.
- 서버 처리 뒤 응답만 유실되면 최신 조회에서 이미 점유·이동·종료된 상태가 보일 수 있다. 이때도 권한을 재확인하되 최초 본문·키로 재시도할 수 있도록 요청 대상을 유지하고 명시적인 재시도 버튼을 제공한다.

## 구현 내용

- 구역·유형·상태 필터와 좌석 현황·기준 시점, 등록·부분 수정·운영 상태 변경을 연결했다.
- 정확 일치 조회·이용권 선택·직원 예외 입실·동일 지점 이동·퇴실 결과를 연결했다. 충돌 후 초안 유지·최신 조회를 제공한다.
- 최신 고정 OpenAPI에서 생성 타입을 갱신하고, 정상처럼 보이는 잘못된 응답을 차단하는 런타임 검사를 추가했다.
- 전용 MSW 계층을 기존 좌석·이용권 원장과 연결했다. 새로고침에 필요한 유형·이동·정산 메타데이터를 보존한다. 데모의 멱등 캐시는 현재 메모리 세션에 한정하며 실제 Backend 영속성 검증과 구분한다.
- GPT-6.1 Sol·High 서브에이전트에 API/권한/훅, UI, MSW를 분담하고 상호 검토했다.

## 검증 결과

완료된 검사와 실제 환경 범위는 다음과 같다.

- 초기 API·모델·훅 검사 36개, UI 검사 6개, MSW 검사 22개 통과. 최종 보완 후 전체 검사를 수행한다.
- 고정 Backend 복사본의 HTTP·DB 통합 테스트: SeatIntegrationTests 19개, SeatSessionIntegrationTests 35개, SeatSessionMoveIntegrationTests 16개, 총 70개 통과(실패·오류·건너뜀 0). 브라우저 실제 서버 검증과 별개다.
- 실제 서버 시험에서 `/api/me`가 활성 소속만 반환하며 개별 소속 status를 생략함을 확인했다. 초기 화면은 이를 명시적 활성 값으로만 검사해 STAFF 입실 버튼을 숨겼다. 정본 세션의 생략값을 허용하되 명시적 승인 대기·회수는 차단하도록 수정하고 실제 응답 형태의 회귀 검사를 추가했다.
- 브라우저 시험의 초기 경로를 실제 `/spaces?tab=seats`로 수정했고, select는 접근성 역할로 선택한다. 운영 상태 저장 후 서버 응답과 화면 완료를 기다린 뒤 새로고침하도록 시험을 보완했다.
- 실제 서버 검증 재현 조건: [seat-live.md](../testing/seat-live.md).
- 실제 Backend·MySQL·Chrome: 최종 3개 시나리오 모두 통과(33.4초). 일반 직원의 타 지점 고객 정확 일치 입실, 권한에 따른 이동·수정 버튼, OWNER 이동과 STAFF 퇴실, 종료 상세의 잔량 null, 운영 상태 저장 후 재조회, 등록·입실·이동·퇴실의 실제 커밋 후 응답 유실과 동일 키 재시도를 확인했다. 모바일 퇴실 결과 스크린샷도 확인했다.
- `npm run test:builds`: live/mock 빌드와 산출물 오염 검사 통과, Chrome 산출물 검사 5개 통과. 이는 HTTP fixture 검사이며 실제 서버 검증과 별개다.
- `npm run check`: typecheck·lint 성공, Vitest 43개 파일 376개 테스트 통과, 메일 도구 검사 9개·빌드 가드 검사 19개 통과. 메일 도구 검사는 실제 메일 발송 검증이 아니다.
