# 2026-11-17 처리 과정 사이드바에서 QuerySpec·ViewSpec 확인

## 1. 배경 / 문제

- 처리 과정 사이드바(`2026-11-16-ai-process-sidebar.md`)는 단계와 시간만 보여 줬다.
- 답변이 실제로 어떤 조회 조건(QuerySpec)으로 읽고 어떤 화면 구성(ViewSpec)으로 그렸는지는 볼 수 없었다.
- 사용자가 두 명세도 사이드바에서 확인할 수 있도록 요청했다.

## 2. 결정 및 이유

- 서버 응답(`/ai/queries`, 대화 다시 열기)에는 이미 `querySpec`, `viewSpec`이 들어 있다. API는 바꾸지 않고 프론트엔드에서 답변마다 보관해 보여 준다.
- 표시 방식은 DomainLens 결과 목업의 "개발자 보기 · QuerySpec / ViewSpec"을 따랐다.
  - 단계 목록 아래 "조회 명세"에 두 명세를 접힌 상태로 둔다.
  - 펼치면 들여쓴 JSON을 보여 준다.
  - JSON이 길어 사이드바를 다 차지하지 않도록 접어 두고, 펼쳤을 때도 높이를 제한해 그 안에서 스크롤한다.
- 서버가 보낸 값을 그대로 보여 준다. 가공하면 실제 조회 조건과 달라 보일 수 있기 때문이다.
- 명세를 다른 곳(이슈, 리뷰)에 붙여 넣기 쉽도록 복사 버튼을 둔다.
- 명세가 없는 답변(되묻기, 거절 등)은 이 영역을 보여 주지 않는다.

## 3. 구현 내용

- `Ai.tsx`: 완료된 답변에 `querySpec`, `viewSpec`을 저장하고 사이드바에 넘긴다. ViewSpec이 응답에 없으면 결과 envelope의 view를 쓴다.
- `ProcessPanel.tsx`: 단계 목록 아래에 "조회 명세"를 추가했다.
  - QuerySpec(조회 조건)과 ViewSpec(화면 구성)을 각각 접는 블록으로 보여 준다.
  - 각 블록에 JSON과 복사 버튼이 있다. 복사하면 버튼이 "복사됨"으로 잠시 바뀐다.
- `styles.css`: 명세 블록, 복사 버튼, JSON 영역(최대 높이 20rem, 스크롤) 스타일.

## 4. 검증 결과

- `npm run typecheck`, `npm run lint`, `npm test`(862개), `npm run build` 통과.
- 테스트를 추가했다.
  - 사이드바에서 QuerySpec·ViewSpec을 펼치면 서버가 보낸 JSON이 보이는지
  - 복사 버튼이 QuerySpec JSON을 클립보드에 쓰는지
- 데모 모드에서 확인했다.
  - ViewSpec 블록(JSON 1,437자)과 복사 버튼이 사이드바에 보였다.
  - 데모의 가상 응답에는 QuerySpec이 없어서 QuerySpec 블록은 나타나지 않았다. 의도한 동작이다.
- 실제 백엔드(live) 응답으로는 확인하지 않았다. 창이 최소화되어 있어서 스크린샷도 찍지 못했다.

## 5. 남은 작업 / 보류 사항

- 데모(MSW) 가상 응답에 QuerySpec을 넣으면 데모에서도 두 명세를 볼 수 있다. 이번 범위에는 넣지 않았다.
