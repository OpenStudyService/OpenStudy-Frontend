# 2026-11-05 공통 입력 보호·반응형·접근성 회귀 (#35)

## 1. 배경 / 문제

Backend는 별도 작업자가 개발하고 있어, 새 API 구현을 기다리지 않고 완료 가능한 Frontend #35의 공통 UI와 이미 구현된 화면을 선택했다. 원격 main을 fetch하고 `b716c4b`와 일치함을 확인한 별도 작업 트리에서 `feature/frontend-usability`를 시작했다. 원래 Frontend의 미추적 `.gitattributes`와 Backend 작업 트리·환경 파일은 작업 범위에서 제외했다.

graphify query로 공통 Panel·기존 이탈 경고·반응형 회귀를 찾았다. 업무·회원·좌석·예약·사물함·시설 등의 일부 폼에는 경고가 있었으나 상품·직원/소속·지점·권한 프리셋·결제·근무·초대 폼에는 빠져 있었다. 이탈 hook 세 곳은 거의 같은 로직이었고, 여러 소속 폼에서 각각 React Router blocker를 등록하면 단일 blocker 제약과 충돌할 수 있었다. 기본 반응형·포커스 검증은 있으나 axe 검사는 없었다.

## 2. 검토한 선택지

- 기존 feature hook을 각 화면에서 복사하면 변경량은 작지만, 중복 경고·복수 blocker와 검증 기준 불일치가 남는다.
- 공통 등록소에 각 폼의 dirty 여부만 등록하고 실제 라우터 blocker는 워크스페이스에서 한 번만 적용하면, 여러 폼이 함께 있어도 한 번 묻고 각 저장 상태를 독립적으로 관리할 수 있다.

## 3. 결정 및 이유

두 번째 방법을 선택했다. 기존 hook export를 유지하며 공통 hook으로 연결해 호출부를 불필요하게 바꾸지 않는다. 등록소에는 메모리의 boolean ref만 있고, 값 비교용 초안도 컴포넌트 메모리에 한정한다. 강제 인증 전환·권한 회수는 초안 경고로 막지 않는다.

모달별 등록소로 로컬 상태 기반 닫기도 보호한다. 모달 닫기 승인 후 URL 정리가 이어져도 재차 묻지 않으며, 취소하면 입력을 유지한다. 저장 성공은 서버 응답이 확정된 뒤에만 기준을 재설정한다. 공통 ResourceForm은 상위 저장 함수가 실제 성공 후 호출하는 확정 콜백으로 URL 이동 전에 경고를 해제한다. 실패나 유효성 오류를 저장 성공처럼 취급하지 않는다. 결제 처리 중에는 닫기를 비활성화하고, 수동 로그아웃 확인은 로그아웃 실패 시 초안 보호를 해제하지 않는다.

#35 원문의 전체 최종 검사는 모든 실제 화면 연결 이후 조건이 있으므로, 이번 PR은 공통 기능과 현재 화면 검증 범위를 명시하고 이슈를 자동 종료하지 않는다. 현재 매출·AI 데모 화면 검사와 향후 실제 결과 화면 인수를 구분한다.

## 4. 구현 내용

- `UnsavedChangesBoundary`와 공통 leave/draft hook: 단일 라우터 blocker, 여러 폼 통합, 새로고침·뒤로가기·지점 변경·URL 기반 모드 변경 경고, 폼/모달 unmount 정리.
- 공통 Panel의 닫기·Escape·바깥 클릭 보호와 처리 중 닫기 제한. 기존 초기 제목 포커스·포커스 복귀를 재사용했다.
- 상품·분류·지점·직원 프로필/소속·권한 프리셋·초대/반려 사유·결제/환불·근무 및 공통 폼에 입력 보호를 적용했다. 상품 상세에서 다른 영역의 저장으로 초안/지점 선택이 덮어써질 때도 확인한다.
- 실제 axe 실패에서 근무표 작은 글씨와 사이드바 분류 글씨의 대비를 보완했다. 검사 규칙 제외나 심각도 완화로 회피하지 않았다.
- `@axe-core/playwright`, 전용 로컬 서버의 `test:e2e:usability`와 CI 실행 단계, 재현 문서를 추가했다. 관련 기존 mock 회귀도 같은 명령으로 실행한다.

## 5. 검증 결과

최종 실행 결과를 아래에 누적한다. 중간 실패와 최종 결과를 구분한다.

- 최초 전체 검사는 제한된 셸의 SSE 소켓 EACCES와 ResourceForm의 변경된 확정 콜백 인수에 대한 기존 단언 두 개로 실패했다. 소켓 시험은 권한 있는 실행으로 확인하고, 단언은 기존 payload 검증을 유지하며 새 콜백 계약을 확인하도록 변경했다. 별도 시험으로 실패 시 보호 유지·확정 저장 후 해제를 검증한다.
- 최초 axe는 근무표 작은 글씨 대비, 이어서 데스크톱 사이드바 글씨 대비를 검출했다. CSS 수정 후 각 화면 검사와 테마 검사를 통과했다.
- 중간 Chrome 실행의 잘못된 정확 일치 분류 locator, 취소된 페이지 로드 대기와 구현 중 Hook 위치/구문 오류를 수정했다. 최종 코드 결과와 혼동하지 않는다.
- 기존 mock 근무 회귀는 실패한 등록 초안을 닫는 동작에서 새 확인창을 명시적으로 수락하도록 보완했다. 기존 충돌/입력 보존 단언은 유지했다.

## 6. 남은 작업 / 보류 사항

- #30~#33 등의 실제 화면 연결 후 실제 표·차트·필터·권한별 상태의 최종 #35 재검증. 현재 mock/연결 대기 화면 검사를 실제 Backend 인수로 보고하지 않는다.
- 실제 스크린리더·실기기·400% 확대·모든 동적 상태에 대한 수동 WCAG 판정은 미검증이다. axe serious/critical 통과는 전체 WCAG 준수 인증이 아니다.
- 기존 500KB chunk 경고와 HydrateFallback 경고는 범위 밖이다. 의존성 설치가 보고한 기존/전이 의존성 moderate advisory 10건에 대한 강제 버전 변경은 하지 않았다.
- Backend 코드·환경·개발 DB를 사용하거나 수정하지 않았다. 로컬 시험 서버는 Playwright가 종료한다. 원격 main 반영·PR 병합·자동 병합은 수행하지 않는다.
