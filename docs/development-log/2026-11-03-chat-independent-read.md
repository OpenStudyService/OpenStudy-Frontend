# 본문·스레드별 독립 읽음과 미확인 수 실제 연동 (#27)

## 1. 배경 / 문제

- #27의 기존 채널·메시지·스레드·업무 카드 연결은 PR #59로 제공됐지만 서버 채널 단일 읽음이 확정된 독립 읽음 정책과 달라 live 읽음과 배지를 보류했다. 기존 기록은 수정하지 않고 이번 후속 결과를 남긴다.
- root AGENTS, #27, Backend #155 / 병합 PR #157, 이전 개발 기록과 현재 구현을 확인했다. 양 저장소에서 graphify query를 먼저 실행했다. Frontend 최신 main `6506107` 기준 새 작업 브랜치를 만들었다.
- Backend의 근무표 코드·계약·환경 파일 등 병행 작업과 Frontend 미추적 `.gitattributes`는 제외한다. 타입과 검증 서버는 병합 커밋 `027f692`만 사용한다.

## 2. 검토한 선택지

- 기존 MessageViewport의 가시성·하단 관측과 demo 독립 읽음을 재사용하고 live transport만 정본 ID로 연결한다. sequence를 Number로 합성하면 bigint 정밀도를 잃으므로 live에서는 문자열을 보존하고 BigInt로 비교한다.
- 배지를 로컬 메시지 수로 계산하지 않고 서버 채널 합계/본문/답글 수와 원문별 스레드 수를 사용한다. 실패를 성공으로 가정해 배지를 지우지 않는다.
- 최신 페이지 밖의 원문은 과거 조회 결과만 병합하면 새 답글·다른 세션의 읽음을 놓친다. 로드된 정본 원문은 단건 API로 메타정보도 갱신한다. 이전 답글이 0개였던 원문도 포함한다.

## 3. 결정 및 이유

- 본문은 `POST /channels/{id}/read`의 `messageId`, 스레드는 `POST /channels/{id}/messages/{messageId}/read`의 `replyId`를 보낸다. 요청 키는 없고 같은 대상 재시도는 서버의 단조 증가 처리에 맡긴다.
- 서버 읽음 위치는 마이그레이션·재참여 기준 때문에 답글 또는 다른 스레드 ID일 수 있다. 비교 전용이며 그 ID를 원문 조회 대상으로 사용하지 않는다. 요청 대상보다 작은 응답, 잘못된 스레드·합계를 거부한다.
- 숨겨진 탭·모바일 본문·0 높이·모달 뒤 aria-hidden/inert 영역·하단 밖에서는 읽음을 보내지 않는다. 스크롤·resize·포커스 복귀 시 다시 확인한다.
- 진행 중 읽음이 새 feed로 대체될 때 이전 요청을 취소하고, 이전 요청의 finally가 새 요청의 잠금을 막지 않게 effect별 잠금을 사용한다. 화면/권한/대화 변경 뒤 완료는 캐시를 갱신하지 않는다. 참여 종료의 404도 비공개 화면 정리 경로로 보낸다.
- M7-D09에 따라 Mock에서 재참여자만 최신 전체 위치까지 읽음으로 두며 남은 참가자·신규 참가자의 위치는 유지한다. 회수 후 자동 복귀는 하지 않는다.

## 4. 구현 내용

- 병합 OpenAPI의 새 스레드 읽음 operation·응답·메시지 필드로 생성 타입을 갱신했다. 런타임 검증과 화면 어댑터에 분리된 수·위치를 추가했다.
- 채널 미확인 합계, 본문/답글 구분, 원문별 답글 수·미확인 배지를 표시하고 live 준비 안내를 제거했다.
- 읽음 성공 뒤 채널 수를 재조회하고 스레드 성공 뒤 원문 메타정보도 다시 가져온다. 실패는 명시적 재시도 버튼을 제공한다. 새로고침·전송·과거 페이지·카드 동작은 기존 구현을 사용한다.
- 기존 실제 채팅 시험을 최신 읽음 동작에 맞추고 독립 읽음/동시성/가시성 3개와 HTTP fixture·단위 회귀를 추가했다.

## 5. 검증 결과

최종 결과·인수 조건별 근거와 환경 정리는 아래에 누적한다. [검증 문서](../testing/chat-independent-read-live.md)에 요청 대역·MSW HTTP fixture·실제 서버를 구분했다.

- 집중 채팅 시험은 중간 53개가 통과했다. 새 typed fixture의 초과 속성 오류는 CanonicalMessage 변수로 명시해 수정했다.
- 실제 시험의 첫 실패는 숨겨진 본문 status를 가시 요소로만 찾는 선택자였고, 반복 실행에서 이전 시험 채널의 같은 숫자 배지까지 찾는 선택자도 확인했다. 숨김 포함 DOM 상태와 현재 채널 범위로 한정했다. 서버가 잘못 읽었다는 근거와 구분한다.
- 두 브라우저 신규 시나리오 집중 재실행은 통과했고, 응답 유실·스크롤·동시성·재참여 및 기존 채팅 4개도 중간 실제 서버 실행에서 통과했다. 최종 전체 실행은 아래에 별도로 기록한다.

## 6. 남은 작업 / 보류 사항

- 로드된 원문/카드별 단건 재조회와 채널별 참여자 요청은 추가 요청 수가 생긴다. 대량 데이터의 최적화·부하 측정은 별도 후속이다.
- 운영 V6 마이그레이션·실제 모바일 기기·운영 배포·다중 인스턴스·Backend 자체 전체 통합 테스트 재실행은 미검증이다.
- DM·채팅 전용 실시간 수신은 M14 범위로 남긴다. main 직접 push·병합·자동 병합 없이 작업 브랜치 PR과 CI 결과만 전달한다.
