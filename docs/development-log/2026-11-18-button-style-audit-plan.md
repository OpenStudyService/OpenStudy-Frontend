# 버튼 색상 조사와 수정 계획

## 배경 / 문제

지점 저장 버튼의 주요 색상 누락을 고친 뒤 다른 메뉴의 같은 문제를 조사했다. 사용자는 주요 실행뿐 아니라 승인·반려·취소·삭제 등 색상 구분을 검토할 항목을 모두 조사하고 수정 계획을 작성해 달라고 요청했다.

## 검토와 결정

TSX의 공통·네이티브 버튼 선언 314개와 동적 액션·상태 전환의 실제 동작을 검토했다. 주요 실행 색상 누락 14개 외에도 위험 작업이 기본 스타일이거나 정상 작업과 같은 primary에 고정된 경우가 있었다. 단어에 따른 일괄 변경 대신 실제 실행 결과와 편집 영역의 역할로 색상을 분류한다.

main 기준 `docs/button-style-plan` 브랜치에 [상세 수정 계획](../design/button-style-plan.md)을 작성했다. 삭제·환불·실제 취소·반려·운영 중단은 danger, 정상 실행·승인은 primary, 화면 닫기·조회·재시도는 보조 스타일을 제안한다. 상태 변경은 제한 방향과 복구 방향을 구분하며 정상 퇴실·반납을 취소·환불과 혼동하지 않는다.

## 구현 내용

현재는 계획 문서만 작성했다. 상세 문서에는 누락된 버튼 목록, 추가 위험 작업 목록, 공통 렌더러와 스타일 개선, 작업 순서, 테스트·브라우저 검증 및 인수 조건을 포함했다. 앱 코드는 변경하지 않았다.

## 검증 결과와 한계

- 정적 AST 목록과 소스의 variant·클래스·실제 호출을 대조했다.
- 관련 기존 이슈와 PR #150을 확인했다. 이번 계획의 전용 이슈는 생성하지 않았다.
- 문서 변경이므로 앱 테스트·빌드는 실행하지 않았다. 모든 권한·상태를 브라우저에서 재현한 결과로 주장하지 않는다.
- PR #150의 작업 브랜치 cc890de에서 조사를 진행했다. main 기반 문서 브랜치에는 해당 PR의 구현을 가져오지 않았다. 후속 구현 시 반영 여부를 재확인한다.

## 남은 작업

상세 계획의 기준에 따라 구현 브랜치를 생성해 변경·검증한다. 계획 작성 단계에서 앱 구현이나 PR 생성·병합은 수행하지 않았다.
