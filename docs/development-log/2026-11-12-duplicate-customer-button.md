# 회원 관리 중복 안내 버튼

## 배경

활성 OWNER에게는 중복 묶음이 없어도 회원 관리 상단에 병합 진입 버튼이 표시됐다. 2026-11-12 로컬 개발 DB에서는 중복 묶음이 0건이었으며, 연락처·이메일 유일화는 [Backend #231](https://github.com/OpenStudyService/OpenStudy-Backend/issues/231)에서 다룬다.

## 검토 및 결정

- 중복 확인이 필요한 경우에만 묶음 수를 표시하고, 목록의 필터 줄에서 회원 등록 버튼 왼쪽에 배치했다. 묶음 수가 함께 표시되므로 패널을 열기 전에 확인할 항목이 있는지 알 수 있다.
- 더보기 메뉴도 검토했다. 공용 더보기 메뉴 컴포넌트가 없어 별도 메뉴를 추가하는 비용을 고려해 필터 줄의 보조 버튼을 선택했다.
- 기존 중복 목록 첫 페이지의 `meta.total`을 읽는다. 회원 목록과 패널이 같은 캐시를 사용하면 첫 페이지를 다시 요청하지 않고 패널을 열 수 있다.

## 구현

- 일반 화면과 탭 내부 화면이 같은 필터 줄을 사용한다. 버튼 묶음에 오른쪽 정렬을 적용해 등록 버튼이 없어도 중복 안내가 오른쪽에 놓인다.
- 활성 OWNER에게만 중복 목록을 요청한다. 조회 중이거나 실패했거나 묶음이 0건이면 안내를 숨긴다. 회원 목록은 독립적으로 조회한다.
- 병합 성공 시 공통 고객 저장 훅이 이미 `customers` 읽기를 무효화하므로 중복 묶음 수도 다시 읽힌다. 패널의 표시 상태는 중복 안내 버튼의 표시 조건과 독립적이다.

## 검증 결과

- 관련 Vitest 48개와 전체 Vitest 762개(`npm test -- --maxWorkers=4`)가 통과했다.
- `npm run typecheck`, `npm run lint`, `npm run build` 및 live 번들 격리 검사가 통과했다.
- 목업 Chrome에서 `tests/customer-merge.spec.ts` 1개가 통과했다. 1280px와 375px에서 두 버튼의 오른쪽 정렬과 간격을 확인했고, 375px에서는 필터 줄바꿈과 화면 안에 버튼이 들어오는 것도 확인했다. 중복 0건일 때 버튼이 숨고, 1건을 병합하면 다시 0건을 조회해 버튼이 사라졌다.
- 기본 Playwright 포트에서 실환경 로그인 화면이 열려 별도 포트의 목업 서버로 재실행했다.
- `graphify update .`로 코드 그래프를 갱신했다. SQL 파서가 없어 SQL 파일 3개는 그래프에 포함되지 않았다.

## 남은 작업

- live 테스트의 OWNER 및 비OWNER 버튼 선택자를 새 이름에 맞췄다. 전용 Backend/MySQL과 테스트 계정이 필요한 live 시나리오는 실행하지 않았다.
