# 시간 입력 너비 통일과 종료 날짜 선택 정리

## 1. 배경 / 문제

가로로 합친 종료 입력과 달리 시작 열은 좁아 시간 문자열이 잘렸다. 시작·종료 시간의 너비를 통일하고 날짜 선택에서 다음 날 24:00을 제거해 달라는 요청을 받았다. [표 배치 변경 기록](2026-11-18-branch-time-table-layout.md)의 후속 작업이다.

## 2. 검토한 선택지

남은 열 너비에 맞춰 시간 입력을 늘리는 방식 대신 두 시간 입력의 너비를 고정하기로 했다. 종료 열에는 날짜 선택 영역이 추가되므로 열 전체를 같은 너비로 만드는 방식은 적합하지 않다.

## 3. 결정 및 이유

시작·종료 시간 입력은 모두 9rem(기본 144px)로 고정하고 flex 축소를 막는다. 표의 시작 열과 최소 너비를 이에 맞추고 좁은 화면에서는 표 내부의 가로 스크롤을 사용한다. 날짜 선택 영역도 별도로 확보해 시간 입력의 공간을 침범하지 않게 한다.

날짜 선택은 당일·다음 날만 제공한다. 기존 데이터에 제거된 상한 2880분이 있다면 다른 시간으로 조용히 바꾸지 않고 재선택 안내와 필수 입력 검증을 제공한다. 기본 24시간 운영인 00:00~다음 날 00:00(1440분)은 계속 지원한다.

## 4. 구현 내용

- 시작과 종료의 시간 입력 너비·최소 너비·좌우 여백을 통일했다.
- 종료 시간의 flex 확장을 제거하고 표의 열 너비와 최소 너비를 조정했다.
- 폼의 grid 열과 fieldset 최소 너비를 제한해 표의 최소 너비가 패널 전체를 넓히지 않게 했다. 표 안의 숨김 접근성 라벨은 각 입력·체크박스 내부를 기준으로 배치해 모바일 패널의 스크롤 영역을 넘어가지 않게 했다.
- 다음 날 24:00 선택지와 해당 선택에 따른 읽기 전용 처리를 제거했다.
- 기존 브라우저 시험을 시·분 입력에 맞게 갱신하고 화면 폭별 실제 입력 너비·종료 날짜와 시간의 세로 위치·패널 넘침 검사를 추가했다.

## 5. 검증 결과

- 관련 Vitest 27개 통과. 날짜 선택지 축소와 기존 상한 값의 시간 재선택 검증을 포함한다.
- 타입 검사·전체 린트·diff 검사 통과. 최종 레이아웃 수정 후에도 다시 실행했다.
- Chrome MSW 브라우저 시험 1개 통과. 1440·1024·390px에서 시작·종료 입력의 동일한 144px 너비, 종료 입력 그룹의 중앙 정렬, 패널 가로 넘침 방지, 당일·다음 날만 제공하는 선택지, 야간 운영시간 저장과 재조회를 확인했다.
- 첫 브라우저 시도는 로컬 소켓 권한, 두 번째는 기존 5173 포트의 live 서버 재사용으로 진행하지 못했다. 전용 mock 설정으로 전환했다. 이후 시험에서 기본 선택기의 높이를 고려해 중앙 정렬을 검사하도록 보완하고 모바일의 폼·접근성 라벨 넘침을 수정한 뒤 최종 통과했다.
- 코드 그래프는 최종 레이아웃 변경 후 갱신했다.

## 6. 남은 작업 / 보류 사항

이번 변경 후 전체 Vitest·빌드와 실제 Backend 연동은 다시 실행하지 않았다.
