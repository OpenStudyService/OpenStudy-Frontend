## 결정과 구현

- 지점·기간·용도·환불 기준을 모든 집계가 공유하고 URL에서 복원한다. 상품 페이지와 추세 단위도 URL과 query key에 포함한다. 집계 범위를 바꾸면 상품과 원장 페이지를 초기화하고, 추세 단위를 바꿀 때는 페이지를 유지한다.
- 이용권 API와 판매량 추세의 용도는 계약상 이용권으로 고정되어 있다. 전체 용도와 이용권 선택에서 해당 API를 조회하고, 스터디룸·사물함 선택에서는 이용권 지표에 해당 없음 상태를 표시한다. 매출 추세는 선택한 용도를 그대로 보낸다.
- 같은 응답에서 계산한 차트와 표에 동일한 메타를 붙인다. 백엔드가 요청 사이의 스냅샷을 보장하지 않아 각각의 `asOf`를 사용한다. 원장 항목이나 순위 페이지처럼 개별 조건이 있는 응답도 자체 메타를 표시한다.
- 403이 한 곳에서라도 확인되면 이전에 성공한 집계 결과를 숨긴다. 기존 공통 조회 정책을 사용하며 새로고침은 활성 집계만 다시 요청한다.
- OpenAPI 타입은 백엔드 원격 main 파일을 임시 경로로 받아 기존 생성기와 Prettier로 생성했다. MSW는 기존 결제·환불 원천을 재사용해 판매 당시 스냅샷과 순위, 기간별 버킷을 만든다.
- 공통 형식에서 이용권 원장 증감의 양수 부호를 유지한다. 운영 홈의 비율도 좌석 비율과 같은 소수 첫째 자리 표시를 사용한다.

## 검증 결과

- `npm run typecheck`, `npm run lint`, `npm test`(75개 파일, 623개 테스트), `npm run build`(live 산출물 검사 포함), `npm run build:demo`(demo 산출물 검사 포함), `git diff --check` 통과.
- MSW 계약 검증에서 공통 조건과 페이지·추세 요청 파라미터, query key, 카드·표·차트의 기간·시간대·통화·환불 기준·기준 시각, 기본 날짜, 빈 결과와 403 전환을 확인했다. 기존 테스트로 366일 입력 제한, 지점 선택 권한, URL 복원을 재검증했다. 공통 유틸 테스트는 음수·0·안전 정수 범위를 넘는 bigint·HALF_UP 경계·누락·해당 없음을 다룬다.
- Backend main 독립 사본과 일회용 MySQL에 live 빌드를 연결한 Chrome 테스트 3개를 통과했다. 승인·환불 뒤 매출·판매량·상품 순위·추세·최소 원장, 지점 권한, 빈 기간과 입력 상한을 확인했다. 기존 백엔드 체크아웃 대신 독립 사본을 사용했고 테스트 서버와 DB를 정리했다.
- demo Chrome 매출 시나리오 1개를 통과했다. 세 화면 너비와 테마에서 필터, 빈 기간, 가로 넘침과 심각도 serious·critical 접근성 위반 여부를 확인했다.
- `graphify update .`로 코드 그래프를 갱신했다.
