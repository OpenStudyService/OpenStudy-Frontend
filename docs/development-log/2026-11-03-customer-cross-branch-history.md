# 고객 상세의 타 지점 최소 요약과 룸·사물함 이력 (#25)

## 1. 배경 / 문제

- 룸·사물함 API 연결(#23, #24, PR #62·#63)이 병합됐지만 고객 상세에는 기존 이용권 구매·사용 이력만 연결돼 있었다.
- #25와 Backend #67 계약, #72 및 병합 PR #156의 구현을 확인했다. Backend `613fafd`는 #72 구현과 조회 기록 출처 분리 수정까지 포함한다. Frontend main `38f79e2`에서 작업 브랜치를 만들었다.
- 양 저장소 그래프에 먼저 query를 실행한 뒤 지목된 DTO·서비스·화면·개발 기록을 읽었다. 기존 권한 배열·직원 소속 폼·프리셋은 이미 `customers:cross-branch-read`를 처리하고 있어 중복 구현하지 않았다.

## 2. 검토한 선택지

- 기존 구매·사용 내역 응답에 임의로 공간 이력을 합치는 대신 정본 `/space-history`를 독립 조회했다. 기존 기간 필터는 이용권 사건의 필터이므로 공간 이력에 잘못 적용하지 않는다.
- 타 지점 요약을 자동 조회하거나 Query 캐시에 저장하면 사유별 기록과 결과 수명을 보장하기 어렵다. 사유 입력 대화상자 안에서 명시적으로 POST하고 결과는 해당 화면 메모리에만 둔다.
- 기존 룸 예약·사물함 배정 검증 스키마와 MSW 원장 변환을 재사용한다. 별도 공간 원장이나 가짜 견적·성공 경로를 만들지 않는다.

## 3. 결정 및 이유

- 요약 POST는 조회 기록을 남기는 동작으로 `branchId`(응대 지점)·trim한 1~500자 사유만 보낸다. scope query나 Idempotency-Key를 보내지 않으며 자동 재시도하지 않는다.
- OWNER, 응대 지점의 활성 MANAGER(추가 권한 없이), 활성 STAFF의 개별 권한을 구분한다. 운영 중단 지점에서도 계약상 열람은 가능하다. 일반 고객 목록 범위는 바꾸지 않는다.
- 최소 요약은 이용권 종류·상품·유효 상태·만료 시각, 최근 50건 이용 종류·지점·일시와 기준 시각만 검증·표시한다. 결제 상세 ID 자체가 없으므로 요약에 결제 링크를 추정해 만들지 않는다. 허용 지점 공간 이력의 결제 링크는 대상 지점 `payments:read`일 때만 표시한다.
- 고객·scope·사용자 권한 문맥이 바뀌면 컴포넌트를 새로 만들고 진행 중 요청을 취소한다. 실패는 입력을 보존하고 403은 세션 재검증을 요청한다. 요약 닫기·화면 이탈 뒤 늦은 결과를 무시한다.

## 4. 구현 내용

- 고객 상세에서 룸 예약·실제 이용, 사물함 배정·반납·청구 이력을 지점별 정본 상세로 연결했다. 비어 있는 결과와 조회 오류를 구분한다.
- 사유 입력은 기존 Panel을 재사용한다. Chrome 접근성 검증에서 공통 Panel의 명시적 제목 ID와 Radix 기본 `aria-labelledby`가 달라 대화상자 이름이 비어 있음을 발견했다. Content를 실제 제목 ID에 연결했다. `onOpenAutoFocus`의 동기 제목 포커스는 유지한다.
- 최소 응답의 추가 민감 필드·고객 식별자 불일치·공간 이력의 scope/고객 불일치·중복 ID를 거부한다. 현재 권한으로 캐시된 금액·링크도 다시 제한한다.
- MSW는 기존 공유 원장으로 두 정본 경로를 구현하고, 사유 기록을 일반 고객 가시성이나 정확 일치 조회 자격에 사용하지 않는다.

## 5. 검증 결과

최종 실행 결과와 인수 조건은 아래에 누적한다. [환경과 재현 방법](../testing/customer-spaces-live.md)에 실제 HTTP·UI, MSW, 요청 대역을 구분했다.

- 중간 검증에서 테스트 옵션의 타입 오류(`getByRole`의 `exact`)와 공통 Panel의 접근성 이름 연결을 수정했다.
- 제한된 셸에서 기존 SSE 프록시 검사가 localhost 소켓 `EACCES`로 실패했다. 제품 실패와 구분하고 로컬 통신이 허용된 환경에서 전체 검사를 재실행한다.

## 6. 남은 작업 / 보류 사항

- 운영 배포·실제 모바일 기기·부하·다중 인스턴스 및 Backend 자체 통합 시험 재실행은 범위 밖이다.
- 기존 미추적 `.gitattributes`, Backend `poc.env` 및 다른 작업은 수정·커밋하지 않는다. 생성한 별도 검증 환경만 정리한다.
- 작업 브랜치 push·main 대상 PR 생성·CI 확인 후 사용자 병합을 기다린다. main 직접 push·PR 병합·자동 병합은 하지 않는다.
