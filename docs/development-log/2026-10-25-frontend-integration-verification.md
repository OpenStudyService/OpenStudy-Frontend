# 초대 UI 및 직원 상세 버전 공유의 결합 검증

## 배경과 결정

초대 UI(PR #11, `594860c`)와 직원 상세 버전 공유 수정(PR #12, `4255a54`)은 같은 직원 관리 파일을 변경했다. main과 분리된 로컬 `chore/frontend-integration-check`에 두 브랜치를 합쳐 최종 조합을 검증했다. 소스 충돌 없이 결합됐다.

## 자동 검증

결합 브랜치에서 `npm run check`와 `npm run build` 성공. TypeScript·ESLint 및 전체 Vitest 95개(13개 파일), live 빌드가 통과했다. 개별 초대 UI의 Chrome 4개 흐름 결과는 해당 작업 로그를 참조한다.

## 실제 백엔드·브라우저 검증

MSW를 끈 live 모드에서 B04 복구·B05·B06 결합 서버와 일회용 MySQL 8.4.11을 사용했다. 직원 생성/소속은 검증용 SQL로 준비했으며 초대 API·메일 검증으로 간주하지 않는다.

1. 같은 직원 상세 창에서 계정 이름과 두 번째 지점 권한을 미리 편집한 뒤 첫 지점 소속을 저장했다. 미저장 입력을 유지했다.
2. 두 번째 소속, 계정 정보를 순서대로 저장했다. 불필요한 409 없이 모두 성공했다. SQL로 직원 DB version 3, 두 소속 DB version 각각 1 및 각각 8개 권한을 확인했다.
3. 새 상세 화면을 열어 같은 직원을 조회한 뒤 원래 화면에서 추가 저장했다. 새 화면의 오래된 계정 저장은 실제 409를 반환했고 입력한 이름과 요청 ID, 최신 버전 확인 버튼이 유지됐다.

## 남은 범위

초대 서버 B07~B09, 실제 메일 수신 링크 및 B11 SSE의 즉시 갱신·회수는 이번 결과에 포함하지 않는다. 공통 lookups 미제공 안내는 화면에 표시됐다. TLS·운영 프록시 검증도 별도다. 원격 main은 변경하지 않았으며 사용자 PR 병합을 기다린다.
