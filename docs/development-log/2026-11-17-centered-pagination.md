# 2026-11-17 · 공용 페이지네이션의 현재 페이지 배치

## 배경 / 문제

회원 관리에서 현재 페이지 주변에 인접 번호를 배치하는 방식을 확인한 뒤, 나머지 번호형 페이지네이션에도 같은 동작을 적용하기로 했다.

## 결정 및 이유

번호 범위 계산을 공용 `Pagination`의 기본 동작으로 설정했다. 회원 관리에서 확인할 때 사용한 옵션을 제거해 화면마다 별도로 설정하지 않아도 같은 범위를 표시한다.

## 구현 내용

- 현재 페이지를 가능한 경우 다섯 번째에 두고, 범위의 양 끝에서는 번호를 최대 10개까지 채운다.
- 업무 관리와 결제 관리의 고객 검색 모달은 공용 컴포넌트를 직접 사용한다. 나머지 24개 메뉴 목록은 공용 목록 하단 영역을 통해 같은 배치를 사용한다.

## 검증 결과

- 전체 프런트엔드 Vitest 95개 파일, 871개 테스트 통과. 이전·다음 버튼과 번호 직접 이동, 현재 페이지 표시, 범위 양 끝을 확인했다.
- `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` 통과.
- 23페이지를 재현한 Mock 응답으로 Chrome의 1440px·390px 뷰포트에서 업무 관리, 변경 이력, 결제 관리의 고객 검색 모달을 확인했다. 12페이지가 다섯 번째에 표시되고 13페이지로 이동하면 번호 범위가 바뀌었다.
- 운영 API 검증은 수행하지 않았다.
