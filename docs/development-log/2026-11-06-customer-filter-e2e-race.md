# 2026-11-06 회원 URL 필터 E2E의 경합 제거

## 1. 배경 / 문제

- 문서만 바꾼 PR #72의 CI(`test:e2e:usability`)에서 `tests/customers.spec.ts`의 "URL filters survive reload…" 테스트가 실패했다.
- 새로고침 후 `회원 상태 필터`가 `정상`이 아니라 빈 값이었다. 같은 커밋 기준 `main`에서는 통과했으므로 변경과 무관한 간헐 실패다.

## 2. 검토한 선택지

- CI 재실행만 한다: 원인이 남아 다른 PR에서도 다시 실패할 수 있다.
- 테스트가 각 필터 변경의 화면 반영까지 기다리게 한다: 실제 사용자 흐름(한 번에 하나씩 바꾸기)과 같고, 앱 코드를 바꾸지 않는다.

## 3. 결정 및 이유

- 테스트를 고쳤다. 필터 변경은 라우터가 마지막으로 렌더링한 검색 파라미터를 기준으로 URL을 다시 쓴다. 브라우저 URL은 렌더링보다 먼저 바뀌므로, 기존 테스트처럼 URL만 확인하고 다음 필터를 바꾸면 느린 CI에서 이전 렌더링 기준으로 URL이 다시 쓰여 `status`가 빠질 수 있다(추정 원인, CI 아티팩트가 없어 직접 확인하지 못함).

## 4. 구현 내용

- 각 `selectOption` 뒤에 해당 컨트롤이 그 값을 표시할 때까지 기다린다(제어 컴포넌트라 렌더링 반영 후에만 값이 바뀐다).
- 새로고침 전에 `q·status·sort·direction·pageSize`가 모두 URL에 함께 남았는지 한 번에 확인한다.

## 5. 검증 결과

- `npm run test:e2e:usability`: 29개 통과.
- `customers.spec.ts` 5회 반복: 20개 통과.
- 로컬에서 원래 실패를 재현하지는 못했으므로, 원인 가설은 CI 재실행으로만 간접 확인된다.

## 6. 남은 작업 / 보류 사항

- CI에 포함되지 않은 기본 설정(`npm run test:e2e`)에서 `tests/workflows.spec.ts:100`이 로컬에서 계속 실패한다(예약 등록 폼의 `회원` 라벨을 찾지 못함). 이번 범위 밖이며 별도 확인이 필요하다.
