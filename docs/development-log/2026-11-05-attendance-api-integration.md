# 2026-11-05 본인 출퇴근·근태 실제 API 연동 (#29)

## 1. 배경 / 문제

[이전 기록](2026-11-04-workforce-api-integration.md)은 근무표만 연결하고 Backend #84를 기다렸다. 이후 Frontend [PR #66](https://github.com/OpenStudyService/OpenStudy-Frontend/pull/66)과 Backend [PR #160](https://github.com/OpenStudyService/OpenStudy-Backend/pull/160)이 병합되어 #29의 남은 실제 연동 조건이 준비됐다. 이전 기록은 당시 판단으로 남기고 이번 기록에서 변경 이유를 추가한다.

Frontend main `ac006f2` 기준 `feature/attendance-api-integration` 별도 작업 트리에서 진행했다. Backend의 별도 main 사본 `aa2ebc8`에서 #82 계약과 #84 구현을 읽고, OpenAPI를 재생성해 타입에 차이가 없음을 확인했다. 기존 작업 트리와 환경 파일은 보존한다.

## 2. 검토한 선택지

- 기존 데모 `/attendance/*` 명령을 바꾸는 방식은 lookup의 오래된 현재 상태와 데모 필드를 계속 의존한다.
- 현재 상태·목록·상세를 계약 API로 분리하면 전역 본인 상태와 탐색 지점의 조회 범위를 각각 정확히 다룰 수 있다.
- 명령 응답을 곧바로 현재 상태에 넣으면 출근의 멱등 재생 응답이 이미 퇴근한 과거 `근무 중`일 수 있다. 따라서 현재 상태를 별도로 재조회해야 한다.

## 3. 결정 및 이유

현재 상태는 지점 선택과 독립적인 본인 조회로 관리한다. 모든 명령 후 성공·실패 여부와 관계없이 서버 현재 상태를 재확인하고, 출근 재시도에는 같은 입력의 요청 키를 유지한다. 휴게·퇴근은 현재 version만 전송하고 자동 재시도하지 않는다. 조회 실패·잘못된 응답은 빈 현재 상태나 성공으로 바꾸지 않고 명령을 차단한다.

실근무 분은 클라이언트 타이머로 추정하지 않는다. 진행 중에는 `퇴근 후 확정`, 퇴근 뒤에는 서버가 반환한 분을 목록·상세·주간·근무 연결 요약에서 표시한다. 같은 UI와 계약을 mock에도 적용하되 mock 구현은 live 번들에서 제외한다.

## 4. 구현 내용

- 본인 출근 지점 선택·휴게 시작/종료·퇴근을 `/me/attendance/*`에 연결했다. 시각·직원 ID·근태 ID를 명령 본문으로 보내지 않는다.
- 출근 선택은 실제 활성 소속이며 운영 중인 지점만 허용한다. OWNER 전역 권한을 소속으로 간주하지 않는다. 진행 중 근태의 휴게 종료·퇴근은 소속이 회수돼도 허용하고, 휴게 시작은 현재 소속이 있어야 한다.
- 현재 상태를 확인하기 전·재조회 중·오류일 때 명령을 비활성화한다. 허용되는 상태의 버튼만 노출하고, 진행 중 근태는 다른 지점을 탐색해도 유지한다.
- `/attendance-records` 목록·상세에 날짜·상태·본인·직원 필터와 페이지를 연결했다. 직원 화면에는 직원 선택이나 관리 기능이 없고, 실제 접근 권한은 서버가 확인한다. 상세는 조회 전용이다.
- 계약 응답을 런타임 검증해 비정상 current/list/detail을 성공으로 받아들이지 않는다. 큰 ID는 문자열로 유지한다.
- 기존 주간 근무표·연결 요약을 재사용하고 mock에서도 같은 근태 계산 함수를 공유한다. 기존 mock 휴가·정정 화면은 유지하되 live에서 제공하지 않는다.
- HTTP fixture·MSW 공유 원장·실제 서버/DB/Chrome을 분리해 검증했다. 실제 서버는 별도 사본과 샘플 비활성 상태, 일회용 DB만 사용한다.

## 5. 검증 결과

- 실제 Backend `aa2ebc8` / MySQL / Google Chrome: 새 출퇴근 6개와 기존 근무표 5개, 총 11개 통과.
- 실제 출퇴근 명령이 생성한 기록으로 상태 전이·예정 연결·네 조회의 분 일치·권한·정리 동작을 검증했다. 과거 498분 경계값은 별도 SQL fixture로 구분했다.
- `npm run check`: typecheck·ESLint, Vitest 69파일/562개, 메일 도구 자체 시험 9개, 빌드 가드 19개 통과. 실제 메일 발송 시험은 아니다.
- `npm run test:e2e:attendance:mock`: 새 출퇴근 2개와 기존 근무표·휴가·반응형·테마 6개, 총 8개 통과.
- `npm run test:builds`: live/mock 프로덕션 빌드·모드 격리 검사, Chrome 산출물 5개 통과.
- `graphify update .`: AST 지도 2,575노드/7,762간선 갱신. API/LLM 비용 없음. 기존 ignore 정책대로 로컬 출력만 갱신했다. SQL parser가 설치되지 않아 두 시험 SQL은 그래프의 심볼 추출 대상에서 빠졌고 TypeScript 소스 관계는 갱신됐다.
- 검증 서버 PID·jar 경로, 컨테이너 전체 ID를 확인해 해당 서버와 일회용 DB/볼륨을 제거했다. 별도 Backend 사본 경로가 삭제됐고 전용 컨테이너가 남지 않음을 확인했다. 원래 Frontend의 `.gitattributes` 변경은 그대로 보존했다.

환경·재현 명령·각 시험의 근거와 제약은 [출퇴근 실제 연동 검증](../testing/attendance-live.md)에 기록한다.
