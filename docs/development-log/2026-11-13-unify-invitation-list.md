# 2026-11-13 · 초대·승인 탭 직원 초대 패널과 공통 목록 레이아웃 적용

관련 작업: [#106 기록](2026-11-13-unify-list-layout.md)(공통 목록 레이아웃), PR #116(상품·입퇴실 이력·출퇴근), PR #117(직원 목록·권한 프리셋 탭)

## 1. 배경 / 문제

사용자 요청으로 직원 관리 > 초대·승인 탭을 다른 목록 화면과 같은 형태로 바꿨다. 이 요청에 대응하는 GitHub 이슈는 없다.

기존 탭은 한 화면에 다음이 세로로 쌓여 있었다.

- `초대·승인 관리` 제목과 안내 문단
- 항상 펼쳐진 `직원 초대` 폼 카드
- 라벨 달린 검색·상태 필터
- 초대마다 쌓은 카드 목록(`초대 상세: {name}` 버튼)과 `Pager`
- 목록 아래에 펼쳐지는 인라인 상세 카드, 맨 아래 저장 오류

요청 내용은 두 가지였다.

- 직원 초대: 다른 메뉴의 등록 버튼처럼 `직원 초대` 버튼을 두고, 누르면 초대 폼이 오른쪽에서 열린다.
- 초대 목록: 지금까지 적용한 공통 목록 레이아웃을 쓴다.

## 2. 검토한 선택지

- **상세 표시 위치**
  - 인라인 카드 유지: 목록 아래에 상세가 펼쳐져서, 목록이 길면 클릭한 행과 상세가 멀어진다. 다른 공통 목록과 동작도 다르다.
  - 오른쪽 패널: 회원·상품·직원 목록처럼 이름 셀 링크로 패널을 연다. 다른 초대를 고르려면 패널을 닫아야 한다.
  - 후자를 택했다.
- **초대 폼 상태 위치**
  - 상위 컴포넌트에 그대로 두기: 패널을 닫아도 입력이 남아 초안 확인 흐름이 어색하다. "버린다"고 확인해도 다시 열면 입력이 그대로 있다.
  - 패널 안 하위 컴포넌트로 분리: 상품 등록(`ProductCreate`)처럼 패널을 닫으면 폼이 사라진다. 패널의 기존 초안 확인(`PanelDrafts`)이 그대로 동작한다.
  - 후자를 택했다.

## 3. 결정 및 이유

- `직원 초대` 버튼은 필터 바 오른쪽 끝에 둔다. 회원 등록과 같은 primary 버튼에 `plus` 아이콘을 붙였다.
- 초대 폼은 `InvitationCreateForm` 하위 컴포넌트로 분리해 `직원 초대` 패널 안에 둔다.
  - 필드, 검증, 멱등 키, 예정 권한, 요청 본문은 바꾸지 않았다.
  - 성공하면 패널을 닫고 목록을 새로 고친다.
  - 입력 중에 닫으면 기존 확인 문구로 묻는다.
- 상세는 `초대 상세` 패널로 옮겼다. 처리 버튼과 조건(관리자 초대는 사장님만, 재발급·취소·승인·반려), 반려 사유 입력 초안 확인은 그대로다.
  - 목록 표에서 빠진 반려 사유와 이메일·지점·역할·수락 기한은 패널에 표시한다.
- 상세 선택과 상태 필터는 기존처럼 화면 상태(`useState`)로 둔다. 상품·직원 목록과 같은 판단이다.

## 4. 구현 내용

`src/features/invitations/Management.tsx`

- `초대·승인 관리` 제목은 탭 이름과 겹쳐서 뺐다.
- 데모 안내는 카드 위, 초대·발송 상태 안내는 필터 바 아래(회원 목록 검색 안내 위치)에 둔다.
- 필터 바에는 검색(`초대 이름·이메일 검색`), 상태(`초대 상태 필터`), `초기화`, 오른쪽 끝 `직원 초대`를 둔다.
  - `초기화`는 `invitationSearch`·`invitationPage`와 상태 필터만 지우고 `tab`은 남긴다.
- `초대 목록` 표의 열은 다음과 같다.
  - 초대 이름(셀 링크)
  - 이메일
  - 지점·역할
  - 초대 상태, 발송 상태
  - 수락 기한
- 로딩·오류·빈 상태는 표 안에 표시하고, 페이지 이동은 `ListFooter`로 바꿨다.
- 저장 오류(`SaveError`)는 해당 패널 안에 표시한다.

시험

- `Management.test.tsx`
  - 상세 열기는 표 범위 셀 링크로, 초대 폼 시험은 `직원 초대` 패널 안에서 하도록 바꿨다.
  - "다른 초대를 고른 뒤 늦게 도착한 응답 무시" 시험은 첫 초대 응답이 오기 전에 패널을 닫고 다음 초대를 여는 흐름으로 바꿨다. 늦은 응답이 화면을 덮지 않는지는 그대로 검증한다.
  - 추가한 시험은 다음과 같다.
    - 초대 성공 후 패널이 닫히고 목록을 다시 읽는다.
    - `직원 초대`가 필터 바 안에 있다.
    - 빈 상태·조회 오류가 표 안에 표시된다.
    - `초기화` 범위가 맞다.
    - 초안이 있을 때 닫기를 취소하면 입력이 유지되고, 확인하면 다시 열었을 때 비어 있다.
- `Organization.test.tsx`: 탭 전환 시험이 `직원 초대` 버튼을 확인한다.
- Playwright `invitations`와 live `invitations` spec은 `직원 초대`를 눌러 폼을 열고, 표 범위 셀 링크로 상세를 연다.
- `usability.spec.ts`의 "지점 전환 전 초안 보호" 시험은 원래 초대 폼에 입력한 채 지점 선택을 바꿨다.
  - 초대 폼이 모달 패널로 옮겨져 패널이 열린 동안에는 지점 선택을 조작할 수 없다.
  - 그래서 화면 안에 있는 분류 등록 폼(상품 관리 > 분류)으로 같은 동작을 확인하도록 바꿨다.

## 5. 검증 결과

- `Management.test.tsx`(9건)와 `Organization.test.tsx`가 통과했다.
- `npm run typecheck`, `npm run lint`, 전체 `npm test`(89파일 799건), `npm run build`(live 빌드와 산출물 검사)가 통과했다.
- Playwright MSW는 15190 포트 임시 설정(`--strictPort`, 재사용 안 함)으로 실행했다.
  - 첫 실행: `invitations`·`organization`·`usability`·`workflows` 22건 중 21건 통과. `usability.spec.ts:215`(지점 전환 초안 보호)가 실패했다(위 4절 이유).
  - 그 시험을 고치고 초대 폼을 분리한 뒤 `usability`·`invitations` 16건 통과.
  - 전체 MSW 스위트는 실행하지 않았다.
- 화면 확인은 MSW dev 서버(15193)에서 했다. 회원 목록과 초대·승인 탭(강남점·전체 범위)을 1440/1024/390px로 Playwright Chrome 스크린샷을 찍고 측정했다.
  - 페이지 가로 스크롤, 카드 밖 컨트롤, 패널 가로 넘침이 없었다.
  - 카드 위치가 회원 목록과 같았다.
  - 데모 데이터에는 초대가 없어서, 초대를 하나 만든 뒤 상세 패널을 1440/390px로 확인했다.
- 실제 백엔드·메일이 필요한 `tests/live/invitations.spec.ts`는 고쳤지만 실행하지 않았다.
- 재발급·취소·승인·반려를 사람이 직접 클릭해 확인하지는 않았다. 단위 시험과 MSW spec으로 확인했다.
- 이 저장소에는 `graphify-out/graph.json`이 없어 graphify 질의·갱신은 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 초대 상세·상태 필터를 URL로 옮기는 작업은 하지 않았다.
- 예정 권한 체크박스가 권한 코드(`members:write` 등)를 그대로 보여 준다. 화면 문구 정리는 이번 범위가 아니다.
- 이 브랜치는 `origin/main` 기준이다. #117과는 `Organization.test.tsx`에서 서로 다른 시험 블록을, `usability.spec.ts`에서 서로 다른 줄을 고친다.
