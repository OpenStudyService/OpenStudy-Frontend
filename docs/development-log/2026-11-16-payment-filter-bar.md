# 2026-11-16 · 결제 관리 필터 바 정리

## 배경 / 문제

결제 관리는 기간과 상태를 한 줄에 표시하고 고객 선택을 고급 필터 아래에 배치했다. 고급 필터는 매출 조회와 같은 조건을 지원하지만 다중 선택 목록을 별도로 구현하고 있었다.

## 결정 및 이유

매출 조회의 반응형 입력 그리드와 펼침형 고급 필터를 결제 관리에 적용했다. 두 화면은 고급 필터의 항목과 URL 값 구조를 이미 공유하므로 매출 조회의 선택 UI를 공용 컴포넌트로 옮겼다. 종료일 포함 여부는 기존 결제 조회 계약에 맞춰 입력 라벨에 표시한다.

## 구현 내용

- 시작일, 종료일, 결제 상태, 결제 지점에 라벨을 붙이고 입력 높이를 맞췄다. 고객 검색·선택과 초기화·Mock 결제 버튼은 기본 조건과 고급 필터 사이에 배치했다.
- 고급 필터는 접힌 상태에서도 적용된 조건 항목 수를 보여준다. 결제 수단, 상품 유형, 환불 처리 지점은 체크박스 드롭다운에서 여러 값을 선택할 수 있다.
- 결제 목록과 페이지 이동은 기존 목록 카드 안에서 제공한다. 필터의 URL 복원, 필터 변경 시 첫 페이지 이동, 초기화 범위는 기존 동작을 따른다.

## 검증 결과

- 결제·매출 관련 Vitest 4개 파일, 67개 테스트 통과. 고급 조건 복원, 복수 선택, 페이지 초기화, 조회 요청, 초기화 버튼을 확인했다.
- 전용 Mock 서버에서 결제 Playwright 3개 통과. 날짜·상태 조회, 결제·환불, 390px 결제 흐름을 확인했다. 기본 포트에서는 기존 서버가 응답해 전용 포트에서 다시 실행했다.
- Chrome Mock 화면의 1440·1024·390px에서 펼친 필터 영역의 가로 넘침이 없고 결제 수단 복수 선택, Escape로 닫기, 초기화가 동작함을 확인했다.
- 타입 검사, 린트, `git diff --check` 통과. `graphify update .` 완료.

## 남은 검증

- 전체 Vitest와 운영 API 연동 검증은 실행하지 않았다.
