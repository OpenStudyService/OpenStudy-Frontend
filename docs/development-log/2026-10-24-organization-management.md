# 2026-10-24 지점·직원·소속 권한 관리 화면

## 1. 배경 / 문제

- Frontend 이슈 #5(F02)는 검토가 끝난 기반 DB/API 계약으로 지점·직원 관리 화면을 전환하는 작업이다.
- 기존 범용 데모 폼은 운영시간이 문자열이며 직원 소속 전체를 한 번에 편집한다. 정본의 7요일 운영시간, 지점별 명령, 계정·소속 두 버전, OWNER/MANAGER 역할 경계를 표현할 수 없었다.
- 기존 live 미리보기 서버가 200으로 반환하는 DTO에도 구조화 운영시간·소속 버전이 없다. 타입 단언으로 이를 실제 편집 가능한 정본 응답처럼 취급하면 화면 오류 또는 잘못된 저장을 유발한다.

## 2. 검토한 선택지 / 결정 및 이유

- 전체 업무 데모 계약을 한 번에 교체하면 아직 API가 구현되지 않은 다른 화면까지 변경된다. 지점·직원·프리셋만 전용 폼·계약 검증 모듈로 전환하고 다른 업무 화면은 유지했다.
- 기존 store를 사용하는 정본용 MSW 핸들러를 일반 resource 핸들러보다 먼저 등록했다. 조직 화면과 기존 데모의 직원·지점 원장이 갈라지지 않으며, 새 저장 명령의 영향도 함께 확인할 수 있다.
- 서버의 누락된 값을 보충하지 않는다. 읽기 경계에서 정본의 필수 운영시간·소속 상태·버전을 검사하고 미지원 응답을 오류로 보여 준다. 예외는 명시적인 MSW 데모 fixture 변환뿐이다.
- 충돌 시 자동으로 최신 버전을 덮어 재시도하지 않는다. 입력을 유지하고 최신 내용을 사용자에게 보여 준 뒤 버전을 갱신한다. 재저장은 사용자의 명시적인 저장 버튼으로 수행한다.

## 3. 구현 내용

- `src/features/organization/`를 지점 폼, 직원·소속 폼, 프리셋 폼, 읽기 계약 검증, 공통 UI/쿼리 도구로 나눴다. DTO는 `foundation.generated.ts`의 타입을 참조한다.
- 지점 설정에 OWNER 전용 생성과 허용된 MANAGER의 정보·운영 상태 수정, 7요일 휴무·익일 운영시간 검증을 추가했다. 생성에는 멱등 키를 사용한다. 기본 정보 PATCH와 운영 상태 POST를 구분하고, 앞 명령만 성공한 경우도 사용자에게 알린다.
- 직원 이름·전역 상태 변경은 OWNER만 표시한다. 로그인 이메일은 읽기 전용이며 승인 대기 계정을 계정 수정으로 활성화하지 않는다.
- 소속 저장은 `/employees/{employeeId}/memberships/{branchId}` PUT에 해당 지점의 값과 `employeeVersion`, `version`만 보낸다. 다른 지점 소속 전체를 재전송하거나 누락 삭제하지 않는다.
- MANAGER는 `people:manage`를 가진 담당 지점의 다른 STAFF만 수정한다. 본인·OWNER·MANAGER 소속 편집, MANAGER 승격은 막는다. 회수 소속은 직접 활성화하지 않고 재초대 절차를 안내한다.
- STAFF 기본 프리셋은 빈 권한, MANAGER 기본은 9종 전체다. 프리셋 선택은 복사이며 개별 조정 후 저장한다. 사용자 정의 프리셋 관리는 OWNER만 가능하고 시스템 프리셋은 수정하지 않는다.
- 검색·페이지 조건은 URL에 저장한다. 사용자·지점·권한 변경 시 조직 폼의 로컬 상태를 새로 구성해 이전 범위의 입력이 남지 않게 한다.
- 공통 세션 모델에서 정본 membership의 상태·버전을 보존한다. 회수 소속을 지점 접근·관리 메뉴 판정에서 제외하고 MANAGER의 행위 권한도 명시 grant로 검사한다. `CurrentUser.sessionMode`를 legacy 호환 optional 필드로 추가했다. 제한 세션의 실제 화면 분기는 같은 배치의 인증 통합 변경에서 다룬다.

## 4. 검증 결과

- `npm run check`: TypeScript·ESLint 통과, 전체 81개 단위/컴포넌트/MSW 테스트 통과. 기존 61개, 조직 관리 16개, 같은 배치 인증 세션 모드 4개를 포함한다.
- 신규 조직 테스트는 OWNER/MANAGER/STAFF 화면, 관리자 명시 grant와 본인·MANAGER 보호, 이메일 읽기 전용, 한 직원의 두 지점 중 한 소속만 수정, 계정·소속 stale 버전 거부, 409 입력 유지·최신 버전 재확인, 7요일·휴무·익일 입력, 프리셋 복사·소급 변경 방지를 확인했다.
- `npm run build`: live 빌드 통과. 실제 서버 API를 호출한 통합 검증은 아니다.
- 상위 작업자의 Chrome 검증: `tests/organization.spec.ts` 2개 통과(지점 생성 시 7요일·익일 값/멱등 키, 직원 소속 PUT의 두 버전·이메일 읽기 전용). 기존 smoke 1개 통과.
- 위 직접 요청 거부·동시 버전 검증은 MSW fixture를 대상으로 수행했다. 실제 서버에서 거부되는지 확인한 결과로 해석하면 안 된다.

## 5. 남은 작업 / 보류 사항

- Backend B05/B06 지점·직원·프리셋 API 구현 후 실제 세션과 DB를 연결해 M1 전체 흐름을 확인해야 한다. F02 이슈의 실제 live 완료 조건은 아직 충족하지 않았다.
- 실제 DB 경합, 회수 후 서버 요청·SSE 즉시 차단, 지점 운영 중지 후 거래 제한은 해당 backend 및 통합 이슈의 검증 대상이다.
- 초대·수락·승인 및 상품 화면의 정본 전환은 이번 작업에 포함하지 않았다.
- 기존 MSW 인증 흐름의 `sessionMode`는 현재 계정 상태에서 계산한다. 실제 B04 서버처럼 로그인 시점의 제한 모드를 고정하는 재현까지 구현하지 않았다. 승인 후 재로그인이 필요한 실제 응답에 대한 화면 분기는 같은 배치의 별도 인증 테스트로 확인한다.
- 일회성 작업 스크립트나 중간 산출물은 추가하지 않았다.
