# M13 결제 고급 필터·일별 마감·집계·점유 추이

## 1. 배경 / 문제

[Frontend #42](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/42)는 FR-PAY-13, FR-PAY-14, FR-AGG-15, FR-SEAT-16의 화면 연동을 요구한다. 백엔드 `origin/main`의 [운영 확장 계약](https://github.com/OpenStudyService/OpenStudy-Backend/blob/main/docs/design/foundation/operations-extension-api.md)과 OpenAPI를 기준으로 작업했다.

## 2. 검토한 선택지

- 매출 화면의 지점 범위·권한·집계 메타정보와 좌석 화면의 지점 선택을 재사용할 수 있었다. 마감과 이용량을 매출 화면에서 열고, 점유 추이를 지점 좌석 화면에서 열면 기존 조회 흐름 안에서 관련 지표를 확인할 수 있다.
- 합계 정합성의 경우 결제 목록은 결제 생성 시각 및 결제 처리자를 사용하고, 집계는 승인·환불 시각 및 거래 항목별 처리자를 사용한다. 전체 합계 일치와 계약이 보장하는 승인액 비교를 구분했다.

## 3. 결정 및 이유

- 사용자가 승인액 비교 범위로 한정하기로 했다. 지점·필터 및 결제 생성/승인 시각 범위가 같고 환불 처리 지점이나 결제 상태 등으로 승인 원거래가 제외되지 않는 경우, 결제 목록의 승인·환불 상태 금액 합을 매출 승인액과 대조한다.
- 좌석 추이의 기간 생략 시 동작은 주 계약과 백엔드 구현에 맞춰 Asia/Seoul 기준 오늘 하루를 사용한다. OpenAPI의 `from` 설명에는 이번 달 1일로 적혀 있다. 화면은 기본 조회 시 기간을 생략하고 서버가 응답한 기간을 표시한다.
- 백엔드 `origin/main`의 OpenAPI를 임시 파일로 추출해 타입을 다시 생성했다. 새 worktree에는 `graphify-out`이 없어 graphify 쿼리와 갱신을 건너뛰었다.

## 4. 구현 내용

- 결제·매출의 고급 필터를 URL 쿼리에 저장한다. 결제 목록은 응답의 적용 조건과 페이지 전체에 걸친 상태별 합계를 표시한다. 매출 카드·표·차트는 각 API가 반환한 조건과 안내 문구를 표시한다.
- 이용 지점별 이용권 사용량은 입실 수, 시간권 차감 분, 정액권 차감액과 판매 지점별 내역을 별도로 표시한다.
- 일별 마감은 서버 세션 시간과 기존 권한 판정을 이용한다. 생성 요청에 멱등 키를 보내고, 목록·상세에서 마감 금액, 조정 합계, 현재 금액, 조정 사유와 처리자를 조회한다.
- 좌석 점유 추이에는 기존 선 차트와 표를 사용한다. 추이 패널을 열 때 차트를 로드한다. 분모가 0인 구간은 차트의 빈 구간과 표의 `해당 없음`으로 표시한다. 측정값 0은 `0.0%`로 표시한다.
- MSW 응답에 고급 필터, 집계 메타정보, 마감, 이용량과 점유 추이 계약을 반영했다.

## 5. 검증 결과

- `npm run typecheck`, `npm run lint` 통과.
- 결제·매출·좌석 및 MSW 관련 단위 테스트 137개 통과. 좌석 추이 지연 로드 적용 후 관련 테스트 28개를 다시 실행해 통과했다.
- 단위 테스트에서 URL 고급 필터 복원, 승인액 일치, 카드·표·차트의 적용 조건과 안내, 마감 조회 및 멱등 재생, 후속 환불 조정 내역, 이용 지점 사용량, 점유율 0과 해당 없음 구분을 확인했다.
- 전체 테스트 재실행 중 홈 빈 상태 테스트 한 건이 대기 시간 안에 완료율 문구를 찾지 못했다. 해당 파일을 단독 실행해 18개가 모두 통과했고, `npm test -- --maxWorkers=4` 재실행에서 전체 76개 파일의 662개 테스트가 통과했다.
- `npm run build`와 내장 `check:build:live` 통과. Vite의 500 kB 초과 청크 경고가 출력됐다.
