# 기반 API 계약과 클라이언트 상태 경계 정리

## 배경 / 문제

Foundation 개발 계획 F01(이슈 #4)에 따라 backend 정본 API를 사용할 준비가 필요했다. 기존 프론트는 전체 업무 데모 계약을 사용하고 있어 기반 API의 오류 추적 ID와 목록 메타데이터가 손실될 수 있었고, 계정·지점·권한 변경 후 이전 요청이나 스트림이 화면에 영향을 줄 수 있었다.

## 검토한 선택지

기존 전체 업무 계약을 한 번에 교체하거나, 기반 API 타입을 정본에서 별도로 생성하고 공통 호출·오류·상태 경계부터 전환하는 방법을 검토했다. 지점·직원·초대·상품 업무 API 구현이 후속 단계이므로 후자를 선택했다. OpenAPI 파일을 프론트에 복제하면 정본이 갈라지므로 인접 backend 저장소의 문서를 직접 입력으로 사용한다.

## 결정 및 이유

`foundation.generated.ts`와 `npm run api:foundation`을 추가하고 공통 오류 타입에 적용했다. 아직 전환하지 않은 화면은 기존 데모 DTO를 유지한다. 취소된 요청은 오류 본문을 읽은 뒤에도 중단 여부를 검사해 이전 지점의 401 응답이 새 세션을 만료시키지 못하도록 한다.

## 구현 내용

- 오류 `requestId`, 충돌 상세, `Retry-After`를 보존하고 안내·폼 오류에서 요청 ID를 확인할 수 있게 했다. 잘못된 JSON 오류 구조와 문자열이 아닌 요청 ID를 안전하게 처리한다.
- 기반 API의 `{items, meta}` 목록을 읽되 기존 데모의 평탄한 페이지 구조도 지원한다. 로그인 비밀번호는 비어 있지 않은 값과 UTF-8 72바이트 제한을 검사한다.
- 지점 이동 시 검색·페이지 URL 조건을 유지하고 이전 지점 쿼리를 취소·제거한다. 계정 변경 시 이전 계정의 모든 지점 캐시, 권한 변경 시 해당 계정 캐시·작성 중 상태를 정리한다.
- 로그아웃·세션 만료 시 SSE를 종료하고 재연결 타이머·종료된 소스의 대기 이벤트를 차단한다. SSE 효과의 수명에 맞춰 재연결 확인용 `/me` 요청도 취소한다.
- 정본 SSE의 `invalidate`, `resync`, `authorization.changed`를 처리한다. 재동기화는 현재 지점 데이터와 세션을 다시 조회하고, 권한 변경은 스트림과 개인 캐시를 정리한 후 세션을 재확인한다. 기존 데모 이벤트도 지원한다.
- 422·409 입력 보존, 빈 응답과 권한·통신 오류 구분, 늦은 응답 취소, 계정·지점 캐시 정리, SSE 종료·재연결·정본 이벤트를 검증했다. 브라우저 지점 전환 테스트의 오래된 빈 목록 문구를 현재 화면의 제목과 총 0건 확인으로 수정했다.

## 검증 결과

- `npm run check`: TypeScript, ESLint 및 Vitest 7개 파일 / 61개 테스트 통과.
- `npm run build`: live 배포 빌드 성공.
- `npm run api:foundation`: 재생성 전후 파일 해시가 같아 생성 결과 재현 확인.
- `git diff --check`: 통과.
- Chrome Playwright 3개 시나리오 통과(31.0초): 사장님 로그인·전체 화면 smoke, 채널 참여자·세션 만료, 지점 전환의 늦은 응답 차단·URL 조건 복원.
- 실제 backend 업무 API와의 권한·DB·메일 연동은 이번 클라이언트 및 모킹 브라우저 검증으로 확인하지 않았다.

## 남은 작업 / 보류 사항

F02 이후 지점·직원·초대·상품 화면을 정본 DTO와 실제 업무 API에 연결한다. 현재 `/me` 등 화면별 데모 DTO를 정본 응답 전체로 전환한 상태는 아니다. B11 구현 후 서버가 보내는 실제 SSE 및 세션 회수 동작을 통합 검증해야 한다.
