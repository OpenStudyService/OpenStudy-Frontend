# 2026-11-04 근무표 실제 API 연동 — Frontend #29 부분 구현

## 1. 배경 / 문제

기존 근무표는 데모 필드(`employeeId`, `breakMinutes`)와 일반 목록 API에 의존했고, 자정을 넘는 근무를 다음 날에도 중복 표시했다. 출퇴근은 아직 병합되지 않은 서버 API 대신 데모 경로를 호출했다.

착수 시 [Backend #82](https://github.com/OpenStudyService/OpenStudy-Backend/issues/82), [#83](https://github.com/OpenStudyService/OpenStudy-Backend/issues/83), [#84](https://github.com/OpenStudyService/OpenStudy-Backend/issues/84) 및 PR을 확인했다. #82는 PR #158로 계약 확정, #83은 [PR #159](https://github.com/OpenStudyService/OpenStudy-Backend/pull/159)로 main에 병합됐다. 별도 clone의 main `44ba201`에는 근무표 operation 6개가 있고 출퇴근 operation 7개는 설계 계약이다. #84는 열려 있고 관련 구현 PR은 확인되지 않았다. 기존 Backend에는 #84의 미커밋 작업이 있어 그대로 보존했다.

## 2. 검토한 선택지

- 데모 공통 폼에 변환만 추가하면 근무 DTO·수정 불가 필드·충돌 응답을 공통 CRUD 모델에 계속 섞게 된다.
- 기존 주간 표와 패널 구성은 재사용하면서 근무 전용 조회·편집기를 두면 실제 계약과 버전 처리를 명시할 수 있다.
- 미병합 출퇴근 구현을 가져오는 방법은 기존 Backend 작업을 침범하고 병합된 계약의 실제 동작 검증이 되지 않으므로 사용하지 않았다.

## 3. 결정 및 이유

근무 관리만 병합된 서버 계약으로 연결한다. live의 출퇴근은 연결 대기를 명시하고 데모 목록·명령·성공 메시지를 사용하지 않는다. M12 휴가·정정·대체근무도 live에서는 노출하지 않는다. 기존 mock 기능은 mock 빌드 안에서 유지한다. #29 전체 완료나 자동 종료로 연결하지 않는다.

Frontend main `91dfc48`에서 별도 `feature/workforce-api` 작업 트리를 만들었다. 원래 Frontend의 `.gitattributes`, Backend 작업 트리 및 환경 파일을 수정하거나 커밋에 포함하지 않는다.

## 4. 구현 내용

- 병합된 Backend OpenAPI에서 타입을 생성한다. 미커밋 계약 파일은 입력으로 사용하지 않는다.
- `/shifts/weekly`의 예정 근무와 실제 근태를 구분한다. 허용된 응답의 직원만 행으로 만들고, `workDate`로 시작일에만 표시한다. 브라우저 시간대와 무관하게 Asia/Seoul 입력을 UTC로 전송한다.
- 목록의 날짜·상태·페이지와 상세 조회를 연결한다. 등록은 관리 지점만 선택하고 같은 입력 재시도에 동일한 멱등 키를 쓴다. 수정은 시각·예정 휴게·사유·version만, 취소는 사유·version만 전송한다.
- 충돌 응답의 시간·표시 가능한 지점 또는 `다른 지점 근무`·승인 휴가를 입력을 유지하며 표시한다. 직원에게 관리 버튼을 보이지 않고 서버 권한도 그대로 따른다.
- 각 상세 편집기를 열 때 새 version을 읽는다. 실제 Chrome 회귀 중 캐시된 상세로 초기 version이 고정되는 문제를 찾아 수정했다. 버전 충돌 뒤 최신 버전 조회 중 저장을 막고, 입력은 유지한다.
- 운영 중지 지점은 등록·수정을 비활성화하고 기존 근무 취소는 허용한다.
- mock 공유 원장에 계약 DTO 어댑터와 MSW HTTP·Chrome 검증을 추가했다. 기존 mock 휴가 overlay는 유지하며 live에서 실행하지 않는다.

## 5. 검증 결과

- `npm run check`: typecheck·ESLint 통과, Vitest 67개 파일/553개 테스트, 실제 메일 도구 자체 테스트 9개, 빌드 가드 테스트 19개 통과. 메일 발송 시험은 아니다.
- `npm run test:builds`: live/mock 빌드와 모드 오염 검사 통과, Chrome 산출물 5개 통과.
- `npm run test:e2e:workforce:live`: 실제 Backend·일회용 DB·Google Chrome 5개 통과. 운영 중지 지점, 일요일 야간 등록·수정·취소·상태 필터, 비공개 충돌, 일반 직원 조회·버튼 제한, 동시 수정 후 버전 충돌/명시적 새로고침을 확인했다. live 출퇴근 데모 요청이 없음을 함께 확인했다.
- `npm run test:e2e:workforce:mock`: 새 근무 흐름·기존 휴가 복원·반응형·테마 6개 통과.
- 확대 실행에서 발견한 기존 채팅 세션 만료 테스트 실패는 별도 main `91dfc48`에서도 단독 재현했다. 이번 근무 변경의 통과 결과에 포함하거나 해결된 것처럼 보고하지 않는다.
- `graphify update .`: 작업 트리의 AST 그래프 2,501노드/7,576간선 갱신, LLM/API 비용 없음. 저장소가 기존부터 `graphify-out/`을 ignore하므로 로컬 출력만 갱신하고 강제로 추적하지 않는다.
- 검증 서버 PID·jar 절대 경로와 컨테이너 전체 ID를 확인해 종료·삭제했다. 일회용 DB/익명 볼륨, 별도 Backend clone, 비교용 main 작업 트리 제거를 확인했다. 기존 환경 파일과 다른 작업의 서버·컨테이너는 변경하지 않았다.

상세 환경·실패와 재현 범위·정리 방법은 [실제 연동 검증](../testing/workforce-live.md)에 기록한다. 최종 확인 시에도 Backend main 계약은 #84 미구현 상태다.
