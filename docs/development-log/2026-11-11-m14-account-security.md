# M14 계정 보안·프로필 사진 화면

## 1. 배경 / 문제

[Frontend #43](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/43)의 비밀번호 변경·재설정, 로그인 잠금 해제와 사진 관리를 설정·직원 관리 화면에 연결했다. 백엔드 `origin/main`의 [계정·협업 계약](https://github.com/OpenStudyService/OpenStudy-Backend/blob/main/docs/design/foundation/account-collab-api.md)과 [ADR-M14-001](https://github.com/OpenStudyService/OpenStudy-Backend/blob/main/docs/db/ADR-M14-001.md)을 기준으로 작업했다.

## 2. 검토한 선택지

- 초대 수락에서 사용한 fragment 제거 방식과 공통 CSRF·세션 만료 처리를 재설정 흐름에 재사용할 수 있었다. 기존 테마 카드와 브라우저 저장 방식도 화면 범위와 재방문 조건을 충족했다.
- 직원 상세의 지점 범위 응답만으로 버튼 권한을 판정하면, 선택한 지점에서는 소속이 회수됐지만 다른 담당 지점에는 활성 소속이 있는 직원의 작업을 숨기게 된다. 이 경우 권한 범위 내 전체 소속을 조회할 수 있다.

## 3. 결정 및 이유

- 비밀번호 변경 뒤 현재 세션과 같은 쿠키를 공유하는 탭은 계속 사용한다. 서버가 취소한 세션의 요청에서 `SESSION_EXPIRED`가 오면 기존 세션 정리 흐름에 재로그인 안내를 표시한다.
- 기존 세션이 있는 브라우저에서도 재설정 완료 시 로그인 폼을 표시한다. 재설정 요청 자체는 기존 세션을 유지한다.
- 대상의 활성 소속을 현재 지점에서 확인할 수 없고 다른 관리 지점이 있을 때만 전체 범위 상세를 조회한다. 초기화에만 활성 계정 상태와 본인 제외 조건을 적용한다. 잠금 해제의 대상 판정은 초기화와 같다고 요약된 계약 문구가 있지만, 실제 백엔드 구현은 잠금 해제에 활성 대상 조건을 적용하지 않는다.
- 닉네임과 사진 수정은 같은 계정 버전을 사용한다. 사진 변경 응답은 세션 캐시에 반영하고, 닉네임 폼의 기준 버전이 해당 작업 직전 버전인 경우에만 한 단계 전진시킨다.
- 백엔드 `origin/main`의 OpenAPI를 임시 파일로 추출해 타입을 생성했다. 새 worktree에 `graphify-out`이 없어 쿼리와 갱신을 건너뛰었다.

## 4. 구현 내용

- 설정에서 본인 비밀번호를 변경한다. 비밀번호는 공백을 유지한 채 Unicode 코드 포인트 수와 UTF-8 바이트 길이를 검사한다. 기존 비밀번호 불일치, 같은 비밀번호, 필드 검증 오류와 요청 제한을 표시한다.
- 공개 `/password-reset`에서 fragment 토큰을 읽고 주소에서 지운다. CSRF 토큰을 포함한 본문 요청으로 링크를 확인하고 새 비밀번호를 설정한다.
- 직원 상세에서 초기화의 영향을 확인한 뒤 요청한다. 발송 예약 상태와 잠금 해제 결과를 각각 표시한다.
- 사진을 업로드·삭제하고, 앱 경유 이미지 로드가 실패하면 이니셜을 표시한다. MSW는 발송 예약, 토큰 교체·소비, 파일 서명 검증, 사진 조회를 재현한다. 데모 비밀번호·토큰·사진 파일은 탭 메모리의 시연 데이터다.

## 5. 검증 결과

- `npm run typecheck`, `npm run lint`, `npm test` 통과. 전체 단위 테스트 688개에 MSW 계약 테스트를 포함했다.
- `npm run build`와 `check:build:live`, `npm run build:demo`와 `check:build:mock` 통과.
- 단위 테스트에서 만료·교체·재사용 링크 거부, 재설정 완료 후 로그인 화면, 비밀번호 오류와 세션 만료 안내, 사진의 사전 검증과 서버 오류, 권한별 버튼, 테마의 문서 적용 및 재방문 복원을 확인했다.

## 6. 남은 작업 / 보류 사항

- live 빌드의 실제 API 연결, 다중 기기의 세션 취소, 실제 메일 발송 및 브라우저 E2E는 마일스톤 검증으로 미룸(미실행).
- 배포 시 백엔드 `openstudy.password-reset.url`의 경로를 `/password-reset`으로 맞춘다.
