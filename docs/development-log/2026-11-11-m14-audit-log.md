# M14 감사 로그 검색·상세 화면

## 1. 배경 / 문제

[Frontend #45](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/45)는 FR-AUD-04에 따라 OWNER가 감사 로그를 검색하고 변경 전후 값을 확인할 화면을 요구한다. 기존 설정의 변경 이력 탭은 공통 리소스 목업을 조회하고 지점 관리자에게도 표시됐다. 백엔드 `origin/main`의 [계정·협업 계약](https://github.com/OpenStudyService/OpenStudy-Backend/blob/main/docs/design/foundation/account-collab-api.md)과 [감사 API 구현 PR #209](https://github.com/OpenStudyService/OpenStudy-Backend/pull/209)를 확인했다.

## 2. 검토한 선택지

- 기존 설정 탭, 표 스타일, 필터 필드, 상세 패널과 페이지 컴포넌트를 재사용할 수 있었다. 감사 검색은 공통 리소스와 검색 조건·응답 형식이 달라 전용 화면을 기존 탭 안에 연결했다.
- 대상 유형과 행위의 선택 목록은 서버 계약에 없다. 사용자에게 입력 방식을 확인했고, 계약 코드 직접 입력을 선택했다.
- 기존 감사 기록 생성 코드는 문자열 JSON을 저장한다. 읽을 때 새 응답 형식으로 변환하면 기존 업무 화면의 기록 생성을 유지할 수 있다.

## 3. 결정 및 이유

- 메뉴는 OWNER에게 표시한다. OWNER 외 사용자가 설정의 감사 탭 주소로 접근하면 권한 안내를 표시하고 감사 API 호출을 시작하지 않는다.
- 검색 조건은 URL에서 복원하고 API에는 허용된 검색 query만 전달한다. 서버가 채운 기간은 응답의 `period`로 표시한다. 같은 요청 보기는 다른 조건을 해제하고 적용 기간과 요청 ID를 전달한다. 직접 연결된 오래된 상세가 현재 기간 밖이면 해당 기록의 서울 날짜를 시작일로 사용한다.
- 작업자 null은 “시스템 / 알 수 없음”, 지점 null은 “지점 없음 / 알 수 없음”으로 표시한다. 이름이 비어 있는 참조는 ID와 함께 “알 수 없음”으로 표시한다.
- 중첩 객체와 배열을 경로별로 펼쳐 추가·삭제·변경·동일을 표시한다. 한쪽 스냅샷이 null이면 값이 있는 쪽을 표시한다. 서버가 가린 값은 받은 값으로 비교한다.
- 타입은 백엔드 `origin/main`의 OpenAPI를 임시 파일로 추출해 생성했다. 이 시점의 버전은 M15 계약이 추가된 `0.1.16-m15-analysis-reuse`다. 새 worktree에 `graphify-out`이 없어 graphify 조회와 갱신을 건너뛰었다.

## 4. 구현 내용

- 설정 안의 변경 이력 탭에서 `/audit-events` 검색과 `/audit-events/{id}` 상세를 조회한다. 공통 탭에 전용 콘텐츠를 연결하는 선택 속성을 추가했다.
- 기간·대상·행위·작업자·지점·결과·요청 ID·페이지 크기를 검색한다. 92일 제한과 대상 ID의 대상 유형 의존성을 미리 안내하고 서버 필드 오류도 표시한다.
- 응답 순서를 유지하고 목록에는 변경 내용 존재 여부를 표시한다. 페이지 이동은 응답의 page·pageSize·total을 사용한다. 기존 페이지 컴포넌트는 기본 크기 20을 유지하면서 선택적으로 다른 크기를 받는다.
- 상세 주소를 공유할 수 있고, 상세에서 같은 요청의 기록을 검색할 수 있다. 403과 404를 각각 안내한다.
- MSW에 검색·상세 응답, 기본 기간, 필터 검증, OWNER 권한, 조회 시 민감 값 가리기를 추가했다. 기존 데모의 직원·지점·대상 ID 별칭은 그대로 조회할 수 있다. 실제 API는 계약의 ID 검증을 적용한다.
