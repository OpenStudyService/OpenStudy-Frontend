# 2026-11-13 · 매출 조회 결과 탭 분리

## 1. 배경 / 문제

매출 조회의 요약, 판매 지표, 추세, 원장이 한 페이지에 이어져 필요한 보고서를 찾기까지 스크롤이 길었다. 조회 조건을 한곳에서 관리하면서 필요한 보고서만 열 수 있도록 했다. [이슈 #110](https://github.com/OpenStudyService/OpenStudy-Frontend/issues/110)

## 2. 검토한 선택지

- 결과를 이슈의 네 묶음으로 나누고, 일별 마감과 이용 지점별 이용권 사용량도 같은 탭 목록에 넣을지 검토했다.
- 보고서를 한꺼번에 조회하면 탭 전환 시 결과를 바로 표시할 수 있다. 선택한 탭의 보고서부터 조회하면 초기 및 필터 변경 시 요청 수를 줄일 수 있다.
- URL에 탭 선택을 기록할 때 다른 메뉴의 `tab`을 재사용하거나 매출 화면에서 `view`를 사용할 수 있다.

## 3. 결정 및 이유

- 요약에는 매출 요약, 용도별 매출, 지점별 순매출 비교를 두었다. 판매 분석에는 이용권 판매량과 상품 판매 순위, 추세에는 매출 추세와 이용권 판매량 추세, 원장에는 최소 원장을 두었다.
- 일별 마감은 자체 지점·날짜로 마감 기록을 조회하고 마감 작업도 수행한다. 이용 지점별 이용권 사용량은 공통 조건 일부를 사용하지만 이용 지점의 소비를 집계한다. 두 화면은 원결제 지점 기준의 매출 결과와 조회 맥락이 달라 제목 아래의 기존 토글로 유지했다.
- 상품·직원·리소스 메뉴에서 쓰는 `tab`과 구분해 매출 화면의 결과 선택은 `view`에 기록한다. 요약은 기본값이며 알 수 없는 값도 요약으로 표시한다.
- 선택한 탭의 쿼리만 활성화한다. CSV는 각 보고서의 조건과 응답 행 수를 사용하고 차트 내보내기는 같은 탭에 있는 차트와 집계 정보를 사용한다. 시작일과 종료일이 모두 비어 있으면 공통 조건 카드에 서버가 적용한 기간을 표시하기 위해 요약 쿼리도 활성화한다.

## 4. 구현 내용

- 공통 조회 조건 아래에 #107과 같은 Radix Tabs 및 `tabs`, `tab`, `active` 스타일을 적용했다.
- 탭 전환에서 `view`만 변경해 공통 필터, 고급 필터, 원장·상품 페이지, 정렬, 추세 단위를 보존한다. 조회 조건을 수정하면 기존 규칙에 따라 관련 페이지를 초기화한다.
- 탭별 기존 로딩과 오류 처리를 유지했다. 매출 조회에서 403을 받으면 결과를 숨긴다. 이용권 지표가 적용되지 않는 용도는 판매 분석과 추세에서 해당 없음으로 안내한다.
- #106과 공유하는 `AdvancedFilters`를 기존 인터페이스로 사용한다.

## 5. 검증 결과

- `npx vitest related src/features/analysis/Sales.tsx --run`으로 3개 파일, 42개 시험 통과. 탭 전환, 알 수 없는 URL 값, 조건과 페이지 유지, 활성 탭 요청 범위, 로딩·오류·403·해당 없음, CSV 계약을 확인했다.
- `npm run typecheck`, `npm run lint`, `npm test -- --maxWorkers=4`(87개 파일, 769개 시험), `npm run build`, `npm run build:demo` 통과.
- Chrome Playwright MSW 데모를 별도 포트 16410에서 실행했다. 1440·1024·390px에서 네 탭의 표가 표시되고 페이지에 가로 넘침이 없는 것을 확인했다. 키보드와 클릭으로 탭을 전환하고 날짜·환불 기준·용도 유지, 새로고침 후 원장 선택 복원, 빈 원장 상태를 확인했다. 세 화면 폭의 원장에서 심각도 serious·critical인 axe 위반은 없었다.
- `graphify update .`로 코드 그래프를 갱신했다.

## 6. 남은 작업 / 보류 사항

- 실제 API용 Playwright 시험은 탭 전환을 반영해 갱신했다. 브라우저 검증은 Chrome MSW 데모에서 수행했으며 실제 API와 다른 브라우저는 미검증이다.
