# 버튼 역할별 색상 적용

## 1. 배경 / 문제

지점 저장 버튼처럼 주요 실행에 기본 스타일이 남아 있었고, 반려·삭제·실제 취소와 정상 실행이 같은 색으로 표시되는 메뉴가 있었다. [조사·수정 계획](../design/button-style-plan.md)에 대한 사용자 승인을 받아 구현했다. main의 e85c791에 지점 사이드바 PR #150이 반영된 것을 확인하고 `fix/button-action-colors` 브랜치를 만들었다.

## 2. 검토한 선택지

모든 submit 버튼이나 ‘취소’라는 문구를 일괄 분류하면 조회 버튼, 편집창 닫기와 실제 업무 취소가 혼동된다. 기본 Button은 중립으로 유지하고 실제 제출·액션·상태 전환별로 primary·danger·quiet를 명시하는 방식을 적용했다.

## 3. 결정 및 이유

- 등록·저장·신청·승인은 테마의 primary로 강조한다.
- 삭제·반려·서버 취소·환불·접근 제한·운영 중단은 danger로 구분한다.
- 중단과 재개를 공용 버튼으로 처리하면 현재 요청할 동작에 따라 색상을 고른다.
- 이미 제한된 상태의 이름만 수정하는 경우에는 danger를 적용하지 않는다.
- 퇴실·반납·업무 완료 등 정상 흐름은 primary를 유지한다. 폼 닫기·조회·재시도는 보조 스타일을 유지한다.
- 위험 버튼의 글자·테두리·옅은 배경·호버·포커스 색상을 공통 토큰으로 정의해 테마의 초록·파랑·갈색 강조와 섞이지 않게 했다.

## 4. 구현 내용과 조사 항목별 결과

### 공통 구현

- `ButtonVariant`를 기본값·primary·quiet·danger로 제한했다. Panel의 닫기 버튼 전달 타입도 맞췄다.
- 공통 ResourceForm에 제출 버튼의 variant를 전달하고 ResourcePage에서 명령 메타데이터의 danger를 연결했다. 기존 일반 저장의 기본값은 primary다.
- 공통 catalog의 퇴실·반납은 정상 실행으로 정리했다. 해당 전문 화면의 진입·확정 흐름은 이미 별도 구현이며 기존 동작을 활성화하거나 대체하지 않았다.

### 주요 실행 누락

계획서의 14개 구현 위치를 모두 적용했다: 직원 계정·소속 저장, 프리셋 등록·저장, 휴무일 등록·안내 저장, 상품 분류 등록·이름 저장, 판매 지점 저장, 휴가 신청·부여, 정정·대체근무의 공통 신청, 시설 유형 등록, 매출 마감 실행. 체크 항목의 현재 편집 저장과 최종 승인도 primary를 적용했다.

## 5. 검증 결과

- 관련 Vitest 6개 파일·98개 테스트 통과.
- PR 전 전체 Vitest 96개 파일·889개 테스트 통과.
- `npm run typecheck`, `npm run lint` 통과. 최초 타입 검사에서 새 Testing Library 시험에 Playwright 전용 exact 옵션을 사용한 오류를 찾아 제거하고 다시 통과했다.
- `npm run build`와 live 산출물 검사 통과. 기존 500kB 초과 청크 안내가 발생했으며 빌드는 성공했다.
- `npx playwright test --config playwright.usability.config.ts tests/button-styles.spec.ts`: Chrome MSW 6개 시나리오 최종 통과. 회귀 시험을 기존 usability 실행 목록에 포함했다.
- 포레스트·네이비·샌드 각각 1440·1024·390px에서 실제 주요·위험 버튼의 색상, 글자 대비 4.5:1 이상, 화면 내 배치, 위험 호버·키보드 포커스를 확인했다. 데스크톱·모바일 캡처를 눈으로 확인했다.
- OWNER·지점 관리자·직원으로 지점 등록·수정 노출, 중단 선택 시 danger 및 원래 상태로 복원 시 primary, 편집창 닫기를 확인했다.
- 첫 브라우저 실행은 다른 검증과 동시에 실행하다 로그인 로딩 제한 시간을 넘겨 중단했다. 단독 재실행에서 세 테마·직원 권한 시험은 통과했고, OWNER·관리자 시험은 exact label 검색이 select를 찾지 못했다. 접근성 역할 combobox로 검색하도록 시험을 고친 후 최종 6개 모두 통과했다. 이 과정에서 앱 동작을 바꾸지는 않았다.
- 버튼 prop·색상·제출 variant 전달 외에 기존 이벤트 처리, 본문·키·권한·확인 절차를 바꾸지 않았음을 diff로 확인했다.
- `graphify update .`로 최종 브라우저 시험 수정까지 포함해 코드 그래프 갱신을 완료했다. SQL 파서 부재 안내는 기존 도구 제약이며 SQL 수정은 없다.

## 6. 남은 작업 / 보류 사항

- 실제 Backend·운영 환경과 실제 메일 발송·환불 실행은 검증하지 않았다.
- 브라우저 자동 검증은 대표 버튼의 테마·상태와 세 역할을 대상으로 한다. 표의 모든 업무 명령을 모든 역할·상태에서 Chrome으로 실행했다는 의미는 아니다. 나머지는 코드 대조와 관련 단위·통합 시험으로 확인했다.
- 다른 조사에서 발견한 회원 상세의 조회 기간 입력 잘림은 이 버튼 색상 변경에 포함하지 않는다.
- 검증 결과를 포함해 작업 브랜치를 push하고 PR을 준비한다. 원격 main 변경과 병합은 사용자가 수행한다.
