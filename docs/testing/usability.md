# 반응형·입력 보호·접근성 회귀 (#35)

## 실행

```sh
npm ci
npm run check
npm run test:e2e:usability
npm run test:builds
```

로컬에서는 설치된 Google Chrome을 사용한다. CI에서는 Playwright Chromium을 사용하며, workflow의 브라우저 설치 단계가 선행한다. 전용 Vite mock 서버는 `127.0.0.1:15180`에서 시작하고 종료한다. `--strictPort`와 `reuseExistingServer: false`로 다른 작업의 서버를 재사용하지 않는다. Backend·DB·환경 파일은 필요하지 않다. `tests/live/`와 `tests/builds/`는 이 mock 회귀에서 제외한다. trace는 끄고 스크린샷은 실패 시에만 남긴다. 기존 반응형 시험의 로컬 스크린샷도 Git ignore 대상이다.

## 확인 범위

- `usability.spec.ts`: 홈·업무·회원·상품·결제·공간·예약·시설·문의·공지·근무·직원·채팅·매출·AI·설정 16개 경로를 1024/1280/1440 × 900에서 검사한다. 본문의 가로 넘침과 오류 화면 여부를 확인하고 WCAG 2 A/AA·2.1 AA 태그의 axe serious/critical 위반이 없어야 한다. 낮은 심각도의 결과까지 없다는 뜻은 아니다.
- 업무·회원·상품·결제·근무 등록 및 직원 상세 6종을 1024/1440 × 900에서 열어 폼 접근성과 가로 넘침을 확인한다.
- 업무 폼의 Enter 열기·초기 제목 포커스·Tab/Shift+Tab 경계 순환·Escape 닫기·트리거 복귀를 확인한다. 포레스트·네이비·샌드에서 포커스 outline 또는 ring과 axe 결과를 확인한다.
- 상품 입력의 닫기·뒤로가기·새로고침 취소, 명시적 폐기 시 한 번의 경고, 저장 성공 후 경고 해제와 새 입력의 재보호, 초대 입력 중 지점 전환 취소를 확인한다.
- 기존 `responsive.spec.ts`는 390/1024/1440 폭과 세 테마·폼 입력·포커스 복귀를 확인한다. 회원·상품·결제·직원·업무·근무의 기존 mock 업무 회귀도 함께 실행한다.
- 단위 시험은 여러 폼의 경고 통합·개별 저장·실패 후 보호·저장 확정 콜백·세션 종료 경로·unmount 정리 및 다른 상품 영역 저장 시 초안 보존을 확인한다.

## 결과 해석과 후속

이 명령은 **프론트엔드 MSW 회귀**다. 실제 Backend API의 저장이나 운영 데이터 정합성을 검증한 결과로 사용하지 않는다. 별도 `test:builds`는 live/mock 산출물 검사와 API 오류가 성공으로 위장되지 않는 브라우저 회귀다.

현재 매출·AI·설정 일부는 데모 또는 live 연결 대기 화면이다. 그 화면의 현재 레이아웃 검사 통과로 향후 실제 결과·설정 폼까지 검증했다고 주장하지 않는다. #30~#33 등 실제 화면 연결 후 데이터가 많은 표·차트·오류·권한별 상태를 다시 검사해야 한다. 이 때문에 #35의 전체 최종 인수는 열린 상태로 유지한다. 자동 검사 외의 실제 스크린리더·실기기·400% 확대 검증은 별도 후속이다.

로그아웃 버튼에는 초안 확인을 적용하되, 강제 재로그인·승인 대기 전환은 차단하지 않는다. 권한·사용자 변경으로 비공개 입력을 정리하는 기존 동작을 유지한다. 브라우저 새로고침 경고는 브라우저가 제공하는 기본 문구와 사용자 상호작용 조건을 따른다. 초안은 컴포넌트 메모리에만 있고 저장소나 분석 로그에 기록하지 않는다.
