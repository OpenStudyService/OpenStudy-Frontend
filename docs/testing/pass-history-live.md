# 입퇴실·이용권 조정·고객 내역 실제 서버 검증

Frontend #22 검증은 MSW와 실제 Backend·MySQL 검사를 분리한다.

## 준비 및 실행

- Node 24, Chrome, Java 21, MySQL 8.4를 사용한다.
- 검증한 Backend는 main에 병합된 `adcf15c`(M5 구현과 종료 잔량 노출 정리 포함)다. 이 커밋을 별도 폴더에 추출해 `bootJar`로 빌드한다. 기존 Backend 작업 트리와 `.env`, 개발 DB는 사용하지 않는다.
- 일회용 MySQL `history_live`를 loopback 13323, Backend를 18093에서 실행한다. 메일 발송은 비활성화한다.
- 공식 `ownerBootstrap`으로 `owner@history.test`를 생성한다. 별도 지점 1·2와 각 지점의 7요일 운영시간을 준비한다.
- 지점 1 STAFF `staff@history.test`는 추가 권한이 없다. 지점 2 STAFF `cashier@history.test`는 지점 2의 `payments:write`만 가진다. 세 계정은 검증 전용 무작위 비밀번호를 사용한다.
- 고객·상품·결제·이용권·좌석은 테스트가 실제 API로 생성한다. 직원 fixture는 일회용 DB에만 적용한다.

검증 비밀번호를 프로세스 환경 변수 `HISTORY_LIVE_PASSWORD`에 설정하고 실행한다.

```powershell
npm run test:e2e:history:live
```

설정은 live Vite 15183을 Backend 18093으로 연결한다. Service Worker를 차단하고 trace를 저장하지 않는다. 결과와 화면 캡처는 git에서 제외된 `qa-artifacts/history-live/`에 저장한다.

## 확인하는 동작

1. 시간권 조정 후 새로고침 지속성, 실제 입실·퇴실 후 고객 내역과 원장 잔량 일치, 기간 필터와 전체 원장 합계의 분리.
2. 구매·이용 지점 구분, 타 지점 이용 사건의 처리자·사유·이용 분·이용 기록 ID 비노출, 입퇴실 필터의 포함 시작·미포함 종료 경계.
3. 조회 직원의 조정 버튼 숨김과 직접 호출 403, 이용 지점에만 결제 권한이 있는 직원의 구매 지점 조정 404.
4. 두 브라우저 세션의 실제 409, 입력 보존·최신값 명시적 확인 후 변경 필드만 저장.
5. 실제 서버가 커밋한 뒤 브라우저 응답만 끊고 같은 본문·키로 재시도하여 조정 사건이 하나만 남음.
6. 정액권·기간권 전용 필드, 환불 뒤 조정 버튼 차단, 모바일 조정 화면.

## 정리 및 한계

실행 후 PID의 명령줄·jar 경로와 포트를 대조해 검증 서버만 종료한다. 저장한 컨테이너 ID와 이름을 대조해 해당 일회용 DB만 제거한다. 임시 자격 증명 파일을 삭제한다.

운영 배포, 부하, 실제 모바일 기기는 별도다. Backend 단위·통합 테스트를 다시 실행한 것으로 간주하지 않는다. MSW의 새 조정 사유·처리자는 메모리에서만 유지하며 전체 새로고침 시 잔량 스냅샷을 초기 데모 원장으로 표시한다. 실제 서버의 이력 지속성과 구분한다.
