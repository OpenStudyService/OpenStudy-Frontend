# 시설·문의·공지 실제 Backend 검증

Frontend #28의 정본 API 저장을 MSW 및 HTTP fixture와 구분해 검증한다.

## 격리 환경

- Node 24, Chrome, Java 21, MySQL 8.4를 사용한다.
- Backend main `9f06eea95f2a5019f3f4e9748bcaf21ddbf6b9f9`를 별도 디렉터리에 `git archive`로 추출하여 `bootJar`로 빌드했다. 원래 Backend의 변경 파일·환경 파일은 복사하지 않았다.
- 일회용 MySQL DB `collaboration_live`만 사용한다. loopback DB 포트는 13325, Backend 포트는 18095다. 기존 개발 DB를 사용하지 않는다.
- 서버는 local 프로필, 메일 비활성화로 실행하고 공식 `ownerBootstrap`으로 `owner@collaboration.test`를 만든다. 테스트용 무작위 비밀번호를 사용한다.
- 검증 DB의 지점 1·2를 사용한다. 직원 2(`staff@collaboration.test`)는 지점 1의 일반 직원, 직원 3(`cashier@collaboration.test`)은 지점 2의 일반 직원이다. 검증 전용 계정은 동일한 테스트 비밀번호를 공유한다. 테스트 중 지점 1 직원에게 부여한 `facilities:write`는 시험 종료 시 회수한다.
- local 프로필의 일부 공통 선택 데이터에 샘플 표시가 있다. 이번 시설·문의·공지의 생성·변경·이력은 실제 API와 일회용 MySQL 저장으로 검증했다.

## 실행

프로세스 환경 변수 `COLLABORATION_LIVE_PASSWORD`에 검증 비밀번호를 지정한 뒤 실행한다.

```powershell
npm run test:e2e:collaboration:live
```

전용 live Vite 15186에서 Backend 18095로 프록시한다. Service Worker를 차단하고 trace를 저장하지 않는다. 결과와 캡처는 git에서 제외된 `qa-artifacts/collaboration-live/`에 둔다.

## 실제 서버 시나리오

1. 직원에게 시설 쓰기 권한을 부여하고 초안을 연 뒤 회수한다. 서버 권한 변경 신호 또는 다음 명령의 403이 반영되면 초안을 폐기하고 직접 등록 주소도 차단한다. 등록 버튼 숨김과 회수 후 POST 거부를 확인한다.
2. 일반 직원이 타 지점 고객의 ID를 직접 지정한 문의는 404다. 회원번호 정확 일치 API로 먼저 조회하고 선택하면 같은 직원·지점의 문의 등록이 성공한다.
3. UI에서 시설 유형과 시설을 등록한다. 별도 로그인 세션이 설명을 수정한 후 첫 세션은 409에서 초안을 유지하고 최신값을 비교한다. 이름만 재저장하여 다른 세션의 설명을 보존한다. 완료 후 새 열린 작업·동일 담당자·다음 점검일 및 새로고침 유지 여부를 확인한다.
4. 허용된 고객 검색으로 문의를 대리 등록한다. 담당자가 없는 문의의 일반 직원에게 담당자 변경 버튼이 없는지 확인한다. OWNER가 UI로 담당자를 배정하면 해당 직원에게 변경 버튼이 나타난다. 직원 답변 후 이력·목록·미처리 집계와 새로고침 유지 여부를 확인한다.
5. 지점 대상 고정 공지를 임시 저장하고 게시·수정·게시 종료한다. 일반 직원에게 임시 저장·게시 종료 공지가 없고 다른 지점 직원에게도 노출되지 않는지 확인한다.
6. 점검일을 미래로 보내 실제 422 필드 오류와 입력 보존을 확인한다. 정상 완료가 서버에 커밋된 뒤 응답만 유실시키고 동일 본문·동일 멱등 키로 재시도한다. 버전은 한 번만 증가해야 한다.

응답 유실은 Playwright가 실제 서버 응답을 받은 후 브라우저 전달만 끊어 만든다. HTTP fixture로 가짜 성공 응답을 만드는 시험이 아니다. 일반 직원 목록에서 게시 종료·임시 저장을 제외한 뒤 고정 공지가 일반 공지보다 먼저 나오는지도 실제 Chrome과 MSW에서 각각 확인한다.

## Mock·공통 UI 회귀

```powershell
npm run test:e2e:collaboration:mock
npm run check
npm run test:builds
```

Mock 회귀는 별도 origin 15187을 사용하여 다른 개발 서버·브라우저 세션의 Service Worker와 분리한다. 새 세 화면, 기존 업무 폼·충돌·Escape, 1440/1024/390px, 세 테마 및 전체 화면을 검사한다. MSW 결과는 실제 DB 검증 결과와 구분한다.

## 정리와 한계

검증 종료 시 PID 명령줄의 이번 jar 경로와 컨테이너 ID·이름을 대조하여 해당 서버·컨테이너만 정리하고 임시 자격 증명 파일을 삭제한다.

운영 배포·실제 모바일 기기·부하·다중 인스턴스는 확인하지 않는다. Backend 자체 통합 테스트는 재실행하지 않는다. 채팅 독립 읽음(Backend #155)은 이번 범위가 아니다.
