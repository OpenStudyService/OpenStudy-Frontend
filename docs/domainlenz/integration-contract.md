# DomainLenz 연동 요청과 화면 계약

## 구현을 요청하는 사용자 경험

사용자가 참여 중인 채널에서 `@DomainLenz`로 질문하면 조회 결과를 우선 개인에게 표시한다. 조건과 수치를 확인한 후 사용자가 선택해 채널에 공유한다. 화면은 설명·조회 조건·KPI·차트·표·상세를 조합하며, 채널 일반 메시지와 함께 볼 수 있어야 한다.

실제 연결에서 명세 생성은 DomainLenz가, 현재 권한 검증·조회 실행·공유 승인과 결과 데이터는 OpenStudy 서버가 책임지는 기존 M10 경계를 따른다. 엔진이 제시한 수치를 그대로 업무 결과로 사용하지 않는다.

## 데모의 내부 인터페이스

| 타입 | 책임 |
|---|---|
| `DemoScenario` | 고정 질문, 업무군, 물리 근거, 지표·grain·기간·조건, 결과 컬럼과 행, UI 종류, 기대 상태 |
| `DemoResult` | 조회 시점의 시나리오·행·지점·채널 및 협의용 QuerySpec·ViewSpec 스냅샷 |
| `DemoViewer` | 시연 사용자와 지점별 AI·매출·결제 조회 권한 |
| `SharedResult` | 공유자와 변경되지 않는 결과 스냅샷 |
| `DemoTrace` | 현재 사용자·채널의 로컬 요청·종료 상태·적용 범위와 결과 명세. 서버 로그가 아님 |

`demo-v1-proposal`은 **설명을 위한 내부 형식**이다. 실제 엔진의 확정 wire schema·버전으로 사용하지 않는다. 물리 컬럼, 조회 의미, UI 바인딩을 검토하기 위한 자료이며 별도의 변환 계층을 거쳐야 한다. 별도 AI 분석 화면의 기존 매출 전용 `Execution` 계약을 전체 업무군 형태로 무리하게 확장하지 않았다. 채팅 메시지 DTO·API·DB 스키마도 변경하지 않는다.

QuerySpec 예시는 `sourceRefs`, 지표 정의, grain, 필터, 실제 시간 필드와 범위, 적용 지점·채널을 포함한다. 지점·사용자·채널 범위는 운영에서는 서버가 확정해야 한다. 매출은 승인·환불을 각각 원장에서 집계한 뒤 결합해야 하므로 두 기간 조건을 같은 조인의 AND로 실행하지 않는다.

ViewSpec 예시는 데이터셋과 필드 바인딩, KPI·차트·표 조합 및 허용 동작을 설명한다. 임의 HTML·JS·URL·API 경로를 실행하지 않는다. 데모의 미등록 차트 시나리오는 같은 수치를 표로 대체한다. 권한 오류를 표 대체로 우회하지 않는다.

v8 개정에서는 히트맵의 요일·시간대·건수, 좌석 배치의 이용 중·가능·사용 불가·전체, 주간 일정의 날짜·시간 필드 바인딩을 추가했다. 상세한 화면 변경은 [v8 개정 안내](./v8-layout.md)에 있다.

## 결과와 동작

- 준비된 질문 선택 → 입력창 확인 → 전송 → 4단계 진행 표시 → 개인 결과. 진행 시간은 연출이며 성능 측정값이 아니다.
- KPI 합계·차트·표는 같은 결과 행을 사용한다. 시간권 분·정액권 원·기간권 일 등 서로 다른 단위를 합산하지 않는다.
- 정렬·페이지 이동·상세보기는 해당 결과 안에서 동작한다. 상세에는 이미 허용된 결과 필드만 보여 준다.
- 매출의 후속 질문은 직전 결과의 기간·지표를 유지하고 지점만 좁힌다. 채널 지점 범위를 확대하지 않는다.
- 데모의 공유 카드는 정렬·필터 편집 불가인 결과 스냅샷이다. 이후 개인 결과 변경으로 갱신되지 않는다.
- 질문 취소·교체·채널 이동·사용자 변경·접근 회수 시 미완료 응답을 반영하지 않는다.
- 조건 확인·지원 불가·빈 결과·권한 부족·지점 초과·조회 실패·취소·표 대체를 서로 구분한다.

## 기존 정책과의 정합성

- KST 기준 기간, 시작 포함·끝 제외. 일정 겹침과 휴가 DATE 종료일은 별도 조건으로 표현한다.
- 매출 기본값은 환불 처리일, 귀속은 원결제 지점, 이용권·룸·사물함 결제 모두 포함. 승인 이후 환불된 원거래를 승인액에서 지우지 않는다.
- 전체 지점 매출은 대상 모든 지점의 `ai:read`와 `sales:read` 필요. 환불 거래 목록에는 `payments:read`도 필요하다. 지점 하나라도 부족하면 조용히 제외해 합계를 만들지 않는다.
- 미확정 업무군의 AI 권한은 임의로 신설하지 않고 OWNER 시연만 허용한다. 전사 휴가의 지점 귀속은 아직 정하지 않았으므로 전체 지점 OWNER에서만 확인한다.
- 보기 편한 데모 페이지 크기는 5행. 실제 M10의 50행 페이지·최대 1,000행·차트 상위 20개는 서버 연동에서 적용한다.

## 실제 연동 전에 합의할 사항

1. DomainLenz starter 공개 인터페이스, 지원 QuerySpec·ViewSpec 버전, 승인할 의미 카탈로그 등록 형식.
2. 질문·진행 이벤트·확인 선택·취소·결과 페이지·상세의 OpenStudy 계약과 엔진 응답 변환 계층.
3. 매출 외 도메인별 AI 조회 권한, 전사 회원·휴가의 지점 귀속, 지원할 필드·지표·관계.
4. 채널 공유의 보관 기간, 공유 스냅샷/원본 참조 방식, 참여자별 열람·권한 회수·원본 접근 상실 동작. 이 데모는 현재 권한으로 열람 가능 여부를 다시 확인하는 방향을 보여 준다.
5. 실제 DB·정형 API 수치 동등성 평가, 실모델 질문 변형 테스트, 지연·비용·예산 측정.

기존 정의의 상세는 Backend ADR-M9/M10/M15와 #92~#97을 따른다. 이 데모는 서버 권한·DB 실행·실모델 정확성·운영 공유 보안을 검증한 결과가 아니다.
