# 명시적 화면 갱신 정책

- 결정일: 2026-11-06
- 상태: **사용자 확정**
- 정본: [Backend ADR-COM-001](https://github.com/OpenStudyService/OpenStudy-Backend/blob/main/docs/db/ADR-COM-001.md), SRS v1.15 POL-52·POL-53

## 화면 동작

| 상황 | 동작 |
| --- | --- |
| 메뉴 진입·같은 메뉴 재클릭 | 현재 계정·지점·권한으로 서버 재조회 |
| 브라우저 새로고침 | 현재 주소를 다시 열어 URL에 저장된 조건으로 조회 |
| 승인 대기 화면 진입·브라우저 새로고침 | 최신 승인 상태를 조회 |
| 검색·필터·정렬·페이지·지점 변경 | 사용자가 요청한 조건으로 조회. 이전 문맥의 늦은 응답은 버림 |
| 화면을 읽거나 편집 중 | 마지막 조회 상태 유지. SSE·polling으로 화면을 바꾸지 않음 |
| 창 포커스 복귀·네트워크 복구 | 이 동작만으로 서버 재조회하지 않음 |
| 본인 등록·수정·처리 성공 | 응답과 해당 목록·상세·필요한 요약 반영. 관련 없는 전역 조회는 하지 않음 |
| 미저장 입력이 있는 이동·갱신 | 기존 이탈 보호 적용. 실패·409의 입력 유지 |
| 다른 세션의 계정·권한 변경 | 다음 API부터 서버가 재검증. 요청 없는 열린 화면의 즉시 삭제는 보장하지 않음 |
| 401·감지된 접근 범위 변경·로그아웃·계정/지점 전환 | 해당 비공개 캐시·초안·진행 요청 정리, 늦은 응답 차단 |

## 구현

공통 SSE 연결, 창 포커스·재연결 재조회, 근태·승인 대기·팀 채팅의 상태 주기 조회를 제거했다. 업무 화면은 현재 메뉴 재클릭과 브라우저 새로고침으로 다시 조회할 수 있다. 공간 관리·스터디룸 예약·시설 관리·고객 문의·공지사항·매출 조회·근무 관리·직원 초대·변경 이력의 메뉴별 새로고침 버튼을 제거했다. 조회에 실패해 이전 결과를 표시할 때는 안내를 표시한다. 오류 복구와 좌석 이동·AI 결과처럼 특정 작업에 필요한 다시 조회는 유지한다.

메뉴 재클릭은 같은 URL로 navigate하는 것만으로 재조회된다고 가정하지 않는다. 캐시 staleTime과 데이터 갱신 시점을 구분한다. 정기 `/me` 조회도 넣지 않는다. 로컬 시계·입력 debounce·사용자 요청에 따른 페이지 조회는 화면 상태 polling이 아니다.

좌석 점유·예약 가능 시간은 마지막 조회 상태일 수 있다. 실제 명령 시 서버가 최신 상태·권한·가격·버전·중복을 검사하고 거절하면 입력을 유지한 채 최신값 확인을 제공한다. 최신 가격과 사용자가 확인한 금액이 달라진 경우 확정 절차는 해당 거래 계약을 따른다.

AI는 JSON 응답으로 처리 중·완료·확인 필요·실패를 구분하고 중복 제출·제한 시간·늦은 응답을 보호한다. SSE 재연결이나 polling으로 진행 단계를 보여 주는 요구는 제거한다. 취소의 서버 처리 범위를 임의로 축소하지 않고 실제 계약과 함께 정리한다.

## 검증 기준

1. SSE·화면 상태 타이머·포커스 복귀·네트워크 복구 때문에 GET이 발생하지 않는다.
2. 메뉴 진입·재클릭은 실제 GET을 보낸다. 재클릭 시 조회 조건을 유지한다. 승인 대기 화면에서는 브라우저를 새로고침하면 승인·반려 결과를 확인할 수 있다. 공통 업무 화면과 승인 대기 화면에서는 새로고침 버튼과 조회 시각을 숨긴다.
3. 본인 저장 결과, 오류·빈값·409·미저장 입력이 정확하게 처리된다.
4. 권한 회수 다음 요청의 거부와 감지 후 캐시 삭제, 계정·지점 전환 뒤 늦은 응답 차단을 확인한다.
5. 두 사용자 좌석·예약 경합과 결제 멱등성은 실제 Backend·DB 검증으로 유지한다.

자동 갱신이 필요해지면 특정 화면의 운영 근거와 허용 지연을 가지고 후속 결정으로 추가한다. 이번 문서에 자동 조회 예외를 임의로 만들지 않는다.
